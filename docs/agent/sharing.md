# Share links, invitations, reminders, travel

> Doctrine for this area, moved verbatim from `AGENTS.md`. Read before touching: share/slots links, ICS invitations, reminders and leads, the travel prompt and tzid.
> Sibling docs live in `docs/agent/`; the index is in the root `AGENTS.md`.

## Invitations: read, never answered

- **Reading an invitation and answering one are separate features; only the first exists.** Emailed `.ics` names who asks and who comes; import discarded both — `ORGANIZER`/`ATTENDEE` now read, stored, shown, written back. Answering is a **message**: no account, no server, no outbound channel, none coming. Hence no verb, no button, no add-guest control, nothing resembling a reply. `AUDIT.md` drew that line first: the reply half "needs a channel this product has refused; **reading** an invite and showing who is coming does not".

- **Three fields; the third keeps the other two honest.** `organizer`, `attendees`, `attendeeCount`. Count separate: the one fact truncation destroys. Editor prints "and 40 others" from the number that _arrived_, not the length that fitted — no cap shrinks a thousand-person announcement to thirty-two colleagues.

- **`PARTSTAT` collapses to four states; unmodelled reads "invited".** `PARTSTATS` = `needs-action` / `accepted` / `declined` / `tentative`. `DELEGATED`, unknown, absent → `needs-action`: RFC default, the only one claiming nothing about intent. `Declined` asserts a refusal nobody made, `Accepted` attendance; the delegate arrives as its own `ATTENDEE` line with its own status, so somebody _is_ coming is already listed — only the relationship is unsayable. Label **"Invited"**, not "No reply": "invited" fits delegation and silent guest, "has not replied" is false for the first. `PARTSTAT_LABELS` beside the vocabulary, not the editor — `REPEAT_LABELS`' rule: word and value, one decision.

- **`ROLE` and `RSVP` read by nothing, deliberately.** Required-vs-optional changes nothing this surface says or the arithmetic does; the organiser is the only different job, with its own field. `RSVP=TRUE` asks for an answer — that demand beside no way to meet it is the actionable look the feature refuses.

- **`METHOD` neither read nor written — sharpest decision in the feature.** It separates `REQUEST` from `PUBLISH`, `REPLY`, `CANCEL`; each reading pays off only in the refused half: `REQUEST` wants an Accept button, `REPLY` patches a status onto an event already on the dial from a mailed file, `CANCEL` deletes somebody else's event on their say-so. Outbound worse — `METHOD:REQUEST` claims to _organise_ a meeting it only read: how a consumer starts replying to the real organiser. Pinned by test: `REQUEST`, `REPLY`, `CANCEL` read as one kept event with its people; `toIcs` never emits it.

- **Every cap names its threat; one is derived.** `readGuests` in `events.ts` owns all caps for its three readers (`ics.ts`, `backup.readEvent`, `store.hydrateEvents`) — `readRecurrence` shape: three copies = three opinions on when a calendar is too big. `ATTENDEE_MAX` = **32**: above lists people read down, below where names become a distribution list. Threat: a mailing-list invite of thousands of lines inside the one ~5MB origin quota `FEED_BUDGET` already carves 2M characters from; `trimFeed` can't help — it drops whole events, blind to **one** event of megabytes of addresses. `GUEST_NAME_MAX` = 64: a pasted paragraph in a `CN`. `GUEST_ADDRESS_MAX` = **254** = RFC 5321 §4.5.3.1.3's forward-path ceiling, derived not picked: nothing longer is a mailbox, so nothing longer is a truncated address. Duplicates collapse on lowercased address: merged replies restate a line, one person twice lies about size. `attendeeCount` clamped never below the list it labels — it reports what the cap dropped: no "and −3 others".

- **`duplicateOf` drops the guests.** A duplicate is your own event, not somebody's invitation — the argument keeping `seriesId`/`seriesKey` home. Nothing here mints a guest list, so the row is absent from everything the user wrote.

- **Display only; every choice avoids looking actionable.** `Guests` row renders `null` unless there's something to show — never an empty field inviting input. Organiser sits _outside_ the scrolling list: it answers "who is asking", must not scroll away; full `ink` against guests' `ink-2`, greyscale both, colour on this face belonging to events. Name or address, never both — 320px fits one, the name answers "who" — address on the row's `title`, its only copy on screen. Statuses are `.label` tags: three words at label weight, not a sentence. `.fade-y` only past `GUEST_ROWS`: a permanent fade on a list that fits reads as a rendering fault.

## One event in a link

- **Payload rides in the URL _fragment_ — this project's constraint, not a preference.** A fragment is never sent to a server; a query string goes on every click and lands in a log. circal has one route and no server-side state, so an event in a query string breaks that promise for whoever pasted the link — the sender leaks, never knowing. `shareFragment` and `shareToken` are the only places the fragment's spelling lives, so nothing downstream can move it. Nothing stored, nothing to expire, nothing to take down: why this is a link, not a service.

- **`.ics` still answers every other calendar; this is the circal-to-circal path.** Rule, mark and colour survive it, not an export to a product with no vocabulary for the last two. A link another app can't read is no defect — it is why the format may be this small.

- **The link is not private, and the app says so as it is minted.** Encoding, not encryption: link-holder = event-holder. Makes the feature work, fatal if a user assumes otherwise — so the copy notice is confirmation and disclosure in one line, not a comment no chat reader sees.

- **Record is positional, and compactness' cost is stated because somebody will want to "clean it up".** Field names run longer than most values they'd label: positional fields, base36 numbers, epoch **seconds** (nothing writes sub-minute instants — dial snaps to fifteen, `parseClock` to one), duration as a delta off the start, not a second absolute instant, trailing empties dropped ⇒ ordinary timed event = four fields, **34 characters against 512** for JSON-plus-base64, pinned by test so a "tidier" format must beat a number. Price: unreadable by eye; fields **appended, never reordered** — what `SHARE_VERSION` leads the token for.

- **base64url's +33% buys a guarantee instead of a guess.** Alphabet `A-Za-z0-9-_`: no title character can need percent-encoding, escape the payload, or be eaten by whatever linkifies the message. Hand-escaping Unicode into a URL-safe subset is a percent-encoder with a different sigil — three bytes per accented character, a table to get wrong. `CompressionStream` is asynchronous, unusable by a synchronous format called from a click handler.

- **Four check digits exist because driving it found the bug, not a spec.** A link cut short on a base64 boundary — chat client breaking a line, half a link pasted — decodes into a _plausible_ event with its last field silently altered: the hostile case shape can't catch, bytes legal, instants fine. `shareCheck` = four base36 digits of the repo's existing `fnv1a`, 1.7 million values for five characters of link, already this codebase's answer to "is this the same content". Refusal is correct; a wrong event that looks right is not.

- **Travel decided field by field; every absence has a reason.** Guests don't: links go to group chats, circal can't send invitations, so a guest list here is somebody else's. **id** doesn't: one id naming two events in two calendars is what a later import merges. `seriesId`/`seriesKey` name a relationship to an event not in the link. `remindLead` doesn't: absent it arrives as `REMIND_INHERIT` — "follow this reader's own setting". Calendar is the receiver's. A **task** never travels in a link at all — the token carries an event, and a task in one is TASKS.md §11's follow-on, made possible by the version field. `duplicateOf`'s rule a third time, now general: **a copy carries what the thing is, never what its relationships or somebody else's answers were.**

- **All-day travels as a day key and a count, never instants.** An epoch second minted in Berlin is mid-afternoon of the previous day in Los Angeles — birthday arriving on the 7th. `allDayInstants` rebuilds this reader's two midnights from `20260308` plus a day count, `addDays` not `n × 1440` minutes, as every multi-day span here does.

- **Receiving opens the editor, writes nothing.** A link silently adding an event: the one thing here changing your data because somebody messaged you. ⌘P-duplicate's path — `setEditor({ id: null, draft })` — seeded **during the first render**, not an effect: the right day is never rendered wrong then corrected, and effects copying into state are the convention this repo rejects. Reads `store.snapshot()`, not props, for the default calendar: the store hydrates at first subscribe one commit later — travel notice's lesson again. `writeLocation`'s construction clears the consumed fragment: a reload re-offers nothing.

- **Share sits in the editor's footer, nowhere else.** Not the palette: its per-event second verb is already Duplicate, one modifier meaning two things on different rows being the bug `Row.alt` avoids. Not a dial keystroke: a key silently copying your calendar to the clipboard shouldn't exist. It **is** on a subscription's event, outside the disabled fieldset: sharing is copying, not editing.

## Free time in a link

- **The second payload, `#f=`, and the first one's decisions re-used whole:** fragment never query string, `version.check.body` envelope, base36, `shareCheck`'s truncation gate, `SHARE_MAX`. It differs in exactly one way — **no text at all**: no name, no titles, no ids, so the privacy is the construction, not a filter. The record is one base instant in epoch minutes plus `offset.length` pairs; the decoder refuses overlap, zero width, a slot over a day, anything past `SLOTS_MAX` or the sixty-two-day window.
- **Slots travel as absolute instants — the timed event's rule, deliberately not the wall clock.** Free time exists to be booked over, so it is a moment two people are meant to share: a Berlin evening _is_ a Los Angeles morning, and sending wall minutes would offer hours the sender is asleep in. Pinned verbatim in `tests/west/share.test.ts` beside the event tokens.
- **`freeSlots` (`events.ts`) reads exactly what the dial draws** — `dayAgenda` over the same list, `freeGaps` against the same waking window — so a link cannot claim an hour the sender's own face shows as booked. The first day starts at `now` (a gap that already started is not on offer, the palette's own rule); every later day at the window's edge. `SLOT_SHARE_MIN` (30) is the narrowest gap offered: a quarter-hour sliver is not an invitation. Seven days from now, not "this week" — Monday-to-Sunday minted on a Friday is four dead days.
- **Receiving draws, never writes — and it draws _hollow_.** The overlay lands on the **week strip** (the one face reading the whole payload at a glance, where an event lands on its day for the editor's sake), each slot a `SlotArc`: `hollowPath` outline at `ARC_HAIRLINE`, ghost white, `SLOT_ALPHA`. Filled translucent shipped first and read as the receiver's own arcs — a fill at any alpha reads as an event — where hollow is already this face's word for "not booked, book over me", which is what somebody else's gap is one calendar removed. `clipToDay` (`events.ts`) is the shared clip; `SlotsNotice` is the accounting line ("Someone's free time, from a link" — BackupNudge's shape, suppresses the nudge while it stands) and the one way to take the overlay down. Session state only: the fragment is consumed on the first location write, a reload starts clean.
- **The verb is a palette command beside the exports** (`Share free time as a link`), because it is one: data leaving the app. An empty week answers with a plain sentence, not a red one, and the copy toast carries the same encoded-not-encrypted disclosure the event share does.
- **Booking a slot is a tap, both faces, and the whole flow writes to the _receiver's_ calendar only.** On the strip, `SlotArc` with `onPress` (`FaceProps.onSlot`, passed only there) grows a generous hit stroke (`SLOT_HIT` — the strip draws the lane at a fifth of dial scale) whose pointerdown `stopPropagation`s so the press neither begins a day run nor selects the day; hover doubles the hairline, the free arc's own answer; the per-day arcs carry `at`, an index into the payload, so the tap hands back the _original_ span rather than the clipped minutes. On the **dial** there is deliberately no hit path — the slot's footprint sits inside the drag annulus, where a target would steal the draw's start on exactly the minutes on offer — so the same tap lives in `onRingUp`'s zero-sweep branch: a press that never moved, landing inside a slot, books the whole slot; a drawn sweep keeps meaning exactly what was drawn, over a slot or not. Both routes open an ordinary draft through the editor — ⌘P-duplicate's path, nothing committed until Save, Escape leaves no orphan — with `EditorTarget.booking` set.
- **The reply is the other half, and circal still posts nothing.** Saving a `booking` draft mints `ReplyNotice` (BackupNudge's shape, first in the top edge's queue — it suppresses the slots line and the nudge): the saved event — _as saved_, the receiver may have trimmed the gap — as a `#e=` link via the editor's own `shareEvent` (same disclosure toast) and as a one-event `.ics` (`exportEventIcs` in `backup.ts`) for a sender on another calendar. The human carries the reply back down the road the offer arrived on; the sender's circal seeds an editor from the link, Save, and both calendars agree. Session state, like the overlay: the event itself is already safe in the store.

## Reminders

- **Reminders never catch up; hence the one-minute window.** `dueReminders` fires only what comes due in `[target, target + 60_000)`; a notification for a meeting that started an hour ago (tab asleep, lid shut) is worse than none — test is "due this minute", not "not yet fired". Also **floors `now` to its minute**: `useNow` fires ms _after_ `:00`, and an unfloored window from `10:17:00.09` misses every event exactly on `10:17:00.000` — all of them. All-day never fires (no minute to count down to); a task's **timed deadline** fires as `Due now` and each **plan** fires at its start (the thing actually on the clock), a done task never — tasks iterate directly, no recurrence walk, their lead resolved through the same `leadOf` with `REMIND_INHERIT` at the event level since a task names no lead of its own in v1. `Reminder` carries `title`/`kind` and exactly one of `event`/`task`; clicking a task's notification opens the task card. Per-event leads changed only _which_ lead an occurrence is measured against.

- **`Notification.requestPermission()` called from the settings switch, nowhere else.** Chrome and Safari honour it only inside a user gesture, `useReminders` runs off a timer ⇒ the hook checks `permission === "granted"`, else nothing. Switch goes _on_ only if granted came back, else the panel promises what the browser won't keep. Reminder `tag` = occurrence key so the platform collapses duplicates; `fired` is the in-memory belt, React invoking effects twice in development.

- **The inherit chain is event → calendar → setting, each level `colorOf`'s shape.** `CalEvent.remindLead` and `Calendar.remindLead` share the three-state vocabulary; the default names nothing and follows the next level down, so moving the setting still moves every event and calendar that never asked for its own — what makes a global preference worth having beside the per-record fields. `leadOf(event, calendars, fallback)` is the sole reader of that precedence, as `colorOf` is of colour's, returning `null` for "nothing fires" so callers can't read silence as zero. A calendar's silence quiets every inheriting event on it; an event's own lead or silence outranks its calendar's either way.

- **Three states in one number; the encoding is the argument.** A lead is minutes _before_ a start, countable one way, leaving the negative half-line free for non-minutes: `REMIND_INHERIT` = `-1`, `REMIND_SILENT` = `-2`. `0` keeps meaning "tell me as it starts"; `0` doubling as off or absent would make the one lead time this app was built around unsayable. `REMIND_LEAD_MAX` (four weeks) bounds nothing the editor writes and everything an imported `VALARM` or hand-edited backup can: a `TRIGGER` of `-P400D` can't put `dueReminders` on a day four hundred days out every minute.

- **Silence is a state, not a convenience.** Per-event control lets a recurring thing you know about stop nudging; without a third state, silencing one event means switching reminders off for all — the trade the field avoids. Silent is skipped whatever the setting says.

- **One day per _distinct lead_, not one per event.** A lead is a property of the event: a 60-minute lead looks into tomorrow, a 0-minute one at today. An occurrence comes due only `lead` minutes before it starts, so its start day is the only day worth asking about. Distinct leads keep two hundred meetings on the setting's own lead at one `occurrencesOn` query — its cost before the field existed.

- **The Remind row stays visible when reminders are off, and says so.** The inherited option reads `Follow settings · off`, not a duration: "10 minutes" under a preference that fires nothing is the panel promising what the app won't do. That's where the fact belongs — a `.caption` paragraph repeated it under the control, saying what one option already said, three lines of prose the loudest thing in a 335px column. Hiding the row hides an imported event's own alarm (its only view anywhere), and a field that vanishes with a preference can't be discovered.

- **The row _is_ hidden on an all-day event, value left alone.** `dueReminders` never fires one: a lead there is a control with no effect, worse than an absence. Whatever an import put on the draft stays — the sender's statement, travelling back out on the next export.

- **A silent event exports no `VALARM`; nor does an inheriting one.** Absence of an alarm is all iCalendar can say, and this app reads absence back as inherit — materialising the current setting turns a preference into data, returning as an override nobody set. `ownLead` is the exporter's question (the lead an event names _for itself_, else `null`), not `leadOf`: one asks what the event says, the other what the app will do.

- **Lead vocabulary in `events.ts`, firing in `remind.ts` — the split marks already use.** `events.ts` owns what a `CalEvent` field legally is (`REMIND_INHERIT`, `REMIND_SILENT`, `REMIND_LEAD_MAX`, `ownLead`, `readRemindLead`, beside `ICON_MAX` and `isIconName`); `remind.ts` owns what a lead does (`REMIND_LEADS`, `remindLabel`, `leadOf`, `dueReminders`). `leadOf` stays up there because its fallback is a **setting**: what a field legally is must be answerable without one. `readRemindLead` is the one validator with four readers — `backup.readEvent`, `store.hydrateEvents`, `ics.ts`'s `VALARM` reader, the editor's `Select` — `readRecurrence`'s shape; the `.ics` reader passing minutes through it instead of re-spelling whole-minutes and cap checks makes it a fourth reader, not a second opinion.

- **Snooze stays in the shell; the page is never told.** `Bridge.snooze` (`mac/main.swift`) re-posts the identical `UNMutableNotificationContent` under the same identifier with a ten-minute `UNTimeIntervalNotificationTrigger` — same banner again, nothing more. Routing it through the page breaks the rule two lines up: a snooze is the user asking for the banner back, not the app deciding a meeting is newly due, and via `remind.ts` the two are indistinguishable. A future reader "fixing" this by involving the page has misread it. The `osascript` fallback has neither the action nor a tag to snooze with, and correctly doesn't try.

## Travel: the device that moved

- **Nothing here is a corruption, and the prose must not pretend otherwise.** A user's event is floating, its instant absolute; the dial draws that instant on the browser's current clock: fly Berlin → New York, 09:00 draws at 03:00 — same moment, precisely _why_ it moved. Defect was never arithmetic; the app said nothing. `travelNotice(stored, current, hasEvents)` compares `settings.deviceZone` against the zone read **once** on load and asks once, as the whole screen (`TravelPrompt`, shaped like `BirthPrompt`), not a modal over a working dial. Names **cities, never IANA identifiers** — `Europe/Berlin` is a database key; someone just landed is owed the name of the place they left — and proves it by resolved illustration, not description: what a 09:00 event written back there reads as on this face. Two answers, both legitimate, neither styled safe, **no dismiss**: "keep them as they are" _is_ the do-nothing answer, and a dismiss would leave the app knowing the device moved and drawing the day as if not.
- **The shift is derived through the wall clock and is a function of each instant, never a subtraction.** `movedInstant` is `instantOfWall(wallClockIn(at, from), to)` — the pivot the recurrence walk turns on, settling DST-gap and repeated-hour wall times as every other reader here does. Two zones are not equidistant all year (Berlin/New York: six hours in July, five in the fortnight their transition dates disagree), so March and July events move differently, and one shift computed for "now" across a list is wrong for most of it. `until` moves at **its own** instant likewise: it bounds a start, and a series handed its old bound stops on the wrong day. `exdates`/`rdates`/`doneKeys` deliberately do not move — local wall-clock keys; both answers keep the wall clock, one by preserving it, one by naming the zone it was kept against. Rewriting them is the resurrection bug `duplicateOf` documents, from the other side.
- **An all-day event is re-anchored under both answers and stamped under neither.** A date has no clock to keep, so "keep the old times" is meaningless, and an offset on a day boundary puts the 5th on the 4th — five hours off midnight is previous evening. `reanchored` puts it on local midnight of its own calendar date in new zone, `addDays` rather than `n × 1440` minutes, the argument dial's multi-day span already makes.
- **Each answer is one recorded commit carrying both the events and the new `deviceZone`, and deliberately does _not_ own its settings.** `commit(next, true)` puts whole answer in one undo step, so ⌘Z gives calendar back — but device zone rides inside that step precisely so an undo does **not** restore it: an undo that "fully" undid the answer would put prompt back in front of somebody who already answered. A later reader tidies that asymmetry into consistency; it is deliberate, and why `setDeviceZone` (silent path for a first run, unmoved device, browser with no events of its own) passes `false` and writes no history. Silent path reads stored zone from store, not props: hydration is lazy and first commit's snapshot is still empty.
- **Keeping stamps the events, and the stamp has to stay legible afterwards or the answer was a trick.** `keptEvents` writes old zone into `tzid`, letting three surfaces name clock those hours belong to: readout prints city beside a span (never during a drag — a range being drawn has no event yet), agenda row prints it in trailing slot, editor's `Times in <city>` caption fires for every zoned event. Agenda slot is the cheap one on purpose: on a row neither headline nor running it was **always empty**, so nothing gives up a column and measurement that took `DAY 2/4` off headline row still holds. Precedence there is urgency first — `ends in 12m` outranks where thing was written — and a place is `uppercase` because slot's other two readings are prose and this one is a tag.
- **The clear knows which zones _this app_ stamped, and that list exists because `tzid` has a second writer.** First version walked every event carrying a zone; an imported `.ics` lands in the same `snapshot.events` with real zones from the file, so the settings row overcounted and its verb flattened a colleague's weekly 09:00 New York standup to floating — which then walks its rule against the reader's wall clock, the exact defect `startsBetweenIn` prevents, reintroduced by a settings row rather than the domain layer. `keepEventsInZone` records what it stamped with in `settings.stampedZones`, same commit; count, places and clear all scoped to it. A **list**, since two journeys kept in a row stamp two zones and one field would strand the first's stamps; `sane()` refuses entries `Intl` cannot resolve and deduplicates, since garbage would scope the clear to nothing while the row still counted it. Residue named in the caption, not papered over: an imported event genuinely naming the same city is indistinguishable from a stamped one and goes with them. Telling them apart needs a provenance field on every event — a permanent model addition for one settings row, against a residue narrow and one undo step wide.
- **Clear is the one travel action that _does_ own its settings.** It empties `stampedZones` as it clears: an undo restoring stamps without list naming them leaves them unclearable. Both derivations — count and places — read what events carry rather than setting alone, so a remembered zone that outlived its events counts nothing and shows no row.
