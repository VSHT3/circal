# Dial, faces, week strip

> Doctrine for this area, moved verbatim from `AGENTS.md`. Read before touching: dial geometry, the Face/Dial split, drag gestures, arc labels, centre panel, busy/free, tasks, sun/moon/zone bands.
> Sibling docs live in `docs/agent/`; the index is in the root `AGENTS.md`.

## Faces, dial, week strip

- **`dayKey()` deliberately local-time.** `toISOString()` shifts the day west of UTC — where day-keyed store breaks. Never swap in.
- **`Face.tsx` draws a day; `Dial.tsx` makes one editable — split by _question_, not size.** "What does this day look like" (geometry, rings, arcs, labels, band-replaces-ramp) → `Face`; "what did that gesture mean" → `Dial`. `Face` takes `svgRef` + pointer handlers, never owns them: capture belongs to whoever reads coordinates. Rings outside arcs opt-in, **off by default**; a `Face` with no `onGrab`/`onHover` draws no hit strokes = read-only face. New dial switch enters `Face` props only if it changes what is _drawn_.
- **Every id inside the face comes from `useSvgId`** — `url(#…)` and `<textPath href>` resolve to _first_ matching id in document ⇒ hardcoded gradient id is right for one face on screen, silently wrong with more. Glow, now-hand gradient, both band masks, every arc label mint their own; anything new needing `#` too.
- **Week strip read-only**, keeping `<Face>` honest: 7 faces of drag targets = 7 chances to edit wrong day, and dial is one keystroke away. `WeekView` passes no `onGrab` ⇒ no hit strokes ⇒ 7 × 0 pointer paths, not 7 × 19. `onHover`/`onFocus` only name the day for shared readout. Face = real `<button>`: 7 tab stops is a usable order ⇒ no `sr-only` listbox (year ring 365, life grid 30,000 need one; as life grid's three milestone buttons).
- **Strip's elapsed ramp on today alone; its rim on every face.** A past day's ramp is full bright ring answering "all of it" — nobody asked — and shouts down neighbouring arcs ⇒ `elapsed` and `hand` both `d.today`. The other six need something to place arcs against ⇒ `Face`'s `track`: one circle at `DIAL.TRACK`, at ramp's floor, so on today ramp reads as that rim lighting up. The one stroke drawn **translucent not opaque**: `TRACK_WIDTH` = three units, two fifths of pixel at strip size ⇒ rim exists only as antialiased fraction browser rounds it into, and opaque grey has no fraction to give. Nothing overlaps it ⇒ no alpha compounds.
- **Day ⇄ week scales _and translates_; no `transform-origin`.** The panel carries one already (life dot) and dial must land on its face whatever that origin is. Under `scale(s)` about origin `o`, `c` lands at `o + (c - o) * s` ⇒ panel centre onto face centre `f` needs `t = f - o - (c - o) * s`. `App.face` solves it once; `weekZoomScale` supplies `s`, tested on what matters: dial's drawn diameter = `layout.size`. One eased tween, not `ZOOM_STEPS`' geometric ladder — ~4× zoom, not two orders of magnitude; ladder over that distance reads as a stutter.
- **`flow.current` is reassigned wholesale ⇒ `face` MUST be carried across it.** `go()` and popstate each build new `ViewFlow`; a field effect wrote into old one dies on next view change — hence `faceFrame`, its own ref both writers copy forward. New `ViewFlow` field = three places: initial `useRef`, `go`, popstate.
- **⌘W is not available to any web page** (Chrome, Safari, Firefox): closes tab, keydown never delivered — unlike ⌘D / ⌘Y / ⌘L / ⌘P, mere menu equivalents this app overrides already. Week = **⌘E**, no mnemonic and needs none: the `Segmented` control prints chip, how every view key here is found.
- **Strip's readout lives outside scroll container.** Inside, it centres on content — wider than window once 7 faces do not fit — and sentence walks off side. Same reason selected face is `scrollIntoView`d on arrival, not left wherever Monday put it, and not smoothly.
- **The strip's three parts are one group, centred together.** 7 circles in a row are ~a seventh of width tall ⇒ landscape window leaves much black under them, and readout pinned to panel's foot captions window, not strip. `weekLayout` returns `groupTop`/`groupHeight` covering captions + faces + readout; leftover height stays outside group.
- **`angleAt` and `minutesAtPoint` are exact inverses** and MUST stay so. Both take `Clock`, differ only by `origin()` — minute at top (720 for `12h`, 0 for `24h`).
- **`arcPath` draws full turn as two half-arcs**: one elliptical arc with coincident endpoints renders nothing. Drop branch, whole-day arc vanishes.
- **A gradient built from overlapping strokes MUST be opaque.** Elapsed ring = chain of arcs; translucent ones compound alpha at overlaps, every join a bright bead, trail reads as tick marks. On true black, opaque grey = translucent white ⇒ `Face.tsx` ramps _colour_ (`grey(level)`), butt caps between segments, rounds only run's two ends.
- **Now-hand stops at `DIAL.HAND_INNER` (205).** A hand through centre crosses readout and agenda — ink on time readout prints. It is a spoke: pip on track at exact minute, fading out along a `userSpaceOnUse` gradient before centre panel. Panel grows ⇒ `HAND_INNER` MUST clear its furthest corner: with totals line on, lowest thing sits ~135 units below centre and 113 out ⇒ corner = 176, 29 units in hand.
- **The strip is read-only about events and _writable_ about days — one gesture, and it is the ring's.** Press, drag across faces, release: press that never left its face is still a click on that day; wider = run of whole days into same `onCreateSpan` year ring and life grid use ⇒ editor cannot tell which face drew draft. Costs no drag targets, no arc grips — keeping "read-only" true where it mattered: 7 faces of grips = 7 chances to edit wrong day. Run live ⇒ every covered face carries the mark an all-day event will get — a `GhostMark` row in `AllDayMarks`' own column, since a run of whole days _is_ that many all-day days and a ring ghost would be a drawing the release throws away; grey at `GHOST_ALPHA` while drawn (no colour yet, dial's own rule), `Day i/n` beside it only where face is `detailed` and run longer than a day. Released, strip reads `pending` (year ring's and life grid's own prop, `App.pendingDays`) ⇒ marks take draft's colour and survive the modal arriving — the one notion of "the event about to exist", now on all four faces. Per-face hover suppressed while run live, shared readout prints `formatDayRange` + count; a card naming one end of run answers a one-answer question twice. Escape abandons it, from strip's own registration, as `Dial` does. Face under pointer from `weekFaceCentre`, never DOM: 7 comparisons against numbers view has, and hit test cannot disagree with drawing. Pointer path is `pointerup` ⇒ faces' `onClick` takes `e.detail !== 0` to keep keyboard activation working.

## Centre panel / readout

- **Centre = one display, four moods, ordered.** `CenterPanel.tsx` resolves `span` first (range being dragged, else arc under pointer), then today's time, then date. Drag and hover print _same_ thing — same question — so they share branch. Size change = CSS `font-size` transition, 140 ms on `var(--ease)`, matched to the arc's stroke-width transition: arc thickening and clock shrinking into its span is one movement; split curves read as two events.
- **Headline row = first _timed_, non-past occurrence, only on today.** An all-day event is context, never next thing, never `running` (`Now … ends in 10h 4m` = countdown to midnight dressed as appointment). Headline drops start time (the ring holds it), spends width on name and wait; `untilText` rounds _down_ — a countdown overstating time you have is worse than none. Under `IMMINENT_MS` dot takes a ring, not a pulse: pulse means "running" already, one signal cannot mean two things.
- **Hovered occurrence added back to the card even when ended.** Today's card filters `occ.end > now`; without exception, pointing at morning arc printed span with no name. Costs one row of shift while pointer is on past arc — honest position for it.
- **`totals` measured against two different windows on purpose.** Booked = whole revolution (a six o'clock run is time spent); free = only `WAKING` — "nineteen hours free" is not offer. They sum to nothing, nobody adds them. `WAKING` lives in `events.ts` beside `freeGaps`; palette's slot search and this line MUST mean same thing by the word.
- **`totalsAt` places line against _stage_, not dial.** `center` = only one rendered inside panel's column, under the card; other eight = `flex` layer at `inset-0` with `p-4` ⇒ corner is _window's_ corner — black a circle in landscape window never reaches. `CORNERS` in `CenterPanel.tsx` maps them, deliberately with no `center` key: that position is not corner of anything.
- **A due date's readout is one instant, not span.** `peekedTask` splits the zero-width pip out of `peeked` ⇒ pointing at one prints `01:15 DUE`, not `01:15 – 01:15 · 0m`, three ways of saying nothing. A _plan_ is a span and prints like one. Still shrinks clock (`aside`, not `span`): readout answers about something other than now, what size change means.
- **No `backdrop-filter` on element also carrying `.fade-y`** — Chromium paints blur over box far larger than element, appearing as grey rectangle mid-dial (see comment in `CenterPanel.tsx`).

## Drag gestures

- **Ring drag accumulates sweep; never measures from grab.** `Draw` holds `{ from, at, sweep, origin }`; `onRingMove` sums `wrapDelta` per pointer event, as the arc's drag does. From grab, new event caps at twelve hours and inverts past that — `wrapDelta` takes short way. Sweep is unbounded and the day is not a wall: up to a full revolution the range draws _whole_ on the anchor face, wrapping the top when it crosses midnight (`angleAt` is linear and `arcPath` takes raw degrees, so an end past 1440 just wraps — the past you drew stays visible); past a revolution no face can show it, so `drawFollow` steps the view onto the leading edge's day (`end - 1` forward, `dayCount`'s exclusive-end rule) — `dayFollow`'s "switch then rather than earlier", one gesture over. The release commits against `origin`, the grab day, so the draft lands on the days actually drawn; Escape gives stepped days back. Steps issue as a difference through the `drawShift` ref, never `shift`-in-state or the `day` prop — two pointermoves can land inside one render, and both running against the same stale closure would step twice.
- **Arc drag accumulates `wrapDelta` per pointer event; never measures from grab.** Two ring positions do not say which way round pointer went ⇒ delta from grab flips sign once drag passes twelve hours. Summing short hops lets drag cross midnight as often as it likes.
- **Minimum duration clamped on `delta`, not on resulting instant** (`clampDelta` in `Dial.tsx`). Clamping end banks overshoot: the arc lags by far pointer ran past limit before following back. Clamping delta stops dead, releases instantly — and since sound fires only on delta change, clamped arc goes quiet: feedback saying "this is as short as it gets".
- **A press on an arc that never changed delta is a click.** `onArcUp` opens editor when `delta === 0` — also whole implementation of read-only arcs: subscription's occurrence gets `grip: "none"`, `clampDelta` pins it to zero, press falls through to opening. No separate `onClick`.
- **`Escape` abandons gesture in flight**, from `useHotkeys` inside `Dial`, not shell's: `cancelDraw()`, `cancelAdjust()` — each also gives back any days the view stepped on the gesture's account. A drag is one thing here you start by accident; before this only exit was letting go, which committed it. Pointer stays captured on purpose — move and up handlers bail on missing gesture ⇒ release does nothing, no cue because nothing happened.
- **Full revolution = all-day event; `draftEvent` decides.** Span ≥ `MINUTES_PER_DAY` becomes `allDay`, instants snapped to the day's two midnights ⇒ ⌘N, palette and ring gesture agree. `CenterPanel` prints `All day` while such drag is live — gesture should say what it will make; the arc vanishes on release, since `EventArc` draws nothing for all-day event.
- **More than one revolution = that many all-day days, same function.** `Math.round(span / MINUTES_PER_DAY)` ⇒ dial's exactly-1440 sweep stays one day, year ring's `n × 1440` becomes `n` — and the dial can now hand over more than one too, since its sweep is unbounded. All-day `end` = `addDays(startOfDay(day), days)`, **not** `base + n × 1440 minutes`: a day is not always 1440 minutes, so span across spring-forward landed `end` at 23:00 on last evening instead of midnight after it — and `end` is exclusive, so trip's last day fell off dial. Latent at n=1 before year ring existed; same fix either way.
- **A whole turn is drawn closed — a second rule from same fact.** `capInset` shortens an arc half stroke each end so painted length = duration — but once ends meet inset is a notch at midnight, and a circle with a notch reads as a rendering fault. `GhostArc` returns `<circle>` for full-day range; `EventArc` drops inset at `to - from >= 360` (a timed event through whole day = any multi-day event's middle).
- **⌘⌫ deletes the arc under pointer; the key lives in `Dial.tsx`** — dial owns hover, so it owns press (as Escape's gesture-abandon). What a delete _means_ stays shell's: `onDelete(occ)` up, one-off straight through `store.remove`, repeating one gets same `ScopeDialog` drag gets, in danger colour. Off while `covered` (the shell's `busy`) — editor has its own ⌘⌫, two handlers on one press delete two different events; off mid-gesture — drag in flight is about to write that arc; never on subscription's occurrence. It **always toasts**: editor's Delete is two deliberate presses inside modal, this is one keystroke, and destructive key with no receipt is a key nobody presses twice.
- **⌘ held at grab duplicates instead of moving; modifier is read once.** `Adjust.copy` fixed at `onArcDown`: a ⌘ let go halfway would turn duplicate into a move of thing being copied — one outcome nothing undoes in single step. Only `grip === "whole"`: duplicate is a move of copy, so end grip is a resize whatever is held, and `grip: "none"` means subscription's arc is never copied either. While copying, `onArcMove` **withholds `onPreview`**: original must stay exactly where it is, and thing following pointer is `copying`, draft's own `FaceGhost` channel in event's own colour. Nothing written until release, and release asks **no `EditScope` question** — three scopes say which occurrences edit reaches, and duplicate reaches none.
- **A duplicate carries whole event, rule and all; `duplicateOf` (`store.ts`) is one place that says what "the whole event" means.** Deltas apply to event's own instants — plain drag's reading — so ⌘-dragging one occurrence of weekly standup returns weekly standup hour later. `seriesId`/`seriesKey` deliberately do NOT travel: they name a relationship to another event, and two events cannot claim one occurrence. Three MUST travel **with shift** not beside it: `until` bounds start; `exdates`/`rdates` name instants — series moved hour later keeping old keys fires on every day original skipped. A day-form key re-emits as a day, carrying whole-day exclusion across drag that crossed midnight.
- **⌘P duplicates through editor; asymmetry is point.** A gesture named time ⇒ drag writes and toasts; palette named none ⇒ unmodified copy would land exactly under its original, toast its only evidence. `actions.duplicateEvent` seeds `setEditor({ id: null, draft })`, commits nothing until Save ⇒ Escape leaves no orphan. Goes to original's own day first: editor over a face that cannot show what is being edited is a form.
- **`onRingMove` and `onArcMove` bail when snapped minute has not changed.** Makes clicks countable (one per fifteen-minute step, not per pointer event) and drops re-render `pointermove` would cause. `cue()` has its own 22 ms floor for same reason: fast flick crosses steps faster than ear separates them.
- **Lane packing is face-independent.** `dayAgenda` takes no `Clock`: both faces put one day on one revolution, so two events collide on screen exactly when they collide in time.

## Arc labels

- **Arc labels live _inside_ stroke — geometry, not taste.** `LANE_STEP - ARC_WIDTH` = 13 units of black between two lanes, and hour numerals come down to 333 just outside first ⇒ label _beside_ an arc works on outermost lane and nowhere else. Inside 14-unit stroke: 11px of mono, 3.1 units of arc either side, identical on every lane, costing no radius — the "do not add a ring" rule again. Also `inkOn(color)`, black on event's own pastel at ~10:1, strongest pairing this face has; grey on black beside the arc would be weakest. **Except on free arc, where there is no pastel to be black on** — see "Busy and free".
- **The label's budget is glyphs measured against _paint_, never minutes and never centre line.** `arcLabel` takes the arc's painted ends (span less any seam neighbour claimed): round caps put half stroke back past `head`/`tail`, and label handed the `capInset`-shortened span forfeits 14 units per arc — every half-hour event going anonymous (it did). Mono ⇒ width is arithmetic: no `getComputedTextLength`, no layout read per arc per frame of drag. Where gate lands in minutes is _consequence_ (a word from about 45 minutes, a stub from about 30 out at rim, nothing on inner lanes) ⇒ duration threshold would label event at rim and crop same event two lanes in.
- **A glyph takes its up-vector from path's direction, so bottom half is drawn backwards.** `arcPath` grew a `back` flag: same arc traced anticlockwise from `to` to `from`, invisible on stroke and whole difference between readable label and upside-down one. `arcLabel` reverses whenever the arc's midpoint is between 90° and 270°; flip must land somewhere and at three and nine o'clock text is vertical either way. From _drawn_ angle ⇒ both faces get it free.
- **The label rides its own radius, a half-cap off the arc's — `dominant-baseline` is not available here.** A glyph stands on its baseline, so text set on radius `r` puts all its ink to one side of the centre line: outward on the clockwise path, inward on the flipped one, half of every letter hanging off a 14-unit stroke (it shipped that way, visible on WebKit). `dominant-baseline` is the CSS answer and **WebKit ignores it on a `textPath`** — measured: `central`, a `dy`, and no rule at all give byte-identical bounding boxes. So `arcLabel` draws its path at `r ± ARC_LABEL_BASELINE` (`back` decides the sign) and `startOffset`/`lean` are measured on that radius, not the arc's; the mark stays at `r`, because `MarkGlyph` is centred on its own point rather than set on a baseline. Never add `dominantBaseline` back to that `<text>`: on the engines that honour it the two corrections compound.
- **The label keeps full alpha on dimmed arc.** Ink here is _absence_ of light ⇒ dimming it with body takes both towards black behind and the name disappears at ~1.5:1. Left alone it softens from about 10:1 to 4.8:1 as the arc recedes — the hierarchy dimming asked for. In `hover` mode it is mounted at `opacity: 0`, not mounted on hover: it arrives in same beat stroke grows by 3, and text popping in on growing arc reads as a wobble.
- **A mark on an arc costs two glyphs of label's budget, and never the name.** `arcLabel` takes the mark, prices it at `ARC_MARK_GLYPHS`, rides it along **only** while what is left clears `ARC_LABEL_MIN` on its own — tight arc drops the glyph, keeps the word: a symbol shared with everything on one calendar is worth less than a name's last two characters. Pair centred as unit: `startOffset` pushes text out by half the mark's slot, the glyph sits at _start_ of that slot so all slack lands between it and first letter, and both flip through bottom half with path. `MarkGlyph` is SVG-native renderer for exactly this; `CalendarMark` answers a `<span>` for emoji and dot for nothing — neither legal inside an `<svg>` nor wanted on an arc already carrying its colour.

## Busy and free

- **An event is busy or free, and `CalEvent.free` says which — explicitly, never inferred.** Nothing about span says how seriously it is meant, so reading it off title, calendar or zero-width end would be typing data by coincidence. Busy is default _and_ absent value, keeping a field arriving in old blob harmless. `TRANSP` on wire (`TRANSPARENT` = free, `OPAQUE` and absent property = busy), named for the word editor prints, not property: property is a spelling, idea UI must say out loud.
- **Checklist for a new optional `CalEvent` field — 22 sites, not the six this sentence used to name.** Measured while threading `travel`; the six-item version omitted ten and shipped nothing wrong only by luck. In dependency order: the interface itself and `taskOccurrences`' synthetic event (`events.ts`); the arithmetic that reads it (`bookedBlock`, and through it `freeGaps`/`dayLoad`/`clashesWith`); `hydrateEvents`' destructure, shape fast-path _and_ rebuild (a field left out of that question is a field blob never gains), `draftEvent`, the demo seed, `SCHEMA`'s header sentence (which does **not** bump — additive fields never have); `readEvent` and `importIcs` (`backup.ts`); `ics.ts`' `EventDraft`, writer and reader — "importIcs" names only the copy step, not those two; `feeds.ts`' mirror; **`share.ts`, the site most likely to be forgotten** — a flag bit for a boolean, a positional base36 slot for a number, plus the docstring enumerating what travels; `mcp/domain.ts`'s create path _and_ patch path (a patch that does not carry the field erases it, since the draft goes back through `readEvent`); `mcp/tools.ts`' schema if an agent may set it; `App.tsx`'s convert-task draft; the editor row; the render; and `tests/helpers.ts`' `event()` factory, which every suite compiles against. `duplicateOf` needs nothing — the field rides `...rest`, and only deliberate omissions are enumerated there.
- **Hollow, because other two encodings were already taken.** Alpha is spoken for: past arc draws at `0.42`, so "free" = "fainter" makes past meeting and future placeholder one picture. `hollowPath` (`dial.ts`) traces outline half hairline **inside** filled arc's own silhouette ⇒ stroking at that weight paints exactly same footprint: same radius, same lane, ends where round caps land, `capInset`'s promise — painted length is duration — untouched. A caller hands it same `from`/`to` it hands `arcPath`. What outline _says_ is "this footprint, none of the event in it" ⇒ travel run-up borrows same construction (below): free event is whole arc of that, commute is run-up of one.
- **`ARC_HAIRLINE` is `ARC_WIDTH / 8`, derived and not chosen.** The same `<Face>` draws 7 to a row on week strip at ~a fifth of dial scale ⇒ weight picked against dial's own pixels means something else there. An eighth leaves ten units of black between two edges — wider than the `SEAM` two neighbouring arcs keep — so hollow reads as a hole, not thick line.
- **One construction, three shapes, each for rule that already existed.** Full turn = two concentric circles, closed and uncapped: inset once ends meet is a notch at midnight (`arcPath`'s own rule). Degenerate sweep = two caps alone, a ring — hollow of dot filled path collapses to. Everything between = racetrack: out along far edge, round cap, back along near one.
- **Hover changes weight, not width.** A filled arc grows three units on CSS transition; outline's width lives in path data and path swap cannot tween ⇒ hovered free arc doubles hairline instead. Footprint never moves, and feedback still lands in same beat as label's fade.
- **The label had to change ink, and this is part that would otherwise have shipped broken.** `arcLabel` draws the name inside stroke in `inkOn(color)` — black on pastel, the face's strongest pairing — but inside outline the arc is mostly black behind it, so that black is not dim, it is _absent_. A free arc's label and its mark glyph take event's **own colour** (`labelInk` in `Face.tsx`): every `PALETTE` entry is high-value pastel reading on true black at same order of contrast black-on-pastel had; it is colour of line it sits in, so pair reads as one object; and colour dark enough to fail here fails outline in same breath — label and arc cannot disagree about whether event is legible. Full-alpha rule on dimmed past arc unchanged.
- **A task's occurrence is never hollow-for-free, and that is decision.** A due pip books nothing already ⇒ "free" has nothing to withhold — and the pip's filled/hollow pair is spoken for: filled is open, hollow is done. One shape cannot carry two meanings on one face, rule that keeps a pulse from meaning both "running" and "imminent". A plan's synthetic event is always busy, so the question never reaches one. An **all-day event still draws no arc**, free or busy, as before.
- **The point of feature is arithmetic, not picture.** `freeGaps` books no block for free occurrence ⇒ `dayLoad`'s booked total stops counting birthday as hour spent, and palette's slot search follows for nothing — it reads `freeGaps` already. What counts as booked changed; window it is counted over did not — booked against whole revolution, free against waking window, still not summing to anything.
- **Measured on strip, and answer is why there is only one encoding.** The two edges do not merge at any size strip draws: at typical desktop strip hairline is 0.625 css px with 3.75 css px of black between edges; at `WEEK_MIN_FACE` — smallest face `weekLayout` will draw — 0.252 css px with 1.515 between them, a faint hoop beside a solid lozenge, confirmed in 1:1 screenshot not argued. Merging needs gap under about one device pixel ⇒ a face roughly a third of strip's own floor. So no second encoding for small faces: one that degrades gracefully beats two that can disagree about what same event is.

## Travel time

- **`CalEvent.travel` is minutes typed by hand, and `0` is both "none" and the absent value.** No geo API: an estimate fetched per event with an address is a network request to somebody else, which is the rule `location` already lives under, and the number a person types is the one they act on. `X-APPLE-TRAVEL-DURATION;VALUE=DURATION:PT30M` on the wire — Apple's own spelling, not an `X-CIRCAL-` one, because a private property round-trips with nothing but this app while Apple Calendar already reserves the same window and raises the same "time to leave" alert off it. `readTravel` + `TRAVEL_MAX` (one revolution) in `events.ts`, one validator, five readers.
- **`bookedBlock(occ)` is now the single statement of what "busy" means on a face**, and travel is why it exists. It returns the minutes an occurrence takes off the day, run-up included, or `null`. Three surfaces read it and so cannot drift: `freeGaps` (and through it `dayLoad` and auto-schedule), `clashesWith`, and `EventArc`, which **draws exactly the block it returns**. All-day, free and zero-width fall out there rather than being re-tested at each caller. The point of the feature is that line, not the drawing: a commute stops being offered as free time.
- **Two readers of one field, clipping differently, deliberately.** `travelMinutes(occ)` is day-clipped (`min(event.travel, occ.startMin)`, so `continuesBefore` yields 0) and answers the face and the day's arithmetic; `leaveBy(occ)` is not clipped and answers reminders, the headline row and the tab title. You leave at 23:40 for a 00:10 meeting whatever the face can show, and the previous day draws nothing — an occurrence is on a day because the event runs during it, and travel is not the event. `lib/travel.ts` is an unrelated subject (moving events between zones); the field has nothing to do with it.
- **A free event's travel is inert everywhere, and that is one rule in two places.** `bookedBlock` drops the occurrence whole, so nothing books and nothing draws; `leaveBy` returns the start, so no reminder claims a departure the face is silent about. The editor hides the row when Free is on, the way it hides Remind on an all-day event: a control with no effect, with its cause in view directly above it.
- **Drawn as the dotted outline of the band it books** — `hollowPath` at `ARC_HAIRLINE`, dots by `travelDots`. Two encodings composed rather than a third invented: an outline is the footprint with none of the event in it, a broken line is an estimate. **A filled dashed band at `ARC_WIDTH` shipped first and was wrong** — at the arc's own weight the run-up reads as the meeting with a fault in it rather than as an approach.
- **The dots are fitted, not a fixed pattern.** The outline is a closed racetrack, so a period that does not divide its length pinches where it wraps. `travelDots` takes the racetrack's own length (two edges summing to twice the centre line, plus two caps making one circle of `off`) and fits a whole number of dots at ~4.5 units' pitch. `0.01` of ink under a round cap is a dot of the stroke's width; not `0`, which renderers disagree about.
- **Hover widens the loop and never the dots.** `band` — the eased `ARC_WIDTH + 3` — goes to both `hollowPath` and `travelDots`, so the outline grows with the arc it joins while each dot keeps its 1.75. Eased through `useEased` because the growth is a path rebuild and CSS cannot tween one; the arc's own `stroke-width` transition takes the same beat. **Doubling the dot weight instead exceeds the pitch and welds the dots into a bead chain** — tried, seen, rejected.
- **It does not survive the strip's floor, measured rather than hoped.** A dot is 0.335 css px every 0.877 at a floor-sized face — about a tenth of a pixel's coverage — so the run-up is simply absent there, where a _continuous_ hairline (the free arc's hoop) survives. Absent is the better failure: nothing is drawn wrongly, the arc is unchanged, and a 180 px face draws a minute in a tenth of a pixel. A fatter dot that read at the floor was a bead on the dial.
- **A run-up is part of the arc's footprint, so packing and seams measure from it** — `packLanes` from `startMin - travelMinutes`, `Face`'s `gaps` likewise, and the leading `seamTrim` goes to the run-up rather than the arc, since the two are one object. **`packLanes`' `pad` is the arc's own and a run-up gets none**: the pad absorbs the round caps two abutting arcs overhang each other with, and a run-up's leading end is inset to land its paint on the leave-by minute. Given the tolerance anyway it lay five minutes across the arc before it, which reads as a rendering fault where two kissing caps read as two events. Driven out in a browser.
- **A lead is measured back from `leaveBy`, not from `start`.** Ten minutes' warning on a 25-minute commute arrives 35 minutes ahead, `dueReminders`' day map reaches `lead + travel` so the day the occurrence starts on still gets expanded, and the notification says `Leave in 10m`. The headline row and the tab title count to the same instant — three surfaces, one function, or the card and the notification disagree about how long you have. Past the leave-by minute the row reads `leave now`.

## Tasks

- **A task is its own record (`Task` in `lib/tasks.ts`), never an event with a degenerate span.** A piece of work has a deadline, a rough length and the time you plan to spend on it — three numbers with three lifetimes — so the model carries `due`+`dueAllDay`, a nullable `estimate`, a three-value `priority`, a `plans` list and a `done` boolean. No `Recurrence` in v1: a repeating deadline and a habit are two features wearing one name, and neither is answered by borrowing an event's rule (TASKS.md §4, §13).
- **Tasks reach the face only as `Occurrence`s.** `taskOccurrences(tasks, calendars, day)` in `events.ts` emits each plan overlapping the day as an arc and a timed due date with no plan on the day as a zero-width pip at its minute; `dayAgenda` concatenates before packing, so no renderer learns there are two models. The occurrence rides a _synthetic_ `CalEvent` (same id, title, colour, mark, calendar) with `occ.task` set — the tick control routes through `occ.task.id`, never `doneKeys`, which no longer exists. A pip (`occ.task && startMin === endMin`) takes no lane and books no minutes (`freeGaps` drops it on width); a plan packs and books like a meeting, which is the whole point of planning one.
- **`done` is a boolean and a tick asks no `EditScope` question**: a task has one deadline and is finished once. Repeating deadlines are v1's largest deliberate cut; when they arrive, `done` becomes a ticked-instants list and that is the only field that changes. Every tick goes through the shell's `tickTask`, so the sidebar's pip and the interior's cannot disagree about the rings-closed gate.
- **Filled while it stands, hollow once done — on every surface.** Rim pip and interior tick target are same two shapes ⇒ the mark you press and the mark you see on the face are one mark. Opposite of checkbox convention, deliberately: on this face ink is _light_, so emptied pip reads as spent. In the list strike through the name is primary signal, the pip only the control. **`CenterPanel`'s row is therefore a `div` with two buttons**, not one button — a control inside a control is not thing HTML has.
- **An all-day due date draws nothing on the dial**, as an all-day event draws no arc. A plan's arc wears its pip at the head, inside the stroke (`EventArc`'s `planArc` branch): the pip is the tick control — a `cursor-pointer` hit circle listed after the grips so it wins the stack, routed through `FaceProps.onTick` → the shell's `toggleDone` — and the thing that says "this arc is work". A done plan takes the free-time hollow drawing (`free` is never asked of a task, so the shape is unclaimed) and its pip empties with it; ticking fires `.pip-burst`, one ring popping off the pip, removed on animation end. The year ring and life grid count plans through `planEvents(tasks)` (`events.ts`), merged as `spanned` in `App.tsx`: planned time is time spent, a bare deadline colours no day.
- **The row-to-rim drag rides window listeners, never a press on the SVG** (TASKS.md §7). A sidebar row's `pointerdown` plus a 6px slop calls `actions.dragTask(id)` — mouse/pen only; touch moving is scrolling, and the Schedule verb is the touch path. The shell holds `dragTaskId`, resolves the `Task`, and hands it to `Dial` as `dragTask`; the dial's effect listens on the window (no pointer event ever targets its SVG), maps the pointer through `getScreenCTM` and refuses everything off the annulus `[LANE − 3·LANE_STEP, C]`. **The mechanic is one move: the ghost rides under the pointer, at the estimate's length, in both directions.** An earlier draft anchored the start and swept the end once the pointer passed it — and moving a task clockwise grew it instead of carrying it; length is chosen after it lands, with the arc's own grips. Steps fire the `step` cue; the ghost is a `FaceGhost` in the task's own colour at `GHOST_ALPHA`. Release commits through the shell's one plan write, `planAt` (Schedule verb, dial drop and strip drop all land there, so commit, `created` cue and toast cannot drift). A release off the face writes nothing; the shell hears the same `pointerup` after every drop target (element handlers before window listeners) and puts the row down. **Escape clears `dragTaskId` first of everything**, before even the panels — a drag is the one thing here you can start by accident. A drop on a week-strip face names a day, never a minute: `dropTaskOnDay` takes the first free gap inside waking hours that fits (today's gaps read from now on), else `defaultStart`.
- **Every arc gesture MUST branch on `occ.task` before touching an event write — the synthetic event's id names a task, and the event list has never held it.** Shipped wrong once, instructively: `openOccurrence` fell through to the event editor over a task's occurrence, whose Save wrote nothing and whose Delete toasted "Deleted" over `store.remove(taskId)` — a no-op on events plus a live grave for the task id, which a later merge would have honoured. The routing now: **open** → the task card (`setTaskEditor`); **drag** (`adjustOccurrence`) → `movePlan` for a plan (matched by its own instants — the id alone is ambiguous across a plan list), `updateTask({ due })` for a pip; **⌘⌫** (`deleteOccurrence`) → the whole task, from a plan arc and a pip alike (`removeTask`, no scope question — the MCP delete's own rule). An earlier draft removed only the block under the pointer, and the due pip surfacing where the arc had just been deleted read as the deletion having half-worked; pruning one block lives in the task card's plan list. **⌘-drag** (`duplicateOccurrence`) → another block of the same task (`planTask`), nothing on a pip. The live preview is `previewedTasks` beside `previewed`: `DragPreview.from` carries the grabbed record's pre-drag start, which is how the shell tells which plan is being held — without it a dragged plan arc froze until release.
- **Tasks travel as VTODO now (TASKS.md §11, stage 5).** `toIcs(events, name, tasks)` writes each task as a VTODO — `DUE` (both value types), `PRIORITY` (urgent→1, high→4, normal absent), `STATUS:COMPLETED`, first plan as `DTSTART`+`DURATION`, further plans as `X-CIRCAL-PLAN` periods, `X-CIRCAL-ESTIMATE` minutes — and `fromIcs` returns `{ name, events, tasks }`, VTODOs through `buildTask` (DUE required: a dateless to-do is a different product; priority read 1–3→urgent, 4–6→high; plans through `readPlans`, the model's own validator). The named cost stands: a consumer ignoring VTODO shows nothing. **Feeds drop a subscription's VTODOs deliberately** — a read-only task you cannot tick is noise on the rim — and there is no legacy `X-CIRCAL-TASK` read: no users, no files. `.ics` import lands tasks on the new calendar in the same commit (`addCalendarWithEvents`' third argument). A `.json` backup and the mirror document carry `tasks` through `readTask` (`backup.ts`), and `merge.ts` unions them under the same stamps and graves events use.
- **Auto-schedule is `lib/plan.ts`, one pure function** — `schedule(tasks, events, calendars, waking, from, horizonDays)` → placements + unplaced, nothing written. Candidates: not done, sized, **zero plans** (a part-planned task is never topped up unasked — invariant 2's literal reading); order `compareTasks`; per day `dayAgenda` over a working copy that already holds this run's placements, `freeGaps` inside waking hours, quarter-aligned, ending by the deadline (the due minute on its day, the day's end for an all-day one). The shell's `fillFreeTime` commits through `store.applyPlans` (one ⌘Z), cues `created`, and always toasts on the hand-run (the sidebar header's Sparkles verb); `settings.autoSchedule` (off by default) re-runs it on load and on a new task id — never on plan changes, so a run cannot re-arm itself. Free is read off the visible agenda, `freeSlots`' own rule; the five invariants are pinned in `tests/plan.test.ts` (+ a `west/` spring-forward re-run).
- **`readEvent` refuses `end <= start` outright** — no task exception left. Everything with no width is a corrupt record: it draws as an arc of whole day or as nothing.

## Previews and drafts

- **One notion of "the event about to exist", both faces: range under pointer, else draft in open editor.** White and translucent while drawn (no colour yet), own colour once the editor has one. Shape identical across release _and_ save — dial's ghost path byte-identical to the arc replacing it — so neither handover looks like the drawing was thrown away.
- **Each face draws it in own units; clipping is the face's question.** `YearView` takes `{ from, to, color }` in dates, lighting those days as days that _carry_ it — `markRadius(count + 1)` in its ink, no white overlay. `Dial` takes instants, since a draft can sit on another day once its date row is edited: `drafted` clips to the day with `minutesOfDay` at each end, not elapsed milliseconds (a day is not always 1440 minutes long), returns `null` for a draft not reaching the day, 0…1440 when its middle covers it. An **all-day draft gets no arc at all**, same reason a saved all-day event gets none.
- **No preview for an event that already exists.** `App.pending` is `null` unless `editor.id === null`. Existing event has its arc and marks; a second set = same event twice, and once the editor's time rows move it the two disagree on screen. Previewing an _edit_ means replacing the arc, not adding one — what `onPreview`/`DragPreview` already does for drags.

## Sun, moon, zones

- **Your lightcycle band replaces the elapsed ring; it does not join it.** Both on `DIAL.TRACK` at `DIAL.TRACK_WIDTH`; `elapsedSegments` returns `[]` whenever band has half left to draw (`place && (daylight || moonlight)`, computed once as `band`). First attempt, second band on own radius _next to_ track, read as one line accidentally doubled. Deliberately no `DIAL.SUN`.
- **Second zone's band = a different place, so it does get its own rim.** `DIAL.ZONE_BAND` (424): 21 units outside track, 13 inside its zone numerals; `SunBand` takes `radius` for this. Halves `zoneDaylight` / `zoneMoonlight`, independent of yours — ring compares two places, half-drawn is no comparison. Coordinates from `placeForZone(secondZone)`, resolved in `App.tsx`; `null` (`UTC`, aliases like `Asia/Calcutta`) = no band, no switches.
- **Lightcycle bands = the one sanctioned break in "chrome is greyscale".** Data about the day, not chrome: warm-but-desaturated day, dim violet night, neither may compete with an event arc. Same opaque-segment technique as ring they replace, same alpha-compounding reason.
- **`light(m)` in `SunBand` MUST stay continuous through zero.** Signed light (positive sun, negative night); civil-twilight shoulders hit exactly `0` at horizon, so warm and violet meet without a step. Any discontinuity = visible rim edge; shoulders once began at `0.04`, so band began with a hard line. 288 segments (five minutes each, eight-unit chord) stops a stepped ramp.
- **Two halves = draw-time filter, not an argument to `light`.** Curve computed for whole day either way; segment loop drops half switched off, so half that stays keeps shape it had beside the other. Yours defaults on — band _is_ track; both off restores elapsed ring rather than emptying rim. Second zone's defaults off: its caption annotates a ring already there, and band is another ring. `night` = old name for `moonlight`; `migrateSettings()` in `store.ts` carries stored one across, `readSettings()` in `backup.ts` same for a backup.
- **`DIAL.ZONE` (446) fixes `PAD` (30).** Crop leaves 470 units of radius; 15-unit numeral centred on `ZONE` reaches 453; caption beside topmost runs 131 units further right — eight short of crop at worst anchor angle. Further out crops: move `PAD` before `ZONE`, keep `ZONE_BAND` _inside_ `ZONE` — caption runs horizontally outwards from numeral, would cross band.
- **Zone caption hangs off the topmost of four marks**, to its right, never beneath: beneath, it collided with hour numeral below and ran off viewBox at three o'clock. Four marks 90° apart ⇒ one always within 45° of top, where horizontal room is.
- **Zone ring measured against the viewer, never against UTC.** `delta = zoneOffset(now, zone) + now.getTimezoneOffset()` — caption reads `Tokyo +7`: you are this dial's origin, "GMT+9" makes reader subtract. Also only form staying right in weeks when one of two zones has changed for DST and other has not.
- **`sun.ts` returns minutes since local midnight and does not clip.** A place far from viewer legitimately gives negative sunrise or sunset past 1440; `Face.tsx` samples inside `[0, 1440]`, rest falls off face.
- **Place chosen by city, never typed.** `settings.place` carries IANA zone it was picked by, and `placeForZone` alone turns a zone into coordinates, so picker always shows what band draws. `store.parse()` drops a stored place with no `zone`: a band settings panel calls off is worse than no band. Coordinates from `zone.tab`, naming zone's principal city — minutes of sunrise error at worst, finer than band draws.
- **The moon lives in the sidebar, the one thing here that draws something the calendar does not contain.** Not on face: every radius costs `PAD` and legibility, and unlike lightcycle band moon is no fact about the _day_. It reads the _selected_ day, which earns it — arrowing through a week walks moon through its week. `moon: false` by default: chrome does not appear unasked.
- **One drawing, in this app's own voice.** A second register went — `Aperture`, disc occulted behind a watchmaker's window by bites of exactly its own radius, night blue with stars: mechanism was better picture, and this was circal's only chrome neither greyscale nor flat, a fight eyecandy does not win. `MOON_STYLES` / `MoonStyle` went with it; a stored `moonPhase` string becomes `moon` in `migrateSettings`, a backup's in `readSettings`, since either register was a moon somebody asked for.
- **`light(m)`'s rule again, for the moon: the terminator is an ellipse of `rx = r|1 − 2k|` over the lit half**, filled black below half, moon above. `k = 0.5` collapses it to nothing — exactly a quarter moon's straight edge; one function, all eight phases, no branch per phase. Only the **lit** part draws: no circumference, no dark limb, so a crescent is a crescent, not a disc with a crescent on it, and a new moon is nothing. Shadow stays a painted `#000000` fill, not a hole: it occludes by covering.
- **`CalEvent.tzid` is the zone a _rule_ is read against, never where an instant is.** Instants stay epoch ms, `end - start` elapsed ms; zone only decides which wall clock recurrence walk sees (`startsBetweenIn`). `""` = floating, every event user writes — an event dragged onto this dial means hours it was dragged onto. A non-empty IANA name now has **two** writers, and which put it there matters: `ics.ts`'s DTSTART reader, zone out of a file; `travel.keptEvents`, where user answered "keep them as they are" and app stamped zone they were written in. `isZone` in `time.ts` is the one validity probe (`Intl` throwing is platform's only signal), shared by both writers and by `backup.readEvent`, which drops what it refuses back to floating rather than storing an unresolvable zone.
- **The `.ics` export carries the zone and deliberately carries no `VTIMEZONE`.** DTSTART/DTEND/RECURRENCE-ID go out `;TZID=<zone>:<wall stamp>`; EXDATE/RDATE reuse the key's digits (the key already _is_ that wall clock, nothing converts); UNTIL stays UTC — §3.3.10 demands that once DTSTART carries a zone, so the stamp is required, not incidental. No `VTIMEZONE`: mainstream consumers resolve IANA names against their own tz database; a synthesised one would duplicate it or lie about DST. User-facing half: one editor `.caption`, `Times in <city>`, now on **every** zoned event, not only subscriptions' — a stamped event is one the user deliberately left on its written clock, and this row keeps that answer legible. Print-only, no picker: a zone reaches an event from a feed's TZID or that answer, never a field.
