# Repository Guidelines

## Project Overview

**circal** = calendar, day view = one dial. One revolution = one day, clockwise 0.25°/minute. Events = arcs; elapsed day = light ramp round rim; hand = current minute.

Four views, one idea at four scales: **dial** (`⌘D`) = one day · **week strip** (`⌘E`) = seven such faces at one rotation · **year ring** (`⌘Y`) = one revolution per year, one mark per day · **life grid** (`⌘L`) = every day you get, one dot each, birth date to expectancy, one viewport. All draw days in day order ⇒ moves between them = geometry, not decoration. Day ⇄ life = _zoom_: dial collapses onto that day's dot, grid wave radiates out. Day ⇄ week = _zoom_ one step less far: strip face for that day **is** the dial ~4× smaller ⇒ dial scales, translates onto it. Year ⇄ life = _unroll_: a year in day order round a circle **is** a life-grid row rolled up ⇒ ring straightens onto that row, back. Other pairs crossfade (day = neither magnified nor rolled-up year; week neither).

`Clock` sets only what the face is _called_, never geometry. `12h`: noon top, labels `12 · 1…11` twice, AM/PM captions. `24h`: midnight top, labels `00 · 1…23`. Switch = 180° rotation + relabel ⇒ arc keeps length, sweep on either face. Governs **every printed time** (readout, agenda, sidebar, palette, editor) ⇒ `splitTime` / `formatTime` / `formatTimeShort` take `Clock`; any surface printing one MUST thread it.

No account, no sync **unless a user asks for one**, no readable server-side state: user events in `localStorage` under `circal.v1`; optional cloud copy = one Postgres row per user, AES-GCM ciphertext sealed in browser by `vault.ts` (`cloudLink.ts`, `SYNC.md` Phase 2). No sign-in ⇒ app runs exactly as described, byte for byte; `supabase-js` fetched only when sync on. Ships as Cloudflare Worker: static assets + **exactly one route**, `/api/feed`, CORS proxy for ICS subscriptions, since no calendar host sends CORS headers. `supabase-js` talks straight to `*.supabase.co`, so that route stays the Worker's only one, rule intact: second route = different product; stop.

`README.md` = user keyboard table + feature tour. This file = how to _edit_ code safely.

## Architecture & Data Flow

```
src/pages/index.astro   static HTML shell  (src/pages/manifesto.astro = prose, no island)
  └─ <App client:only="react" />        ← the ONLY island in the project
       ├─ useStore()   → { events, calendars, feeds, settings }   (persisted)
       ├─ useState ×5  → location{day,view}, sidebar, editor, palette, settings
       ├─ useNow()     → ticking Date, minute-aligned
       ├─ useReminders() → the minute tick → `Notification`, when switched on
       ├─ useTitleCountdown() → the same tick → `document.title`, only while hidden
       └─ actions: ShellActions (one useMemo object)
            ├─ TopBar / Sidebar / CommandPalette / Settings  receive `actions` whole
            └─ Dial / EventEditor / YearView / LifeView      receive narrow callbacks

  Settings travel as one `settings: Settings` prop, never field by field.
```

- **`src/lib/` = domain layer**, mostly pure. One-way deps: `time.ts`, `fuzzy.ts`, `base64.ts`, `theme.ts` (base, import nothing) ← `vault.ts` ← `recur.ts` ← `dial.ts`, `events.ts`, `sun.ts`, `moon.ts`, `ics.ts`, `quickadd.ts` ← `describe.ts`, `life.ts`, `remind.ts`, `travel.ts`, `merge.ts`, `store.ts` ← `feeds.ts`, `backup.ts` ← `share.ts`, then `mirrorLink.ts` / `cloudLink.ts` last, one per transport. `merge.ts` beside `mutate.ts`, `mutate.ts`'s own reason: pure over lists, imports only `./events`, takes `Settings` as _type parameter_ not import — `store.ts` above it, merge needs no field of it. `base64.ts` carved from `share.ts`, not respelled in `vault.ts`: alphabet swap written twice = two chances for payload ends to disagree; box nobody can open has no undo step. `vault.ts` one step above, imports nothing else — passphrase + WebCrypto; no event, no day, no zone. `cloudLink.ts` at `mirrorLink.ts`'s tier, composing `store.ts`, `merge.ts`, `mirror.ts`, `vault.ts`, `notify.ts`; **the two links do not depend on each other at all**: only reference to `mirrorLink.ts` = `import type { MirrorStatus }`, compile-time erased ⇒ shared status vocabulary, no runtime edge, no drifting copy. Components import via `@/lib/*`; never reimplement geometry or date maths locally. `share.ts` last on purpose, not beside `travel.ts` where its subject fits: reads stranger payload via `backup.readEvent` rather than judging event legality itself; taking a validator from a tier = sitting below it. **Every module here has a test file** `tests/<module>.test.ts`; change one, add the case there.
- **Dependency order = _constraint_, not description — difference load-bearing.** Violated exactly once, instructively: per-event reminder leads shipped with `ics.ts` importing `remind.ts` for three lead states. Acyclic ⇒ nothing failed, no lint fired, no test could have — tier is not a type. Reader seeing imports and sentence disagree has two honest options, **move the code or change the constraint**; noting it is neither: ordering makes the graph legible, unpredictable graph = next import chosen by what compiles. Fixed by moving, along splits marks already use — see lead vocabulary under "Reminders".
- **Store = only source of truth for persisted data.** `App.tsx` holds _view_ state only. Mutations via `store.*`, never a `setState` copy of an event. Settings-only mutations (`setSecondZone`, `setPlace`, `addFeed`) called straight from `Settings.tsx`, not `ShellActions` — shell has nothing to update. `removeCalendar` = exception, also called there: calendar action, and removing a subscription is the one way a calendar leaves the settings panel.
- **Two event lists, two _keys_.** `snapshot.events` = user-written; `snapshot.feeds[calendarId]` = subscription-mirrored. `App.tsx` concatenates into `visible` for rendering, _only_ that. Only `lib/feeds.ts` writes `feeds`; nothing exports it; event whose calendar has `feed` opens read-only. `feeds` = **read model**: built from one `circal.feed.<id>` key per subscription, the one `Snapshot` field `write()` never serialises.
- **`dayAgenda(events, calendars, day)`** = single read path onto a day: expands recurrence, clips to day, packs overlaps onto concentric lanes. `Dial`, `CenterPanel` render its output; sidebar reads `occurrencesOn` directly, mini-month dots only.
- **Units.** In the dial everything = _minutes since local midnight_ (`0…1440`). `CalEvent.start`/`end` = **epoch ms**, `end` **exclusive**. Nothing below `dayAgenda` reasons about `Date`.
- **Day and view = URL.** `?d=YYYY-MM-DD&v=year|life`, written via `go()` in `App.tsx`: `push` for deliberate jump, `replace` for arrow stepping. `go` reads location from a ref, not the render closure — two `go` calls in one tick would clobber each other. `v` omitted for day view, validated against `VIEWS` inbound.
- **Panels take `settings` whole, not one prop per field.** `Dial` reads twenty-two; `Settings` thirty-seven of the interface's thirty-eight (`deviceZone` = shell's business, not panel's). Threaded individually, one new boolean meant editing six files (`Settings` interface, panel prop interface in `types.ts`, `App.tsx` forwarding, panel destructure, `backup.ts`). Counts make it rule, not preference: at twenty-two the forwarding is the file, and the four settings backup nudge + travel notice added cost the panel one line each, not six files each. Same bargain as `actions`: one prop, shell forwards nothing. Panels destructure on body's first line ⇒ bodies read as before. `LifeView` = last holdout at four fields, converted when it wanted a sixth. `zonePlace` = the one exception, own prop: shell derives it from `settings.secondZone` via `placeForZone`, so not a setting.

## Development Commands

```sh
pnpm install
pnpm dev        # astro dev — http://localhost:4321. NO /api/feed here
pnpm dev:worker # astro build && wrangler dev — the only way to exercise /api/feed
pnpm build:mcp  # esbuild → mcp/dist/circal-mcp.mjs, the MCP server's single-file bundle
pnpm build:mac  # astro build && mac/build.sh → mac/build/circal.app (1.3M)
pnpm mac        # the same, then opens it. `bash mac/build.sh --universal` for both arches
pnpm test       # vitest run — two TZ-pinned projects
pnpm test:watch # vitest
pnpm verify     # THE gate: format:check && lint && check && test && build
pnpm format     # prettier --write . (run this, never hand-format)
pnpm deploy     # astro build && wrangler deploy
```

`pnpm verify` = only gate; run before declaring done. Steps: `pnpm format:check`, `pnpm lint` (eslint), `pnpm check` (astro check / tsc), `pnpm test` (vitest), `pnpm build:mcp` (esbuild — gate exercises bundle `--external`/`--alias`; how stale published bundle once stayed invisible), `pnpm build`.

Format and lint carry `--cache` → `node_modules/.cache/` (ignored, no new entry): gate ~25s cold, ~8s repeat — difference between running it and not. Caches key config **content**, not mtime: edited rule or changed `printWidth` re-checks every file. Verified: injected rule, `printWidth` → 40, 95 files flagged either way. Fresh checkout and CI have no cache: gain nothing, risk nothing.

## Git & Commits

Commit **regularly** — one commit per coherent change, not per session. Commit spanning dial geometry + store schema + doc cannot be reverted, bisected or reviewed.

- **Conventional Commits**: `<type>(<scope>): <imperative summary>`, scope optional. Types: `feat`, `fix`, `refactor`, `perf`, `docs`, `test`, `chore`, `build`, `ci`, `style`, `revert`.
- Subject ≤ 50 chars where it fits, hard cap 72. Imperative, lowercase after colon, no trailing period.
- Scope = area, not filename: `dial`, `center-panel`, `store`, `events`, `time`, `sidebar`, `palette`, `editor`, `styles`.
- **Body only when _why_ is not obvious** from diff (rendering artefact worked around, schema bump, reverted decision). Wrap 72, bullets `-`, issue refs last (`Closes #42`).
- Never: AI attribution trailers, "this commit does X", emoji, restating filename scope already names.
- Run `pnpm verify` before committing. Gate per-commit, not per-branch.

## Code Conventions & Common Patterns

**Imports** — always `@/*` alias (`@/lib/events`, `@/components/react/types`), never deep relative paths leaving a directory.

**Formatting** — Prettier, `printWidth: 100`. `prettier-plugin-tailwindcss` sorts Tailwind classes automatically, incl. inside `cn()` and `cva()`. **Never hand-sort class strings**; run `pnpm format`.

**Styling** — Tailwind v4, config-less; theme in `src/styles/global.css`. Token utilities, not raw hex (hexes below = **midnight**'s, the default preset):

| Utility                          | Token                             | Use                                     |
| -------------------------------- | --------------------------------- | --------------------------------------- |
| `bg-void`                        | `#000000`                         | canvas, true black                      |
| `bg-surface` / `bg-surface-2`    | `#131315` / `#1d1d20`             | popovers & cards / controls inside them |
| `border-hairline`                | `rgba(255,255,255,.08)`           | every divider                           |
| `text-ink`                       | `#ffffff`                         | only pure white                         |
| `text-ink-2` / `ink-3` / `ink-4` | `#8e8e93` / `#5c5c60` / `#2e2e31` | secondary / numerals / ticks & disabled |
| `text-accent`                    | `#a3d9e4`                         | default calendar colour                 |
| `text-danger`                    | `#ff5a5a`                         | destructive only                        |

**Every token is one of three greyscale presets** — `settings.theme`, `midnight | ember | paper`, written onto `<html data-theme>` by one `App` effect; `global.css` holds a token block per preset, the bare-`:root` selector doubling for midnight so pre-hydration paint is the default install. Enumerated and `sane()`-pinned, never a theme editor: a slider is a thousand faces nobody tested. Two consequences. **White-alpha is banned in class strings** — `bg-white/10` is invisible on paper; the ladder of `--veil-05…20` (+ `--ring-40`, `--chip`, `--on-accent`, `--scrim-a/b`) exists per preset with the direction flipped, used as `bg-(--veil-10)`. **A canvas or computed SVG colour never spells white or black** — `fillStyle` cannot read a token, so `lib/theme.ts` carries `THEME_PALETTES[theme]` (ink, tick, numerals, accent, empty mark…) and `wash`/`washHex`, a lerp from the theme's own void that on a black void is byte-identical to the multiply it replaced (pinned in `tests/theme.test.ts`, with the contrast floors: ink ≥ 7:1 on void, ink-2 ≥ 4.5:1 on surface, accent ≥ 4.5:1 as small text). `Face`, `Ring`, `drawField`, the loupe and the moon all take `theme` for exactly this.

`fill-*` / `stroke-*` variants exist for SVG. Component classes: `.label` (uppercase 11px mono, label voice), `.caption` (12px sans `ink-2`, prose voice — anything reading as sentence), `.kbd`, `.fade-y` (masks both ends of scroll area), `.fade-b` (bottom only, proportional — short list, first row stays crisp), `.no-scrollbar`. Pair fade with `.no-scrollbar` on every scroll region; fade **only when the list actually overflows** — permanent fade on fitting list reads as rendering fault. Chrome greyscale by rule: **colour belongs to events.** Never read `calendar.color` or `event.color` directly — call `colorOf(event, calendars)`: event override first, else its calendar. **Touch targets grow, they are not padded.** Every mouse-sized control in `primitives.tsx` carries `pointer-coarse:` variant sized for fingers — 40px `IconButton`/`ActionPill`, 36 a `Segmented` item, 34 a position cell, 30 a swatch. **`ColorPicker` is a 5 × 2 grid, not a wrap.** `PALETTE` = one walk round hue wheel (aqua 174° through mint 150°); ten in two rows of five reads that walk as text reads, wheel closing where row two ends and row one begins. Two swatches that are _not_ a colour — inherit-the-calendar, any-colour — own column beside it behind one divider: column is one or two cells by turns, block of ten must never change shape. Wrap divided eleven or twelve cells by whatever column was, landing six and five. On `pointer-coarse` column takes `w-full`, drops to own line, divider hidden: 34px cells leave no room beside five-wide block; line break = separation divider drew.

**State sync — hard convention.** `react-hooks/set-state-in-effect` active: effect copying props into state rejected. New props must reset local state → use React render-phase adjustment (three sites: `Sidebar.tsx`, `EventEditor.tsx`, `CommandPalette.tsx`):

```tsx
const [seeded, setSeeded] = useState(day);
if (seeded !== day) {
  setSeeded(day);

```

**Effects for external systems only** — `window` listeners, `ResizeObserver`, timers.

**Hotkeys** — `useHotkeys({ "mod+k": fn }, enabled?)`. Combo: optional `mod+` (⌘ or Ctrl), optional `shift+`, then lowercased `e.key` (`k`, `escape`, `arrowleft`, `t`). `shift+` belongs to combo whenever Shift held, printable keys included — without it `⇧⌘Z` and `⌘Z` are one string, redo becomes undo. **Modals** — `const dialog = useFocusTrap<HTMLDivElement>(open)` on `role="dialog"` element. Three dialogs, one hook, no `<Modal>` wrapper: palette = combobox, editor = form, settings = sheet; share this behaviour, nothing else.

**TypeScript** — `strict`, no `any`. Prefix intentionally unused bindings with `_`.

**Comments** explain _why_, never _what_. Most non-obvious decisions carry one; read before changing a line.

## Gotchas

### Faces, dial, week strip

- **`dayKey()` deliberately local-time.** `toISOString()` shifts the day west of UTC — where day-keyed store breaks. Never swap in.
- **`Face.tsx` draws a day; `Dial.tsx` makes one editable — split by _question_, not size.** "What does this day look like" (geometry, rings, arcs, labels, band-replaces-ramp) → `Face`; "what did that gesture mean" → `Dial`. `Face` takes `svgRef` + pointer handlers, never owns them: capture belongs to whoever reads coordinates. Rings outside arcs opt-in, **off by default**; a `Face` with no `onGrab`/`onHover` draws no hit strokes = read-only face. New dial switch enters `Face` props only if it changes what is _drawn_.
- **Every id inside the face comes from `useSvgId`** — `url(#…)` and `<textPath href>` resolve to _first_ matching id in document ⇒ hardcoded gradient id is right for one face on screen, silently wrong with more. Glow, now-hand gradient, both band masks, every arc label mint their own; anything new needing `#` too.
- **Week strip read-only**, keeping `<Face>` honest: 7 faces of drag targets = 7 chances to edit wrong day, and dial is one keystroke away. `WeekView` passes no `onGrab` ⇒ no hit strokes ⇒ 7 × 0 pointer paths, not 7 × 19. `onHover`/`onFocus` only name the day for shared readout. Face = real `<button>`: 7 tab stops is a usable order ⇒ no `sr-only` listbox (year ring 365, life grid 30,000 need one; as life grid's three milestone buttons).
- **Strip's elapsed ramp on today alone; its rim on every face.** A past day's ramp is full bright ring answering "all of it" — nobody asked — and shouts down neighbouring arcs ⇒ `elapsed` and `hand` both `d.today`. The other six need something to place arcs against ⇒ `Face`'s `track`: one circle at `DIAL.TRACK`, at ramp's floor, so on today ramp reads as that rim lighting up. The one stroke drawn **translucent not opaque**: `TRACK_WIDTH` = three units, two fifths of pixel at strip size ⇒ rim exists only as antialiased fraction browser rounds it into, and opaque grey has no fraction to give. Nothing overlaps it ⇒ no alpha compounds.
- **Day ⇄ week scales _and translates_; no `transform-origin`.** The panel carries one already (life dot) and dial must land on its face whatever that origin is. Under `scale(s)` about origin `o`, `c` lands at `o + (c - o) * s` ⇒ panel centre onto face centre `f` needs `t = f - o - (c - o) * s`. `App.face` solves it once; `weekZoomScale` supplies `s`, tested on what matters: dial's drawn diameter = `layout.size`. One eased tween, not `ZOOM_STEPS`' geometric ladder — ~4× zoom, not two orders of magnitude; ladder over that distance reads as a stutter.
- **`flow.current` is reassigned wholesale ⇒ `face` MUST be carried across it.** `go()` and popstate each build new `ViewFlow`; a field effect wrote into old one dies on next view change — hence `faceFrame`, its own ref both writers copy forward. New `ViewFlow` field = three places: initial `useRef`, `go`, popstate.
- **⌘W is not available to any web page** (Chrome, Safari, Firefox): closes tab, keydown never delivered — unlike ⌘D / ⌘Y / ⌘L / ⌘P, mere menu equivalents this app overrides already. Week = **⌘E**, no mnemonic and needs none: the `Segmented` control prints chip, how every view key here is found.
- **Strip's readout lives outside scroll container.** Inside, it centres on content — wider than window once 7 faces do not fit — and sentence walks off side. Same reason selected face is `scrollIntoView`d on arrival, not left wherever Monday put it, and not smoothly.
- **The strip's three parts are one group, centred together.** 7 circles in a row are ~a seventh of width tall ⇒ landscape window leaves much black under them, and readout pinned to panel's foot captions window, not strip. `weekLayout` returns `groupTop`/`groupHeight` covering captions + faces + readout; leftover height stays outside group.
- **`angleAt` and `minutesAtPoint` are exact inverses** and MUST stay so. Both take `Clock`, differ only by `origin()` — minute at top (720 for `12h`, 0 for `24h`).
- **`arcPath` draws full turn as two half-arcs**: one elliptical arc with coincident endpoints renders nothing. Drop branch, whole-day arc vanishes.
- **A gradient built from overlapping strokes MUST be opaque.** Elapsed ring = chain of arcs; translucent ones compound alpha at overlaps, every join a bright bead, trail reads as tick marks. On true black, opaque grey = translucent white ⇒ `Face.tsx` ramps _colour_ (`grey(level)`), butt caps between segments, rounds only run's two ends.
- **Now-hand stops at `DIAL.HAND_INNER` (205).** A hand through centre crosses readout and agenda — ink on time readout prints. It is a spoke: pip on track at exact minute, fading out along a `userSpaceOnUse` gradient before centre panel. Panel grows ⇒ `HAND_INNER` MUST clear its furthest corner: with totals line on, lowest thing sits ~135 units below centre and 113 out ⇒ corner = 176, 29 units in hand.
- **The strip is read-only about events and _writable_ about days — one gesture, and it is the ring's.** Press, drag across faces, release: press that never left its face is still a click on that day; wider = run of whole days into same `onCreateSpan` year ring and life grid use ⇒ editor cannot tell which face drew draft. Costs no drag targets, no arc grips — keeping "read-only" true where it mattered: 7 faces of grips = 7 chances to edit wrong day. Run live ⇒ every covered face draws `GhostArc`'s closed ring through `Face`'s own `ghost` channel — dial's picture of "a whole day being drawn", white/translucent at `GHOST_ALPHA` (exported from `Face.tsx` beside `GhostArc` so strip and dial cannot drift to two alphas) — today's hand recedes via `gesturing`, per-face hover suppressed, shared readout prints `formatDayRange` + count; a card naming one end of run answers a one-answer question twice. Escape abandons it, from strip's own registration, as `Dial` does. Face under pointer from `weekFaceCentre`, never DOM: 7 comparisons against numbers view has, and hit test cannot disagree with drawing. Pointer path is `pointerup` ⇒ faces' `onClick` takes `e.detail !== 0` to keep keyboard activation working.

### Centre panel / readout

- **Centre = one display, four moods, ordered.** `CenterPanel.tsx` resolves `span` first (range being dragged, else arc under pointer), then today's time, then date. Drag and hover print _same_ thing — same question — so they share branch. Size change = CSS `font-size` transition, 140 ms on `var(--ease)`, matched to the arc's stroke-width transition: arc thickening and clock shrinking into its span is one movement; split curves read as two events.
- **Headline row = first _timed_, non-past occurrence, only on today.** An all-day event is context, never next thing, never `running` (`Now … ends in 10h 4m` = countdown to midnight dressed as appointment). Headline drops start time (the ring holds it), spends width on name and wait; `untilText` rounds _down_ — a countdown overstating time you have is worse than none. Under `IMMINENT_MS` dot takes a ring, not a pulse: pulse means "running" already, one signal cannot mean two things.
- **Hovered occurrence added back to the card even when ended.** Today's card filters `occ.end > now`; without exception, pointing at morning arc printed span with no name. Costs one row of shift while pointer is on past arc — honest position for it.
- **`totals` measured against two different windows on purpose.** Booked = whole revolution (a six o'clock run is time spent); free = only `WAKING` — "nineteen hours free" is not offer. They sum to nothing, nobody adds them. `WAKING` lives in `events.ts` beside `freeGaps`; palette's slot search and this line MUST mean same thing by the word.
- **`totalsAt` places line against _stage_, not dial.** `center` = only one rendered inside panel's column, under the card; other eight = `flex` layer at `inset-0` with `p-4` ⇒ corner is _window's_ corner — black a circle in landscape window never reaches. `CORNERS` in `CenterPanel.tsx` maps them, deliberately with no `center` key: that position is not corner of anything.
- **A task's readout is one instant, not span.** `peekedTask` splits out of `peeked` ⇒ pointing at one prints `01:15 DUE`, not `01:15 – 01:15 · 0m`, three ways of saying nothing. Still shrinks clock (`aside`, not `span`): readout answers about something other than now, what size change means.
- **No `backdrop-filter` on element also carrying `.fade-y`** — Chromium paints blur over box far larger than element, appearing as grey rectangle mid-dial (see comment in `CenterPanel.tsx`).

### Drag gestures

- **Ring drag accumulates sweep; never measures from grab.** `Draw` holds `{ from, at, sweep }`; `onRingMove` sums `wrapDelta` per pointer event, as the arc's drag does. From grab, new event caps at twelve hours and inverts past that — `wrapDelta` takes short way. Sweep clamped to `[-from, 1440 - from]`: clamping _sweep_, not resulting instant, stops range dead at midnight and follows pointer back moment it turns, instead of unwinding overshoot first (same reason as `clampDelta`).
- **Arc drag accumulates `wrapDelta` per pointer event; never measures from grab.** Two ring positions do not say which way round pointer went ⇒ delta from grab flips sign once drag passes twelve hours. Summing short hops lets drag cross midnight as often as it likes.
- **Minimum duration clamped on `delta`, not on resulting instant** (`clampDelta` in `Dial.tsx`). Clamping end banks overshoot: the arc lags by far pointer ran past limit before following back. Clamping delta stops dead, releases instantly — and since sound fires only on delta change, clamped arc goes quiet: feedback saying "this is as short as it gets".
- **A press on an arc that never changed delta is a click.** `onArcUp` opens editor when `delta === 0` — also whole implementation of read-only arcs: subscription's occurrence gets `grip: "none"`, `clampDelta` pins it to zero, press falls through to opening. No separate `onClick`.
- **`Escape` abandons gesture in flight**, from `useHotkeys` inside `Dial`, not shell's: `setDraw(null)`, `setAdjust(null)`. A drag is one thing here you start by accident; before this only exit was letting go, which committed it. Pointer stays captured on purpose — move and up handlers bail on missing gesture ⇒ release does nothing, no cue because nothing happened.
- **Full revolution = all-day event; `draftEvent` decides.** Span ≥ `MINUTES_PER_DAY` becomes `allDay`, instants snapped to the day's two midnights ⇒ ⌘N, palette and ring gesture agree. `CenterPanel` prints `All day` while such drag is live — gesture should say what it will make; the arc vanishes on release, since `EventArc` draws nothing for all-day event.
- **More than one revolution = that many all-day days, same function.** `Math.round(span / MINUTES_PER_DAY)` ⇒ dial's exactly-1440 sweep (its own clamp) stays one day, year ring's `n × 1440` becomes `n`. All-day `end` = `addDays(startOfDay(day), days)`, **not** `base + n × 1440 minutes`: a day is not always 1440 minutes, so span across spring-forward landed `end` at 23:00 on last evening instead of midnight after it — and `end` is exclusive, so trip's last day fell off dial. Latent at n=1 before year ring existed; same fix either way.
- **A whole turn is drawn closed — a second rule from same fact.** `capInset` shortens an arc half stroke each end so painted length = duration — but once ends meet inset is a notch at midnight, and a circle with a notch reads as a rendering fault. `GhostArc` returns `<circle>` for full-day range; `EventArc` drops inset at `to - from >= 360` (a timed event through whole day = any multi-day event's middle).
- **⌘⌫ deletes the arc under pointer; the key lives in `Dial.tsx`** — dial owns hover, so it owns press (as Escape's gesture-abandon). What a delete _means_ stays shell's: `onDelete(occ)` up, one-off straight through `store.remove`, repeating one gets same `ScopeDialog` drag gets, in danger colour. Off while `covered` (the shell's `busy`) — editor has its own ⌘⌫, two handlers on one press delete two different events; off mid-gesture — drag in flight is about to write that arc; never on subscription's occurrence. It **always toasts**: editor's Delete is two deliberate presses inside modal, this is one keystroke, and destructive key with no receipt is a key nobody presses twice.
- **⌘ held at grab duplicates instead of moving; modifier is read once.** `Adjust.copy` fixed at `onArcDown`: a ⌘ let go halfway would turn duplicate into a move of thing being copied — one outcome nothing undoes in single step. Only `grip === "whole"`: duplicate is a move of copy, so end grip is a resize whatever is held, and `grip: "none"` means subscription's arc is never copied either. While copying, `onArcMove` **withholds `onPreview`**: original must stay exactly where it is, and thing following pointer is `copying`, draft's own `FaceGhost` channel in event's own colour. Nothing written until release, and release asks **no `EditScope` question** — three scopes say which occurrences edit reaches, and duplicate reaches none.
- **A duplicate carries whole event, rule and all; `duplicateOf` (`store.ts`) is one place that says what "the whole event" means.** Deltas apply to event's own instants — plain drag's reading — so ⌘-dragging one occurrence of weekly standup returns weekly standup hour later. Three fields deliberately do NOT travel: `seriesId`/`seriesKey` name a relationship to another event, and two events cannot claim one occurrence; `doneKeys` tick work done once. Three MUST travel **with shift** not beside it: `until` bounds start; `exdates`/`rdates` name instants — series moved hour later keeping old keys fires on every day original skipped. A day-form key re-emits as a day, carrying whole-day exclusion across drag that crossed midnight.
- **⌘P duplicates through editor; asymmetry is point.** A gesture named time ⇒ drag writes and toasts; palette named none ⇒ unmodified copy would land exactly under its original, toast its only evidence. `actions.duplicateEvent` seeds `setEditor({ id: null, draft })`, commits nothing until Save ⇒ Escape leaves no orphan. Goes to original's own day first: editor over a face that cannot show what is being edited is a form.
- **`onRingMove` and `onArcMove` bail when snapped minute has not changed.** Makes clicks countable (one per fifteen-minute step, not per pointer event) and drops re-render `pointermove` would cause. `cue()` has its own 22 ms floor for same reason: fast flick crosses steps faster than ear separates them.
- **Lane packing is face-independent.** `dayAgenda` takes no `Clock`: both faces put one day on one revolution, so two events collide on screen exactly when they collide in time.

### Arc labels

- **Arc labels live _inside_ stroke — geometry, not taste.** `LANE_STEP - ARC_WIDTH` = 13 units of black between two lanes, and hour numerals come down to 333 just outside first ⇒ label _beside_ an arc works on outermost lane and nowhere else. Inside 14-unit stroke: 11px of mono, 3.1 units of arc either side, identical on every lane, costing no radius — the "do not add a ring" rule again. Also `inkOn(color)`, black on event's own pastel at ~10:1, strongest pairing this face has; grey on black beside the arc would be weakest. **Except on free arc, where there is no pastel to be black on** — see "Busy and free".
- **The label's budget is glyphs measured against _paint_, never minutes and never centre line.** `arcLabel` takes the arc's painted ends (span less any seam neighbour claimed): round caps put half stroke back past `head`/`tail`, and label handed the `capInset`-shortened span forfeits 14 units per arc — every half-hour event going anonymous (it did). Mono ⇒ width is arithmetic: no `getComputedTextLength`, no layout read per arc per frame of drag. Where gate lands in minutes is _consequence_ (a word from about 45 minutes, a stub from about 30 out at rim, nothing on inner lanes) ⇒ duration threshold would label event at rim and crop same event two lanes in.
- **A glyph takes its up-vector from path's direction, so bottom half is drawn backwards.** `arcPath` grew a `back` flag: same arc traced anticlockwise from `to` to `from`, invisible on stroke and whole difference between readable label and upside-down one. `arcLabel` reverses whenever the arc's midpoint is between 90° and 270°; flip must land somewhere and at three and nine o'clock text is vertical either way. From _drawn_ angle ⇒ both faces get it free.
- **The label keeps full alpha on dimmed arc.** Ink here is _absence_ of light ⇒ dimming it with body takes both towards black behind and the name disappears at ~1.5:1. Left alone it softens from about 10:1 to 4.8:1 as the arc recedes — the hierarchy dimming asked for. In `hover` mode it is mounted at `opacity: 0`, not mounted on hover: it arrives in same beat stroke grows by 3, and text popping in on growing arc reads as a wobble.
- **A mark on an arc costs two glyphs of label's budget, and never the name.** `arcLabel` takes the mark, prices it at `ARC_MARK_GLYPHS`, rides it along **only** while what is left clears `ARC_LABEL_MIN` on its own — tight arc drops the glyph, keeps the word: a symbol shared with everything on one calendar is worth less than a name's last two characters. Pair centred as unit: `startOffset` pushes text out by half the mark's slot, the glyph sits at _start_ of that slot so all slack lands between it and first letter, and both flip through bottom half with path. `MarkGlyph` is SVG-native renderer for exactly this; `CalendarMark` answers a `<span>` for emoji and dot for nothing — neither legal inside an `<svg>` nor wanted on an arc already carrying its colour.

### Busy and free

- **An event is busy or free, and `CalEvent.free` says which — explicitly, never inferred.** As with `task`: nothing about span says how seriously it is meant, so reading it off title, calendar or zero-width end would be typing data by coincidence. Busy is default _and_ absent value, keeping a field arriving in old blob harmless. `TRANSP` on wire (`TRANSPARENT` = free, `OPAQUE` and absent property = busy), named for the word editor prints, not property: property is a spelling, idea UI must say out loud. Same checklist `task` was: `hydrateEvents`' shape fast-path (a field left out of that question is a field blob never gains), `readEvent`, `duplicateOf`, `importIcs`, `feeds.ts`, `mcp/domain.ts`'s patch path — last sharpest: assistant editing free event's title would otherwise hand back rebooked one.
- **Hollow, because other two encodings were already taken.** Alpha is spoken for: past arc draws at `0.42`, so "free" = "fainter" makes past meeting and future placeholder one picture. A dashed stroke reads as tentative — a third meaning nobody asked for, on a face where dash must also survive a fifth of its size on strip. `hollowPath` (`dial.ts`) traces outline half hairline **inside** filled arc's own silhouette ⇒ stroking at that weight paints exactly same footprint: same radius, same lane, ends where round caps land, `capInset`'s promise — painted length is duration — untouched. A caller hands it same `from`/`to` it hands `arcPath`.
- **`ARC_HAIRLINE` is `ARC_WIDTH / 8`, derived and not chosen.** The same `<Face>` draws 7 to a row on week strip at ~a fifth of dial scale ⇒ weight picked against dial's own pixels means something else there. An eighth leaves ten units of black between two edges — wider than the `SEAM` two neighbouring arcs keep — so hollow reads as a hole, not thick line.
- **One construction, three shapes, each for rule that already existed.** Full turn = two concentric circles, closed and uncapped: inset once ends meet is a notch at midnight (`arcPath`'s own rule). Degenerate sweep = two caps alone, a ring — hollow of dot filled path collapses to. Everything between = racetrack: out along far edge, round cap, back along near one.
- **Hover changes weight, not width.** A filled arc grows three units on CSS transition; outline's width lives in path data and path swap cannot tween ⇒ hovered free arc doubles hairline instead. Footprint never moves, and feedback still lands in same beat as label's fade.
- **The label had to change ink, and this is part that would otherwise have shipped broken.** `arcLabel` draws the name inside stroke in `inkOn(color)` — black on pastel, the face's strongest pairing — but inside outline the arc is mostly black behind it, so that black is not dim, it is _absent_. A free arc's label and its mark glyph take event's **own colour** (`labelInk` in `Face.tsx`): every `PALETTE` entry is high-value pastel reading on true black at same order of contrast black-on-pastel had; it is colour of line it sits in, so pair reads as one object; and colour dark enough to fail here fails outline in same breath — label and arc cannot disagree about whether event is legible. Full-alpha rule on dimmed past arc unchanged.
- **A task is never hollow, and that is decision.** It books nothing already ⇒ "free" has nothing to withhold — and its pip's filled/hollow pair is spoken for: filled is open, hollow is done. One shape cannot carry two meanings on one face, rule that keeps a pulse from meaning both "running" and "imminent". The editor does not offer switch on task at all. An **all-day event still draws no arc**, free or busy, as before.
- **The point of feature is arithmetic, not picture.** `freeGaps` books no block for free occurrence ⇒ `dayLoad`'s booked total stops counting birthday as hour spent, and palette's slot search follows for nothing — it reads `freeGaps` already. What counts as booked changed; window it is counted over did not — booked against whole revolution, free against waking window, still not summing to anything.
- **Measured on strip, and answer is why there is only one encoding.** The two edges do not merge at any size strip draws: at typical desktop strip hairline is 0.625 css px with 3.75 css px of black between edges; at `WEEK_MIN_FACE` — smallest face `weekLayout` will draw — 0.252 css px with 1.515 between them, a faint hoop beside a solid lozenge, confirmed in 1:1 screenshot not argued. Merging needs gap under about one device pixel ⇒ a face roughly a third of strip's own floor. So no second encoding for small faces: one that degrades gracefully beats two that can disagree about what same event is.

### Tasks

- **A task is explicit `CalEvent.task`, never "`end === start`, therefore a task".** A degenerate span is arithmetic coincidence, and typing data by one is how five-minute event dragged to nothing silently becomes a to-do. The flag comes _with_ `end === start`, making rest free: dial's sub-cap dot-collapse draws a pip at right minute already, `freeGaps` drops zero-width block on its own, `dayLoad` sums nothing. Two things needed line each — `occurrencesOn` measures day-overlap against `Math.max(duration, 1)`, or task at exactly midnight is thrown away by exclusive `end`; and `packLanes` returns task untouched, so a pip neither buries nor is buried by meeting it happens during. **Undated tasks are deliberately not modelled**: a list with no day on it is different product wearing this one as a skin.
- **`doneKeys` = list of `instantKey`s, for reason `exdates` is one.** A repeating task is ticked one occurrence at time; boolean on series would tick every Monday at once. Always datetime form — day-only form `exdates` also carries exists because EXDATE has two RFC value types, and nothing outside this app writes these. `Occurrence.done` resolved once in `occurrencesOn`: `dayAgenda` is one read path onto a day, and a list lookup is not renderer's job. **A tick asks no `EditScope` question**: per-occurrence is only thing it could mean.
- **Filled while it stands, hollow once done — on every surface.** Rim pip and interior tick target are same two shapes ⇒ the mark you press and the mark you see on the face are one mark. Opposite of checkbox convention, deliberately: on this face ink is _light_, so emptied pip reads as spent. In the list strike through the name is primary signal, the pip only the control. **`CenterPanel`'s row is therefore a `div` with two buttons**, not one button — a control inside a control is not thing HTML has.
- **A task's ICS = VEVENT with no DTEND, plus `X-CIRCAL-TASK`.** §3.6.1 requires DTEND strictly later than DTSTART, and same section says DATE-TIME DTSTART on its own ends when it starts ⇒ spec-legal spelling of zero-length event is to omit property. `buildEvent` reads flag _before_ computing `end`: hour-long fallback for missing DTEND MUST stay for everybody else's VEVENTs (reading those as zero-length would collapse every unterminated meeting onto rim). VTODO was other option and is worse: circal models the half of VTODO that has a day and minute, and consumer ignoring the `X-` lines still shows task at right time on right day.
- **`readEvent` lets `end === start` through only for task**: guard is `task ? end < start : end <= start`, not blanket loosening. Everything else with no width is corrupt record — it draws as an arc of whole day or as nothing.

### Invitations: read, never answered

- **Reading an invitation and answering one are separate features; only the first exists.** Emailed `.ics` names who asks and who comes; import discarded both — `ORGANIZER`/`ATTENDEE` now read, stored, shown, written back. Answering is a **message**: no account, no server, no outbound channel, none coming. Hence no verb, no button, no add-guest control, nothing resembling a reply. `AUDIT.md` drew that line first: the reply half "needs a channel this product has refused; **reading** an invite and showing who is coming does not".

- **Three fields; the third keeps the other two honest.** `organizer`, `attendees`, `attendeeCount`. Count separate: the one fact truncation destroys. Editor prints "and 40 others" from the number that _arrived_, not the length that fitted — no cap shrinks a thousand-person announcement to thirty-two colleagues.

- **`PARTSTAT` collapses to four states; unmodelled reads "invited".** `PARTSTATS` = `needs-action` / `accepted` / `declined` / `tentative`. `DELEGATED`, unknown, absent → `needs-action`: RFC default, the only one claiming nothing about intent. `Declined` asserts a refusal nobody made, `Accepted` attendance; the delegate arrives as its own `ATTENDEE` line with its own status, so somebody _is_ coming is already listed — only the relationship is unsayable. Label **"Invited"**, not "No reply": "invited" fits delegation and silent guest, "has not replied" is false for the first. `PARTSTAT_LABELS` beside the vocabulary, not the editor — `REPEAT_LABELS`' rule: word and value, one decision.

- **`ROLE` and `RSVP` read by nothing, deliberately.** Required-vs-optional changes nothing this surface says or the arithmetic does; the organiser is the only different job, with its own field. `RSVP=TRUE` asks for an answer — that demand beside no way to meet it is the actionable look the feature refuses.

- **`METHOD` neither read nor written — sharpest decision in the feature.** It separates `REQUEST` from `PUBLISH`, `REPLY`, `CANCEL`; each reading pays off only in the refused half: `REQUEST` wants an Accept button, `REPLY` patches a status onto an event already on the dial from a mailed file, `CANCEL` deletes somebody else's event on their say-so. Outbound worse — `METHOD:REQUEST` claims to _organise_ a meeting it only read: how a consumer starts replying to the real organiser. Pinned by test: `REQUEST`, `REPLY`, `CANCEL` read as one kept event with its people; `toIcs` never emits it.

- **Every cap names its threat; one is derived.** `readGuests` in `events.ts` owns all caps for its three readers (`ics.ts`, `backup.readEvent`, `store.hydrateEvents`) — `readRecurrence` shape: three copies = three opinions on when a calendar is too big. `ATTENDEE_MAX` = **32**: above lists people read down, below where names become a distribution list. Threat: a mailing-list invite of thousands of lines inside the one ~5MB origin quota `FEED_BUDGET` already carves 2M characters from; `trimFeed` can't help — it drops whole events, blind to **one** event of megabytes of addresses. `GUEST_NAME_MAX` = 64: a pasted paragraph in a `CN`. `GUEST_ADDRESS_MAX` = **254** = RFC 5321 §4.5.3.1.3's forward-path ceiling, derived not picked: nothing longer is a mailbox, so nothing longer is a truncated address. Duplicates collapse on lowercased address: merged replies restate a line, one person twice lies about size. `attendeeCount` clamped never below the list it labels — it reports what the cap dropped: no "and −3 others".

- **`duplicateOf` drops the guests.** A duplicate is your own event, not somebody's invitation — the argument keeping `seriesId`/`seriesKey` and `doneKeys` home. Nothing here mints a guest list, so the row is absent from everything the user wrote.

- **Display only; every choice avoids looking actionable.** `Guests` row renders `null` unless there's something to show — never an empty field inviting input. Organiser sits _outside_ the scrolling list: it answers "who is asking", must not scroll away; full `ink` against guests' `ink-2`, greyscale both, colour on this face belonging to events. Name or address, never both — 320px fits one, the name answers "who" — address on the row's `title`, its only copy on screen. Statuses are `.label` tags: three words at label weight, not a sentence. `.fade-y` only past `GUEST_ROWS`: a permanent fade on a list that fits reads as a rendering fault.

### One event in a link

- **Payload rides in the URL _fragment_ — this project's constraint, not a preference.** A fragment is never sent to a server; a query string goes on every click and lands in a log. circal has one route and no server-side state, so an event in a query string breaks that promise for whoever pasted the link — the sender leaks, never knowing. `shareFragment` and `shareToken` are the only places the fragment's spelling lives, so nothing downstream can move it. Nothing stored, nothing to expire, nothing to take down: why this is a link, not a service.

- **`.ics` still answers every other calendar; this is the circal-to-circal path.** Rule, mark and colour survive it, not an export to a product with no vocabulary for the last two. A link another app can't read is no defect — it is why the format may be this small.

- **The link is not private, and the app says so as it is minted.** Encoding, not encryption: link-holder = event-holder. Makes the feature work, fatal if a user assumes otherwise — so the copy notice is confirmation and disclosure in one line, not a comment no chat reader sees.

- **Record is positional, and compactness' cost is stated because somebody will want to "clean it up".** Field names run longer than most values they'd label: positional fields, base36 numbers, epoch **seconds** (nothing writes sub-minute instants — dial snaps to fifteen, `parseClock` to one), duration as a delta off the start, not a second absolute instant, trailing empties dropped ⇒ ordinary timed event = four fields, **34 characters against 512** for JSON-plus-base64, pinned by test so a "tidier" format must beat a number. Price: unreadable by eye; fields **appended, never reordered** — what `SHARE_VERSION` leads the token for.

- **base64url's +33% buys a guarantee instead of a guess.** Alphabet `A-Za-z0-9-_`: no title character can need percent-encoding, escape the payload, or be eaten by whatever linkifies the message. Hand-escaping Unicode into a URL-safe subset is a percent-encoder with a different sigil — three bytes per accented character, a table to get wrong. `CompressionStream` is asynchronous, unusable by a synchronous format called from a click handler.

- **Four check digits exist because driving it found the bug, not a spec.** A link cut short on a base64 boundary — chat client breaking a line, half a link pasted — decodes into a _plausible_ event with its last field silently altered: the hostile case shape can't catch, bytes legal, instants fine. `shareCheck` = four base36 digits of the repo's existing `fnv1a`, 1.7 million values for five characters of link, already this codebase's answer to "is this the same content". Refusal is correct; a wrong event that looks right is not.

- **Travel decided field by field; every absence has a reason.** Guests don't: links go to group chats, circal can't send invitations, so a guest list here is somebody else's. **id** doesn't: one id naming two events in two calendars is what a later import merges. `seriesId`/`seriesKey` name a relationship to an event not in the link. `doneKeys` tick the sender's work: a shared task pre-ticked is a to-do list that lies. `remindLead` doesn't: absent it arrives as `REMIND_INHERIT` — "follow this reader's own setting". Calendar is the receiver's. `duplicateOf`'s rule a third time, now general: **a copy carries what the thing is, never what its relationships or somebody else's answers were.**

- **All-day travels as a day key and a count, never instants.** An epoch second minted in Berlin is mid-afternoon of the previous day in Los Angeles — birthday arriving on the 7th. `allDayInstants` rebuilds this reader's two midnights from `20260308` plus a day count, `addDays` not `n × 1440` minutes, as every multi-day span here does.

- **Receiving opens the editor, writes nothing.** A link silently adding an event: the one thing here changing your data because somebody messaged you. ⌘P-duplicate's path — `setEditor({ id: null, draft })` — seeded **during the first render**, not an effect: the right day is never rendered wrong then corrected, and effects copying into state are the convention this repo rejects. Reads `store.snapshot()`, not props, for the default calendar: the store hydrates at first subscribe one commit later — travel notice's lesson again. `writeLocation`'s construction clears the consumed fragment: a reload re-offers nothing.

- **Share sits in the editor's footer, nowhere else.** Not the palette: its per-event second verb is already Duplicate, one modifier meaning two things on different rows being the bug `Row.alt` avoids. Not a dial keystroke: a key silently copying your calendar to the clipboard shouldn't exist. It **is** on a subscription's event, outside the disabled fieldset: sharing is copying, not editing.

### Reminders

- **Reminders never catch up; hence the one-minute window.** `dueReminders` fires only what comes due in `[target, target + 60_000)`; a notification for a meeting that started an hour ago (tab asleep, lid shut) is worse than none — test is "due this minute", not "not yet fired". Also **floors `now` to its minute**: `useNow` fires ms _after_ `:00`, and an unfloored window from `10:17:00.09` misses every event exactly on `10:17:00.000` — all of them. All-day never fires (no minute to count down to), tasks do (a to-do with a time most deserves a nudge), ticked ones don't. Per-event leads changed only _which_ lead an occurrence is measured against.

- **`Notification.requestPermission()` called from the settings switch, nowhere else.** Chrome and Safari honour it only inside a user gesture, `useReminders` runs off a timer ⇒ the hook checks `permission === "granted"`, else nothing. Switch goes _on_ only if granted came back, else the panel promises what the browser won't keep. Reminder `tag` = occurrence key so the platform collapses duplicates; `fired` is the in-memory belt, React invoking effects twice in development.

- **The inherit chain is event → calendar → setting, each level `colorOf`'s shape.** `CalEvent.remindLead` and `Calendar.remindLead` share the three-state vocabulary; the default names nothing and follows the next level down, so moving the setting still moves every event and calendar that never asked for its own — what makes a global preference worth having beside the per-record fields. `leadOf(event, calendars, fallback)` is the sole reader of that precedence, as `colorOf` is of colour's, returning `null` for "nothing fires" so callers can't read silence as zero. A calendar's silence quiets every inheriting event on it; an event's own lead or silence outranks its calendar's either way.

- **Three states in one number; the encoding is the argument.** A lead is minutes _before_ a start, countable one way, leaving the negative half-line free for non-minutes: `REMIND_INHERIT` = `-1`, `REMIND_SILENT` = `-2`. `0` keeps meaning "tell me as it starts"; `0` doubling as off or absent would make the one lead time this app was built around unsayable. `REMIND_LEAD_MAX` (four weeks) bounds nothing the editor writes and everything an imported `VALARM` or hand-edited backup can: a `TRIGGER` of `-P400D` can't put `dueReminders` on a day four hundred days out every minute.

- **Silence is a state, not a convenience.** Per-event control lets a recurring thing you know about stop nudging; without a third state, silencing one event means switching reminders off for all — the trade the field avoids. Silent is skipped whatever the setting says.

- **One day per _distinct lead_, not one per event.** A lead is a property of the event: a 60-minute lead looks into tomorrow, a 0-minute one at today. An occurrence comes due only `lead` minutes before it starts, so its start day is the only day worth asking about. Distinct leads keep two hundred meetings on the setting's own lead at one `occurrencesOn` query — its cost before the field existed.

- **The Remind row stays visible when reminders are off, and says so.** The inherited option reads `Follow settings · off`, not a duration: "10 minutes" under a preference that fires nothing is the panel promising what the app won't do. That's where the fact belongs — a `.caption` paragraph repeated it under the control, saying what one option already said, three lines of prose the loudest thing in a 335px column. Hiding the row hides an imported event's own alarm (its only view anywhere), and a field that vanishes with a preference can't be discovered.

- **The row _is_ hidden on an all-day event, value left alone.** `dueReminders` never fires one: a lead there is a control with no effect, worse than an absence. Whatever an import put on the draft stays — the sender's statement, travelling back out on the next export.

- **A silent event exports no `VALARM`; nor does an inheriting one.** Absence of an alarm is all iCalendar can say, and this app reads absence back as inherit — materialising the current setting turns a preference into data, returning as an override nobody set. `ownLead` is the exporter's question (the lead an event names _for itself_, else `null`), not `leadOf`: one asks what the event says, the other what the app will do.

- **Lead vocabulary in `events.ts`, firing in `remind.ts` — the split marks already use.** `events.ts` owns what a `CalEvent` field legally is (`REMIND_INHERIT`, `REMIND_SILENT`, `REMIND_LEAD_MAX`, `ownLead`, `readRemindLead`, beside `ICON_MAX` and `isIconName`); `remind.ts` owns what a lead does (`REMIND_LEADS`, `remindLabel`, `leadOf`, `dueReminders`). `leadOf` stays up there because its fallback is a **setting**: what a field legally is must be answerable without one. `readRemindLead` is the one validator with four readers — `backup.readEvent`, `store.hydrateEvents`, `ics.ts`'s `VALARM` reader, the editor's `Select` — `readRecurrence`'s shape; the `.ics` reader passing minutes through it instead of re-spelling whole-minutes and cap checks makes it a fourth reader, not a second opinion.

- **Snooze stays in the shell; the page is never told.** `Bridge.snooze` (`mac/main.swift`) re-posts the identical `UNMutableNotificationContent` under the same identifier with a ten-minute `UNTimeIntervalNotificationTrigger` — same banner again, nothing more. Routing it through the page breaks the rule two lines up: a snooze is the user asking for the banner back, not the app deciding a meeting is newly due, and via `remind.ts` the two are indistinguishable. A future reader "fixing" this by involving the page has misread it. The `osascript` fallback has neither the action nor a tag to snooze with, and correctly doesn't try.

### Store, feeds, backup

- **`Settings` schema-versioned.** `SCHEMA` in `src/lib/store.ts` bumps when a stored value changes _meaning_, not shape (→ `2` when `clock: "24h"` stopped meaning noon-at-top face). Stale schema resets settings to defaults, keeps events.

- **One validator, three readers.** `recur.ts` owns what a legal rule is: RFC range tables, `readRecurrence`, unknown → `Recurrence`. `backup.readRecurrence` (untrusted JSON), `store.hydrateEvents` (fields a blob predates), `ics.readRecurrence` (RRULE strings) — three _jobs_, shared rules; left to themselves they disagreed: backup clamped `interval` at 999, ics had no ceiling, the store range-checked nothing. Two keepers: **the exdate/rdate lists are read before the frequency**, an RDATE-only series being real (`repeats()` says so) and a bare `NEVER` for `repeat: "never"` losing every date a producer named on a `.json` round trip; and `hydrateEvents` keeps its identity fast path — asks _shape_, hands the rule over only when shape is wrong.

- **Store hydration lazy, at first `subscribe`**, not module scope. `load()` and `write()` swallow `localStorage` errors on purpose (private mode / quota must not brick the app) — but both `notify(…, "error")`: silent failure is indistinguishable from success, and that is how a day's events disappear. `load()` is sharper, starting the app **empty**, exactly what a first run looks like: the notice is the only thing telling them apart. `readFeeds` is the one silent catch, and says why — a corrupt payload is a cache miss the next pull replaces.

- **Every action derives from `fresh()`, never the module `snapshot`.** `fresh()` re-reads the blob when another tab wrote since we last looked; the in-memory snapshot loses that tab's events wholesale before its `storage` event lands.

- **Undo in-memory and session-scoped**, cleared on an inbound `storage` event _only when the base actually moved_: undoing onto a base another tab moved past resurrects what it deleted, but a background tab's **feed pull** writes the same key and used to cost the foreground tab all sixty steps — a loss the user can't attribute to anything they did. `baseSignature()` compares events + calendars minus their `feed` + settings. `undo`/`redo` carry today's `feeds` across, not recorded ones: a feed is a live mirror, never part of an undo step. `commit(next, false)` opts out of history — settings and feed pulls do.

- **A feed payload never shares the blob.** One `circal.feed.<id>` key each, budgeted: `FEED_BUDGET` (2M stored characters) split equally between subscriptions, re-divided every pull. Inside `circal.v1` a mirrored calendar is unbounded and competes with your own events for one ~5MB origin quota: one fat subscription made every later save fail. Quota is per origin — also why the cap is a shared total, not "1MB each" five times over. Over budget `trimFeed` keeps recurring events first (a rule is bytes describing years), then nearest today; the meta line says `1,228/4,000 cached`, a refused `setItem` drops the key and says `Not cached — no room`, both under twenty characters since that line is one `.label` wide and truncates. Legacy inline `feeds` migration runs in `hydrate()` — shared by `load()` and `fresh()`, either can see a blob first — rewriting the blob immediately, so it happens once. Deliberately **not** a `SCHEMA` bump: a bump resets settings, and where a payload is stored is not something a setting means.

- **`feedCache` is not a droppable optimisation.** `fresh()` runs on every action and re-reads every feed key; without the id → `{ raw, events }` map one 300-event subscription re-parses on every nudge of an arc. It also lets `sameFeeds` tell a change from a re-read, so `fresh()` won't hand React a new snapshot for nothing.

- **`seed()` only runs when no stored blob exists**, anchors on today's local midnight.

- **The backup nudge — why a data-safety setting defaults on.** `localStorage` is the only copy, "Clear site data" erases it without asking, and the macOS app and every Chromium browser answer with a live mirror; Safari and Firefox have no File System Access API, no way to hold a file handle: noticing no backup in a long time is the only answer they get. Hence `settings.backupNudge` **on** where `remind` is off: a reminder is a convenience somebody opts into, a warning about losing everything is not, and a prompt defaulting to off is one nobody meets. Interval from `BACKUP_INTERVALS` (7/14/30/60/90 days, **30** default, strays pinned by `sane()` like every enumerated setting). `backupDue(lastBackup, intervalDays, now)` in `backup.ts` is pure, taking `now` as an argument: same predicate in every zone, pinned in a test with no clock to stub.

- **Four decisions about that clock, each a way of not lying to the user.** Only the **`.json`** export advances it, and only when a file landed — `download` reports that, the macOS save panel being dismissable and a cancel that quieted the nudge a warning switched off by a gesture that saved nothing. An `.ics` never advances it: events handed to another app, not a restore path. A **live copy of either kind suppresses the line entirely** (`App.showNudge` reads `mirrorStatus.state !== "live"` **and** `cloudStatus.state !== "live"`): nagging somebody to export a backup they take continuously is the app not knowing what it does, and the cloud copy is the same document one transport over — the argument can't apply to one only. The Nudge caption in the settings panel says both: a switch whose behaviour depends on another panel two sections down looks broken. **Dismiss restarts the interval and does not switch the feature off** — "not now" is not "never", and `settings` is where never lives. A never-backed-up browser anchors at **first run**, not the epoch: from zero the app is overdue the instant it opens, a chore handed to somebody with no events, and no honest earlier anchor exists — an event's `start` is when it happens, not when it was written, and seed events aren't the user's work. `backupSnapshot()` stamps that anchor inside the getter `useSyncExternalStore` calls during render, so **without `emit()`**: notifying there would loop.

- **A line over the stage, on every view — the feature's whole risk.** Nothing in circal ever interrupted the user, so the change of character had to be as small as possible while still being seen: `BackupNudge` is one `.caption`, an export pill and a dismiss pill at the top edge, clear of the readout, reserving no layout when away, `pointer-events-none` except on the pills so it can't eat a click meant for an arc under it. A modal was the obvious build, refused for the same reason a `Suspense` spinner is. Off while `shaded` or in ambient (a notice over something that owns the screen is the interruption this design avoids), and above every view, not the dial alone: a warning met in one of four views can be missed indefinitely.

- **A VEVENT with no UID gets a _derived_ one, never a generated one.** `derivedUid()` in `ics.ts` = FNV-1a over DTSTART/DTEND/SUMMARY/LOCATION/RECURRENCE-ID as `<base36>@circal.local`. `crypto.randomUUID()` meant a new id per parse; `feeds.ts` keys events off the uid, so every pull remounted every arc — hover, selection, the arc under the pointer dropped. RFC 5545 requires UID: this fires only on a feed nobody can fix.

- **`zonedToUtc` brackets the wall time with two candidate offsets** — one a day before, one a day after — taking the pre-transition one when neither or both read back. Spring-forward gaps resolve to the instant _after_, fall-back ambiguity to the _first_ of the two, every zone. The earlier two-pass version converged from the naive UTC reading, so which side of a gap it landed on followed the offset's sign: Berlin right, Los Angeles an hour early.

### Recurrence

- **`src/lib/recur.ts` = somebody else's spec, not this app's idea.** RFC 5545 §3.3.10 expand/limit table: BY\* parts expand period into candidate days, given clock, BYSETPOS narrows, then bound. Verified against every worked example in §3.8.5.3. Never "simplify" a branch without re-running that suite — most exist for one example.
- **Seed = instance only when rule generates it.** RFC calls DTSTART first instance yet demands sync with rule; readings differ only for rule contradicting own seed. Editor can _write_ that (deselect weekday event sits on); event stuck on that day = bug user cannot fix. Synchronised rule generates its seed anyway.
- **Rule naming date some months lack simply does not fire there** — 31st, 29 February, fifth Friday (§3.3.10 invalid-instance rule). Only answer inventing no date sender never wrote.
- **COUNT walked into `until` on way in; model stores one bound.** `countedUntil` in `recur.ts`, called from `ics.ts`. Counting by _rule_, before EXDATE — RFC subtracts exceptions from generated set, so excluded day still spends one count. Count past `WALK_CAP` = unbounded, deliberately: over-running shows occurrences that should have stopped, guessing early deletes them; only second loses data.
- **`exdates`/`rdates` = local keys, two forms** — `YYYY-MM-DD` whole day, `YYYY-MM-DDTHH:mm:ss` one instant — exactly EXDATE's two RFC value types. Local: every other day-identity here is (see `dayKey`).
- **Every entry point capped.** `MAX_INSTANTS` (512) per call, `WALK_CAP` (2000) periods per COUNT walk. `SECONDLY` rule names 86,400 instants a day; feed not obliged to be reasonable. Truncation is visible, frozen tab is not.
- **EXDATE and RDATE = properties collected as lists.** Both legitimately appear on several lines of one VEVENT; flat prop map keeps only last — series regains every occurrence it was told to skip. Hence `Block { props, exdates, rdates }` in `ics.ts`.
- **RECURRENCE-ID = override _event_, not patch on series.** `seriesId` + `seriesKey` on `CalEvent`; `occurrencesOn` builds index once per query, skips generated occurrences an override claims. Separate event because that is what it is — own time, title, place, colour, maybe another day than one it replaces. `feeds.ts` MUST give it id including recurrence-id: it shares parent's UID.
- **`RANGE=THISANDFUTURE` resolved in `fromIcs`, not in a consumer.** `linkThisAndFuture` runs once every VEVENT is read, turning flagged override into tail of split series — shape `splitRule` and `store.splitSeries` already model, since that is what range means. There because `feeds.ts` and `backup.ts` each link overrides themselves; one wrong = series drawing twice. Five things to get right, three non-obvious: chained splits **fold left** (second cut measured against first cut's tail, which by then generates the instant); promoted tail takes `uid#recurrence-id`, drops `recurrenceId`, else collides with parent in both key maps; lacking own RRULE it inherits parent's rule with `splitRule`'s **partitioned** lists (merged with its own), else skipped days return; **ordinary** override past cut re-pointed at tail, as `store.splitSeries` does (on head it suppresses nothing, day draws both); cut at or before series' first instant makes tail **absorb** head, keeping its uid — `effectiveScope`'s "folds `future` into `all`" one layer down.
- **`EditScope` asked at press, never standing controls.** Three answers, `"one" | "future" | "all"`; scope belongs to the commit, not the event; one-off has one meaning, never asked. `EventEditor` holds `pending: "save" | "delete"`, swaps footer for question — replacing verbs, not stacking above them: two rows with one inert = footer that lies. Escape backs out, second press closes.
- **"This and all future" = two series; `splitRule` (`recur.ts`) is the whole decision.** Head takes `until = at - 1` (inclusive, bounds a _start_), or existing bound when earlier — split cannot extend series. **The exdate/rdate lists MUST be partitioned, not copied**: `until` bounds generated set only, so RDATE past it still fires, one left on head fires from both halves, future EXDATE not carried over resurrects a skipped day. `store.splitSeries` = one commit — two = two ⌘Z presses per edit, with a futureless series between them — and it **re-points overrides past the cut at the new series**: `seriesKey` still names the instant, so an override left on head suppresses nothing and day draws both it and tail's arc.
- **Splitting at series' first occurrence = "the whole series".** Head would generate nothing, so `effectiveScope` in `App.tsx` folds `future` into `all` — one live event, not two with one dead.
- **`store.remove` takes overrides with it** (`e.id !== id && e.seriesId !== id`). Orphaned override = ordinary event on the day it replaced, nothing explaining it, no surface finding it.
- **`Occurrence.key` = `${event.id}@${instantKey(start)}`.** Event can appear twice on a day now (hourly rule, BYHOUR list); day alone no longer identifies one.
- **Full recurrence shape filled at `store.parse`, not guarded at every read.** Older blob has no `interval`; `undefined` hits maths as `NaN` — series firing on no day. `hydrateEvents` covers `events` _and_ every `feeds` array, returns same object when nothing missing, since `parse` reruns on every cross-tab write. No `SCHEMA` bump: nothing stored changed meaning.
- **Day's query looks back exactly event's duration — whole multi-day fix.** `occurrencesOn` scanned one flat day back, so anything over ~48h existed two days then vanished (every feed holiday is that shape; `lifeDensity` already coloured days dial denied). Overlap test = `start + duration > dayStart`: exact in _milliseconds_, no DST reasoning (old `addDays(dayStart, -1)` guessed by day arithmetic). `lookbackCap` bounds it because lookback _is_ the recurrence window: `Infinity` for `never` (one-off costs one instant however wide), a year for ordinary frequencies, a **day** for `secondly`/`minutely`/`hourly` — `startsBetween` keeps _earliest_ instants, so a wider minutely window answers with last week's and the day vanishes instead of gaining copies.
- **`dayIndex`/`dayCount` on `Occurrence`; `spanLabel` = one voice.** `continuesBefore`/`continuesAfter` say only _that_ a span runs past the day, so a five-day holiday printed one row five times. `Day 3/5` replaces the time column in `CenterPanel` — on the third morning neither a clock time from three days ago nor "Now" answers. `dayCount` measured from `end - 1`: `end` is exclusive, one-day event must read `1 of 1`.
- **Headline row does _not_ get span column, measured.** `DAY 2/4` costs `Sleeper train` most of its letters at interior width; its wait already reads `ends in 45h 34m`, the multi-day fact, and the non-lead row prints position. Keep `!lead`.
- **`startsBetweenIn` = `startsBetween` walked over another zone's wall clock; that is all of zone support.** Feed's `TZID` says the rule was written against _that_ clock's transitions, not the reader's, so seed, window and `until` move into wall time via `wallClockIn`, the walk runs unchanged, results return through `instantOfWall`. `zone === ""` — every event user wrote — delegates through, so floating path costs one string check. Three consequences: `exdates`/`rdates` resolve _inside_ the delegated call, so read as that zone's wall keys, which `EXDATE;TZID=…` means; wall window widened by `ZONE_SLACK` (3h, DST's hour and double summer time's two) with real `[from, to)` re-applied, else an instant a transition moved across the bound is lost; wall time in the _viewer's_ own DST gap shifts an hour, since `wallClockIn` goes through the local `Date` constructor, normalising a nonexistent local time forward. That last is the file's floor — a local event at 02:30 that morning does the same — and closing it means walking the rule in UTC fields, i.e. every getter in `recur.ts`.

### Event editor

- **Card = two columns above `md`, one below, 672px wide rather than 330.** Seam file already had: left = event — Date, Time, zone caption, Where, URL, Guests, Type, Shows as, Remind, Repeat — right = filing and face — Calendar, Color, Mark. `URL` under `Where`: one question, room or link. Notes span both: read not scanned, and they balance the halves. Width paid twice: thirteen rows in one 330px column scroll on every laptop, hiding fields behind a fold on the surface whose point is seeing the draft while editing; footer's four verbs measured ~397px against the 306px a 330px card leaves, so "Share link" wrapped to two lines with Save's chips clipped off the right edge. Each column = 335, above the 320px floor every inline `FieldRow` row wraps at.
- **Footer's `Kbd` chips = `hidden md:flex` (`Chord`), Share link icon-only, below that width.** Something had to go at 306px; chips are honest: ⌘↵ and ⌘⌫ still work, four verbs keep their words, and a card that narrow is usually a phone, where a chip advertises a key the reader lacks. Hidden not dropped: one footer, wider on desktop, not two. `ScopeChoices` caps its three answers at `max-w-[300px]` from the same arrival: unstretched they were 645px, reading as a settings page not a question — no-op in `ScopeDialog`, card 300px anyway.
- **A `<fieldset>` cannot be scroll parent; scroll container = plain `div` _around_ it.** Fieldset lays children in an anonymous box sized to content, ignoring the height flexbox gave it, so `flex-1 overflow-y-auto` scrolls nothing. Measured at 390×844: grid took its full 592px, notes band ran a hundred pixels past the card, footer painted over it. Height now on a real box; fieldset sits inside as a block, only as tall as its contents, keeping the `disabled` cascade that is its whole reason for existing.
- **Editor's Date row = two dates; second names _last day covered_, inclusive.** `lastDay = startOfDay(new Date(draft.end - 1))`. Edits at the far end are then a day-shift of `end` (`daysBetween(lastDay, picked)`), no all-day branch: timed span keeps its clock time, all-day keeps exclusive midnight. `handleEndTime` anchors on `lastDay` too — anchoring on start's day collapsed a multi-day span when one time was retyped. Both fields always show: hiding the only control reaching a state is worse than printing the same day twice.
- **Editor's Date row MUST call `showPicker()` itself.** Row = transparent `input[type=date]` over a label; Chrome and Safari open the calendar only from the indicator the input hides, so clicking opens nothing. `openDatePicker()` in `EventEditor.tsx` wraps the call: it throws outside a user gesture and is absent in some browsers rendering the field.
- **All-day toggle remembers times it had, never span.** `timedSpan` in `EventEditor.tsx` = ref holding `{ startMin, endMin }`, captured entering all-day, reapplied to current first and last day on exit; without it, off → on → off reset every event to 9–10am, discarding times user set. Two clock times not a duration: span in _days_ belongs to the Date row now, a stored duration would overrule it — and the toggle carries the span across (`end: addDays(lastDay, 1)`), since a switch must not delete four days of a five-day trip.
- **`<input type="time">` banned here** — renders in _browser's_ UI locale, not app's. Use `TimeField` in `EventEditor.tsx`, backed by `parseClock` (accepts `10:45 AM`, `10:45am`, `1045`, `9p`, `13:00`).
- **Editor refuses to flatten a rule it cannot spell.** `isExpressible` in `EventEditor.tsx` gates controls; `describeRule` prints a sentence. Snapping BYSETPOS or BYWEEKNO to the nearest checkbox is how an import quietly becomes a different meeting.
- **Read-only events = `disabled` fieldset**, not a prop threaded through every control — it cascades to swatch buttons and `Select`s two components deep, which nothing else reaches. Title input sits outside, carries own `disabled`. A block **inside** the scroll container, never the container — see fieldset bullet above.
- **Editor's live draft rides on `EditorTarget.live`, not own state.** Five fields (`DraftMark`), reported from the one `patch` in `EventEditor`, folded in by `App.trackDraft`, which **returns same target when none moved** — React bails on an identical state value, so typing a title costs no render, no canvas repaint, no SVG diff. On the target, not beside it: only lifetime that could be right, since a preview outliving its modal = mark nothing can clear, and six `setEditor(null)` sites would each have to remember. Readers fall back to `target.draft`, the seed, correct until first change.
- **`patch` in `EventEditor` merges off render's own `draft`, not the updater form** — shell must be told the value the field is about to show, and a prop cannot be called inside an updater (those stay pure). Safe: no handler there patches twice per event; one needing to MUST merge both partials into a single call.
- **`colorOf` takes `Pick<CalEvent, "color" | "calendarId">`.** Draft is no event yet, has no id; widening the parameter to what the function reads beats minting a fake one, and keeps colour precedence in one place.
- **Drag on repeating arc asks the same `EditScope` question; nothing written until answered.** `App.adjustOccurrence` holds `PendingAdjust` (occurrence + dial's two minute deltas) and **re-arms `preview`**, since the dial drops its own on pointer-up: without it the arc springs back and jumps again on the answer, reading as a failed gesture. Cancel = dropping the preview; nothing to undo. `"all"` puts deltas on the event's own instants (seed moves, occurrences follow); `"one"`/`"future"` measure from `occ.start`/`occ.end`, real instants not clipped ones. One-off written on release, no question.
- **Notice after a drag is measured against what was written** — series' new seed for `"all"`, occurrence's for the other two. A multi-day event's clipped occurrence notifies either way, deliberately: its visible ends are not the event's instants, so the dial could not step the day, and an arc leaving the face silently reads as deletion.
- **`ScopePrompt.tsx` owns the question; `ScopeChoices` = shared body.** Editor renders it in its own footer (edit already on screen; modal over modal = unreadable stack); dial gets `ScopeDialog`, which must print event and new span, since the gesture is over and the card covers the readout. Two copies of a three-way question drift into two vocabularies. `ScopePrompt.tsx` is in `eslint.config.js`'s `no-autofocus` exemption for the same WAI-ARIA reason as palette and editor.
- **`CalEvent.color` = override, not the colour.** Empty string = "follow the calendar", the default every event should stay on, so recolouring a calendar still moves them. Only `colorOf` knows precedence.

### Previews and drafts

- **One notion of "the event about to exist", both faces: range under pointer, else draft in open editor.** White and translucent while drawn (no colour yet), own colour once the editor has one. Shape identical across release _and_ save — dial's ghost path byte-identical to the arc replacing it — so neither handover looks like the drawing was thrown away.
- **Each face draws it in own units; clipping is the face's question.** `YearView` takes `{ from, to, color }` in dates, lighting those days as days that _carry_ it — `markRadius(count + 1)` in its ink, no white overlay. `Dial` takes instants, since a draft can sit on another day once its date row is edited: `drafted` clips to the day with `minutesOfDay` at each end, not elapsed milliseconds (a day is not always 1440 minutes long), returns `null` for a draft not reaching the day, 0…1440 when its middle covers it. An **all-day draft gets no arc at all**, same reason a saved all-day event gets none.
- **No preview for an event that already exists.** `App.pending` is `null` unless `editor.id === null`. Existing event has its arc and marks; a second set = same event twice, and once the editor's time rows move it the two disagree on screen. Previewing an _edit_ means replacing the arc, not adding one — what `onPreview`/`DragPreview` already does for drags.

### Calendars and marks

- **Calendar may be made, renamed, recoloured, deleted; deleting keeps its events.** `store.removeCalendar` _moves_ user's own events to the first calendar still standing, returns `{ into, moved }` so the toast says where — a calendar is a label, and deleting a label is no way to ask for a year of appointments. Two invariants keep that possible: last calendar that is _not_ a feed cannot go (return `null`; card disables its verb, says why), and a feed's payload lives in `feeds`, so removing a subscription is a wholesale drop anyway. `App.calendarRemoval` mirrors the rule so the verb disables rather than fails — change one, change both.
- **Mark = one field, two vocabularies, told apart by alphabet — only one still typable.** `Calendar.icon` and `CalEvent.icon` each a Phosphor name (`[a-z0-9-]+`) or literal emoji; `isIconName` is the whole discriminator — no prefix, so the stored value reads as itself in a backup and devtools. `""` = plain colour dot on a calendar, "no mark" on an event, **and so is a name this build does not carry**: `CalendarMark` falls through rather than rendering nothing, and neither `readCalendar`/`readEvent` nor hydrators drop an unknown name, since a backup through an older build MUST NOT return with the mark missing. `firstGrapheme` keeps a flag, skin tone or ZWJ family one character — `[...s][0]` gets all three wrong. **The emoji input is gone from the picker, the format is not.** Emoji belongs in the title: searchable, travels through `.ics`; a 72px box saying the same thing twice was not worth a third of the row. Everything that _renders_ one stays, so a value from a backup or older build keeps drawing — why `isIconName` and `firstGrapheme` stay exported and tested.
- **Cap per vocabulary; name never sliced — `readMark` is the one validator.** `ICON_MAX` (16) guarded both alphabets with one number: silent data loss. One grapheme against a word list whose longest entry is `currency-circle-dollar` at 22, so ten of 247 names in `marks.ts` were over it, and the cap ran in `readEvent`/`readCalendar` **after** `isIconName` approved the value. A validated name was stored as sixteen characters matching no path, drawing as the plain colour dot, nothing raised. `person-simple-run` is one of five `SEED_MARKS`, so not just hand-picked marks: every new install corrupted its own seed data the first time a backup round-tripped, and `suitcase-rolling` survived only by being exactly 16. So `ICON_NAME_MAX` (48) is its own number, roomy not fitted — a cap of 22 must move whenever an icon is added, the maintenance nobody did to the old one. The vocabularies fail differently: a **name** is kept whole or dropped, since slicing makes an invalid value from a valid one while dropping lands on the same dot honestly (`""` is already what an unknown name renders as); an **emoji** is still truncated, since there one grapheme is exactly what the field holds and `firstGrapheme` keeps a flag or ZWJ family intact. `readMark` is `readRecurrence`'s shape — one place deciding what the field legally is, with `backup.readEvent` and `backup.readCalendar` as readers. A name under the cap returns untouched even with no path: a shrinking set must not blank a mark.
- **`markOf` is deliberately not `colorOf`; its third argument is why.** Colour _must_ inherit: every event needs one, so `CalEvent.color` overrides a required field. A mark is optional at both levels, and a face where forty arcs share three glyphs says nothing the colour did not — so `markOf(event, calendars, inherit = false)` returns the event's own and stops unless asked. Argument = `settings.inheritMarks`, **off**; on, a calendar's mark becomes its events' default, the useful reading for one-calendar-per-kind-of-thing. Parameter default matches setting default, so a forgetful caller gets the conservative answer.
- **Shape and colour read apart.** `CalendarMark` takes whatever colour the caller resolved — `calendar.color` for a calendar, `colorOf(event, calendars)` for an event — so an event can borrow its calendar's glyph and wear its own colour, neither implying the other. Two deliberate abstentions: the event editor's _header_ dot is the event's colour swatch, no mark; **`CenterPanel` has none at all** — its dot is `4.5–5.5 × u`, about five pixels, so a glyph is a smudge, while a legible one would widen every row's leading slot in a panel whose corner has 29 units of clearance to `HAND_INNER`.
- **247 icons, and the number is measured.** All 1,512 Phosphor bold paths = 621 KB raw / **206 KB gzipped**, more than the rest of the app ⇒ "just ship them all" is a picker costing more than the product. These 247 = 120,676 raw / **44,496 gzipped**, the fifth of the library a calendar wants. Long tail was the emoji field beside the grid, now the title: free and in colour either way. Still the heaviest module in the build — a fifth of everything a cold load used to fetch — and **no longer a byte of the critical path**: `ui/marks.ts` has no static importer, fetched on demand, taking the three chunks `client:only` blocks first paint on from 236,732 to 193,796 gzipped — **−42,936, −18.1%**, against −1.7% for lifting both modals off the same path. Old "a quarter of the bundle" line went with the mis-attribution behind it (see `icons.*` chunk below). Set may grow an icon at that price per icon; it may not grow back onto the first frame.
- **A mark still draws on the first painted frame, and a dot popping into an icon is still the failure being avoided** — now why the eager core exists, not why not to split. Two mechanisms, both in `ui/icons.tsx`. **Path cache in `localStorage` under `circal.marks`**, read _synchronously at module load_, so an already-chosen mark draws immediately, no chunk fetched: a few path strings, a kilobyte or two against the table's 44,496. A miss on a real name kicks the lazy import off, repainting through a `useSyncExternalStore` signal; `""` and emoji need no path, never fetch. And **`SEED_MARKS`, five paths inlined eagerly** — `house`, `briefcase`, `users` from `DEFAULT_CALENDARS`, `person-simple-run` and `suitcase-rolling` from the sample events — loaded into the cache _before_ the `localStorage` layer, since a new visitor's cache is empty and the app's first impression was those five dots turning into glyphs. Costs **1,072 gzipped bytes** (74,376 → 75,448 on the shared chunk), deliberately the seed's own five: mirrors `seed()` in `store.ts`, and a creeping "popular icons" set is how 44 KB returns to the first frame one defensible addition at a time.
- **One case is left late on purpose: a backup restored into a browser with no cache.** Names are real, nothing drew them here before, so the plain coloured dot draws — already what an unknown mark name draws — filling in when the table lands. Once per browser per restore, stated in the module's comment rather than hidden; the alternative was 44 KB on every cold start of every user for that one frame. The flicker was found by clearing storage and throttling the chunk to three seconds, the only way any of this is visible: at full speed fault and fix look identical.
- **The chunk the build calls `icons.*` is not the mark renderer, and the name is wrong on purpose.** It measures 75,448 gzipped, inviting the reading that the split did nothing; inside is the `motion` library plus shared UI, and Rollup named a shared vendor chunk after `icons.tsx` because that module sits in its import graph. The renderer is a few hundred bytes. The name has already cost two rounds: `AUDIT.md` quoted the chunk's **whole** 118,143 gzipped bytes as the weight of `marks.ts` + `icons.tsx`, so the table looked three times its real size, and the same chunk still measures 75,448 with every path gone — 118,143 − 74,376 ≈ 43,767, the table's actual share, agreeing with the 44,496 chunk it became. Fixing the name means pinning `manualChunks` in the Astro config — fighting the bundler for cosmetics, real chunking to re-argue after — so it was not done; the rule is the mitigation: read a bundle report by what a chunk contains, never by its name.
- **The paths are vendored, and that is not an optimisation.** `@phosphor-icons/react` ships every icon as a component carrying all six weights inline — four times the weight of the one this app draws. Bold only, as data, is the whole library's choice at none of the price. Measure before adding an icon library here; the number is the argument, not taste. To add a mark, copy the `bold` entry out of `@phosphor-icons/react/dist/defs/<Name>.es.js`; viewBox is 256 units, paths unmodified MIT.
- **One `MarkPicker`, own file, two sizes; `noneLabel` is the only thing the two callers differ on.** Calendar card and event editor ask the same question and `""` is the same empty string in both — "a plain colour dot" on one, "follow the calendar" on the other. It is `src/components/react/MarkPicker.tsx` not `ui/icons.tsx` because a picker is chrome: speaks lucide, reaches for `primitives.tsx` and `useFocusTrap`, which that file may not use. Search matches bare letters (hyphens and spaces stripped both sides), so `first aid`, `firstaid` and `aid` all find `first-aid`; `fuzzyScore` is deliberately unused, its subsequence match being tuned for command titles and ranking `bird` over `barbell` for `b`.
- **Picker asks for the whole table on open, rendering empty rather than "no match" while it arrives.** `useAllMarks` is the one caller wanting all 247, so the lazy import follows from opening it rather than the grid arranging it; a search on an unloaded table would print "no match" for a mark that exists, a lie indistinguishable from a missing icon. Empty is silent, one round trip. The count comes from the same hook, saying 0 then 247 rather than a number the grid is not showing.
- **Compact grid is a porthole, so the expand button is not a luxury.** Four rows of eight in a 330px card = thirty-one rows' worth of set seen 24px at a time: enough for a shape already in mind, useless for _choosing_ one. `MarkBrowser` = same controls — none, search, count — over `auto-fill minmax(46px, 1fr)` cells, all 247 on one screen at 1.8× size in a 900px window, measured. Height **fixed** (`min(88vh, 640px)`): a card hugging its rows would jump a foot up the screen on the first search keystroke. One query serves both grids, so narrowing large then closing leaves the row narrowed the same; picking closes — the grid covers the card whose field you were filling.
- **`Color` and `Mark` share one 26px rhythm, arithmetic not taste.** The rows sit directly above each other in the card's right column, so any disagreement reads as a ragged column. `Swatch` = 26px cell, ring on the **dot** at 2px offset — `18 + 2 × (2 + 2)` is exactly 26, where the ring on the _wrapper_ drew 4px outside the cell, putting a selected swatch's left edge clear of every other row's content. That 26 is also `MarkFields`' none-button and its `h-[26px]` fields, so both dividers land on one x. Both blocks end on the column's right edge: mark grid cells are `aspect-square w-full` (eight fixed 26s plus seven gaps = 236 against 220, so each cell spilled 2px out of its 24px track and the last column past the card), swatch grid is `flex-1` with centred cells (left tight it stopped 39px short of the grid under it). Colour tracks then carry ~1.5px more air than the 8px row gap — invisible, where a 39px step is not.
- **`FieldRow`'s 38px is a _step_, not a minimum, and `ColorPicker` is sized against it.** Two columns of different rows align only where a tall row is a whole multiple of the short one, and a rule one pixel out reads as a rendering fault where an obviously different height reads as a different row — `Color` came out 77 against the left column's 76, and that pixel is what you see. `min-h-[38px]` is border-box with `border-b` inside, so two steps = **75px of content**: swatch block is 60, hence `py-[7.5px]` = `(2 × 38 − 1 − block) / 2`, moving if cell or gap does. Half-pixel padding is a whole device pixel at DPR 2, the honest way to an odd content height.
- **`FieldRow fill` is how a column stops ending in a hole.** The two columns stretch to the taller, so the shorter's leftover sat under its last row, reading as that row's empty space — 116.5px under `Mark`, measured. The mark grid is the one thing there with a use for the room: `shrink grow basis-[108px]`, four rows wherever nothing imposes a height (one column, calendar card, fullscreen browser), eight in a stretched column. `fill` makes the row a `flex-1` item and stretches its value cell; the parent column carries `md:flex md:flex-col`, so on one column the row is `auto` again and no `md:` prefix leaks into `primitives.tsx`. Settings never uses it.
- **Browser is a portal to `document.body`, and Escape is the _caller's_ prop.** Portal because the card it opens from is `overflow-hidden` and animates a transform, either clipping a `fixed` descendant, and because it must sit above that card (`z-[65]`). `browsing`/`onBrowse` live in `EventEditor` and `CalendarEditor` because every modal claims Escape on a `window` **capture** listener and capture listeners on one target fire in the order added — the editor's is first, so a listener inside the picker could only close the card too. Same argument as the shell holding the life grid's drawn run. While the grid is up the card's ⌘↵ and ⌘⌫ are off, which is `busy` one layer in. Focus returns to the expand button from an effect declared **above** `useFocusTrap`, so its cleanup lands first: the trap remembers the last focus outside any `[role=dialog]`, and this dialog opened from inside one, so its answer is a control on the page behind.
- **`MarkTip` names the mark under the pointer, at the mark, in both grids.** A glyph grid is read with the pointer, so a name in a strip elsewhere is a saccade away from its subject — the footer version was built first and lost to that. It costs the neighbours it covers, the trade every tooltip makes and why it is 26px, `pointer-events-none` (a click still lands on the cell under it) and gone with the pointer. The `title` attribute went too: the platform's tooltip answered the same question again, later, in another voice. Three load-bearing things. **Portalled and `fixed`**, since the grid scrolls and the card is `overflow-hidden` for its corners — either crops a bubble drawn inside. Width is **arithmetic**, not measured: `.label` is 11px mono at 0.18em tracking, so ~8.6px a glyph clamps it against the window edge with no layout read and no second render (`arcLabel`'s trade; the estimate was exact on the set's longest name). And a **scroll moves it rather than dropping it** — focus on a cell above the fold scrolls the grid, so dropping meant the first Tab named a mark and unnamed it in one beat. `usePeek` is one delegated listener reading `data-mark`, and the 4px between cells is deliberately not an answer, the loupe's rule about blanks between years.
- **Mark grid has no fade — a rule about what a fade is for.** A fade says "the list continues" and pays by dimming its own last row: good over prose or an agenda, where a half-legible row is still placed by those above; bad over a glyph grid, where the dimmed row is what you are comparing. Search is the real answer to 247. `.fade-b` survives on `CenterPanel`, gated on row count, over text.
- **Calendar card is a `CalendarEditor`, opened from two places, owned by neither.** Sidebar's pencil and ⌘P's `New calendar…` / `Edit …` rows both go through `actions.newCalendar` / `actions.editCalendar`; the shell holds `{ id }` and resolves the `Calendar` from the store every render, so a rename in another tab updates the card and a deletion closes it. Palette rows are not decoration: the pencil is a pointer affordance and the sidebar is off screen entirely on a phone.
- **A palette row's second verb is `Row.alt`, on ⌘↵ and on the foot of the panel.** A row names one target, so a per-event action hangs off the event's own row — a `Duplicate …` row would double the result list or guess which match was meant. ⌘↵ falls through to _nothing_ when the highlighted row has no `alt`: running the primary instead would make one modifier mean "duplicate" on one row and "open" on the next. The foot is fixed height and always present, same reason as the mini-month's dot row: a strip that appears would move the list under the pointer.

### Sun, moon, zones

- **Your lightcycle band replaces the elapsed ring; it does not join it.** Both on `DIAL.TRACK` at `DIAL.TRACK_WIDTH`; `elapsedSegments` returns `[]` whenever band has half left to draw (`place && (daylight || moonlight)`, computed once as `band`). First attempt, second band on own radius _next to_ track, read as one line accidentally doubled. Deliberately no `DIAL.SUN`.
- **Second zone's band = a different place, so it does get its own rim.** `DIAL.ZONE_BAND` (424): 21 units outside track, 13 inside its zone numerals; `SunBand` takes `radius` for this. Halves `zoneDaylight` / `zoneMoonlight`, independent of yours — ring compares two places, half-drawn is no comparison. Coordinates from `placeForZone(secondZone)`, resolved in `App.tsx`; `null` (`UTC`, aliases like `Asia/Calcutta`) = no band, no switches.
- **Lightcycle bands = the one sanctioned break in "chrome is greyscale".** Data about the day, not chrome: warm-but-desaturated day, dim violet night, neither may compete with an event arc. Same opaque-segment technique as ring they replace, same alpha-compounding reason.
- **`light(m)` in `SunBand` MUST stay continuous through zero.** Signed light (positive sun, negative night); civil-twilight shoulders hit exactly `0` at horizon, so warm and violet meet without a step. Any discontinuity = visible rim edge; shoulders once began at `0.04`, so band began with a hard line. 288 segments (five minutes each, eight-unit chord) stops a stepped ramp.
- **Two halves = draw-time filter, not an argument to `light`.** Curve computed for whole day either way; segment loop drops half switched off, so half that stays keeps shape it had beside the other. Yours defaults on — band _is_ track; both off restores elapsed ring rather than emptying rim. Second zone's defaults off: its caption annotates a ring already there, and band is another ring. `night` = old name for `moonlight`; `migrateSettings()` in `store.ts` carries stored one across, `readSettings()` in `backup.ts` same for a backup.
- **`DIAL.ZONE` (446) fixes `PAD` (30).** Crop leaves 470 units of radius; 15-unit numeral centred on `ZONE` reaches 453; caption beside topmost runs 131 units further right — eight short of crop at worst anchor angle. Further out crops: move `PAD` before `ZONE`, keep `ZONE_BAND` _inside_ `ZONE` — caption runs horizontally outwards from numeral, would cross band.
- **Zone caption hangs off the topmost of four marks**, to its right, never beneath: beneath, it collided with hour numeral below and ran off viewBox at three o'clock. Four marks 90° apart ⇒ one always within 45° of top, where horizontal room is.
- **Zone ring measured against the viewer, never against UTC.** `delta = zoneOffset(now, zone) + now.getTimezoneOffset()` — caption reads `Tokyo +7`: you are this dial's origin, "GMT+9" makes reader subtract. Also only form staying right in weeks when one of two zones has changed for DST and other has not.
- **`sun.ts` returns minutes since local midnight and does not clip.** A place far from viewer legitimately gives negative sunrise or sunset past 1440; `Face.tsx` samples inside `[0, 1440]`, rest falls off face.
- **Place chosen by city, never typed.** `settings.place` carries IANA zone it was picked by, and `placeForZone` alone turns a zone into coordinates, so picker always shows what band draws. `store.parse()` drops a stored place with no `zone`: a band settings panel calls off is worse than no band. Coordinates from `zone.tab`, naming zone's principal city — minutes of sunrise error at worst, finer than band draws.
- **The moon lives in the sidebar, the one thing here that draws something the calendar does not contain.** Not on face: every radius costs `PAD` and legibility, and unlike lightcycle band moon is no fact about the _day_. It reads the _selected_ day, which earns it — arrowing through a week walks moon through its week. `moon: false` by default: chrome does not appear unasked.
- **One drawing, in this app's own voice.** A second register went — `Aperture`, disc occulted behind a watchmaker's window by bites of exactly its own radius, night blue with stars: mechanism was better picture, and this was circal's only chrome neither greyscale nor flat, a fight eyecandy does not win. `MOON_STYLES` / `MoonStyle` went with it; a stored `moonPhase` string becomes `moon` in `migrateSettings`, a backup's in `readSettings`, since either register was a moon somebody asked for.
- **`light(m)`'s rule again, for the moon: the terminator is an ellipse of `rx = r|1 − 2k|` over the lit half**, filled black below half, moon above. `k = 0.5` collapses it to nothing — exactly a quarter moon's straight edge; one function, all eight phases, no branch per phase. Only the **lit** part draws: no circumference, no dark limb, so a crescent is a crescent, not a disc with a crescent on it, and a new moon is nothing. Shadow stays a painted `#000000` fill, not a hole: it occludes by covering.
- **`CalEvent.tzid` is the zone a _rule_ is read against, never where an instant is.** Instants stay epoch ms, `end - start` elapsed ms; zone only decides which wall clock recurrence walk sees (`startsBetweenIn`). `""` = floating, every event user writes — an event dragged onto this dial means hours it was dragged onto. A non-empty IANA name now has **two** writers, and which put it there is load-bearing: `ics.ts`'s DTSTART reader, zone out of a file; `travel.keptEvents`, where user answered "keep them as they are" and app stamped zone they were written in. `isZone` in `time.ts` is the one validity probe (`Intl` throwing is platform's only signal), shared by both writers and by `backup.readEvent`, which drops what it refuses back to floating rather than storing an unresolvable zone.
- **The `.ics` export carries the zone and deliberately carries no `VTIMEZONE`.** DTSTART/DTEND/RECURRENCE-ID go out `;TZID=<zone>:<wall stamp>`; EXDATE/RDATE reuse the key's digits (the key already _is_ that wall clock, nothing converts); UNTIL stays UTC — §3.3.10 demands that once DTSTART carries a zone, making the stamp load-bearing, not incidental. No `VTIMEZONE`: mainstream consumers resolve IANA names against their own tz database; a synthesised one would duplicate it or lie about DST. User-facing half: one editor `.caption`, `Times in <city>`, now on **every** zoned event, not only subscriptions' — a stamped event is one the user deliberately left on its written clock, and this row keeps that answer legible. Print-only, no picker: a zone reaches an event from a feed's TZID or that answer, never a field.

### Travel: the device that moved

- **Nothing here is a corruption, and the prose must not pretend otherwise.** A user's event is floating, its instant absolute; the dial draws that instant on the browser's current clock: fly Berlin → New York, 09:00 draws at 03:00 — same moment, precisely _why_ it moved. Defect was never arithmetic; the app said nothing. `travelNotice(stored, current, hasEvents)` compares `settings.deviceZone` against the zone read **once** on load and asks once, as the whole screen (`TravelPrompt`, shaped like `BirthPrompt`), not a modal over a working dial. Names **cities, never IANA identifiers** — `Europe/Berlin` is a database key; someone just landed is owed the name of the place they left — and proves it by resolved illustration, not description: what a 09:00 event written back there reads as on this face. Two answers, both legitimate, neither styled safe, **no dismiss**: "keep them as they are" _is_ the do-nothing answer, and a dismiss would leave the app knowing the device moved and drawing the day as if not.
- **The shift is derived through the wall clock and is a function of each instant, never a subtraction.** `movedInstant` is `instantOfWall(wallClockIn(at, from), to)` — the pivot the recurrence walk turns on, settling DST-gap and repeated-hour wall times as every other reader here does. Two zones are not equidistant all year (Berlin/New York: six hours in July, five in the fortnight their transition dates disagree), so March and July events move differently, and one shift computed for "now" across a list is wrong for most of it. `until` moves at **its own** instant likewise: it bounds a start, and a series handed its old bound stops on the wrong day. `exdates`/`rdates`/`doneKeys` deliberately do not move — local wall-clock keys; both answers keep the wall clock, one by preserving it, one by naming the zone it was kept against. Rewriting them is the resurrection bug `duplicateOf` documents, from the other side.
- **An all-day event is re-anchored under both answers and stamped under neither.** A date has no clock to keep, so "keep the old times" is meaningless, and an offset on a day boundary puts the 5th on the 4th — five hours off midnight is previous evening. `reanchored` puts it on local midnight of its own calendar date in new zone, `addDays` rather than `n × 1440` minutes, the argument dial's multi-day span already makes.
- **Each answer is one recorded commit carrying both the events and the new `deviceZone`, and deliberately does _not_ own its settings.** `commit(next, true)` puts whole answer in one undo step, so ⌘Z gives calendar back — but device zone rides inside that step precisely so an undo does **not** restore it: an undo that "fully" undid the answer would put prompt back in front of somebody who already answered. A later reader tidies that asymmetry into consistency; it is deliberate, and why `setDeviceZone` (silent path for a first run, unmoved device, browser with no events of its own) passes `false` and writes no history. Silent path reads stored zone from store, not props: hydration is lazy and first commit's snapshot is still empty.
- **Keeping stamps the events, and the stamp has to stay legible afterwards or the answer was a trick.** `keptEvents` writes old zone into `tzid`, letting three surfaces name clock those hours belong to: readout prints city beside a span (never during a drag — a range being drawn has no event yet), agenda row prints it in trailing slot, editor's `Times in <city>` caption fires for every zoned event. Agenda slot is the cheap one on purpose: on a row neither headline nor running it was **always empty**, so nothing gives up a column and measurement that took `DAY 2/4` off headline row still holds. Precedence there is urgency first — `ends in 12m` outranks where thing was written — and a place is `uppercase` because slot's other two readings are prose and this one is a tag.
- **The clear knows which zones _this app_ stamped, and that list exists because `tzid` has a second writer.** First version walked every event carrying a zone; an imported `.ics` lands in the same `snapshot.events` with real zones from the file, so the settings row overcounted and its verb flattened a colleague's weekly 09:00 New York standup to floating — which then walks its rule against the reader's wall clock, the exact defect `startsBetweenIn` prevents, reintroduced by a settings row rather than the domain layer. `keepEventsInZone` records what it stamped with in `settings.stampedZones`, same commit; count, places and clear all scoped to it. A **list**, since two journeys kept in a row stamp two zones and one field would strand the first's stamps; `sane()` refuses entries `Intl` cannot resolve and deduplicates, since garbage would scope the clear to nothing while the row still counted it. Residue named in the caption, not papered over: an imported event genuinely naming the same city is indistinguishable from a stamped one and goes with them. Telling them apart needs a provenance field on every event — a permanent model addition for one settings row, against a residue narrow and one undo step wide.
- **Clear is the one travel action that _does_ own its settings.** It empties `stampedZones` as it clears: an undo restoring stamps without list naming them leaves them unclearable. Both derivations — count and places — read what events carry rather than setting alone, so a remembered zone that outlived its events counts nothing and shows no row.

### Shell, sidebar, top bar, focus

- **The shell's hotkeys are two registrations, split on `busy`.** Escape always live — it belongs to whatever is on top — everything else off while a panel is up: ← stepping day under an open editor is same bug as ⌘Z undoing behind one, and "is the user typing" misses it, since focus on a button inside a dialog is not typing. A panel wanting one of those keys keeps it: palette closes on its own ⌘P, shell's copy being off while it is open.
- **Escape's order is panel → life run → drawer → lit grid → ambient, and the life run is in the shell for exactly that reason.** `useHotkeys` fires every registration; no precedence between them. So year ring keeps its own `setSpan(null)` — nothing else on shell's list is live in that view — but a run drawn across a **lit** life grid is the natural way to use field, and a local handler there would abandon drag and clear thread in one press, the two-things-per-key bug this list argues against. Hence `LifeViewProps.draw`/`onDraw`: `App` holds run to put it at front of queue. Field's handlers then bail on `!draw` (dial's "both handlers bail on missing gesture" rule) so a pointer still down and moving cannot re-arm what Escape dropped, and `Field` clears run on unmount for the reason `Dial` clears its preview.
- **`useFocusTrap` finds the opener by `[role=dialog]`, not by its own ref.** React commits a child's `autoFocus` _before_ attaching parent's ref, so a ref-based "is this focus inside me" test recorded dialog's own first field as its opener, and Escape restored focus to a detached node. One document `focusin` listener for every trap, refcounted, same ordering reason: a dialog mounted only while open (the editor) does not exist when button opening it takes focus.
- **A trap's restore runs from a passive cleanup, by which time the dialog's nodes are gone** and focus has fallen to `body`. So restore fires on `body`-or-still-inside and checks `isConnected` — anything else moved focus deliberately and knows better than the trap.
- **The sidebar is `inert` when closed, not `aria-hidden`.** Held mounted 180 ms while it leaves, and `aria-hidden` over live tab stops is a keyboard user tabbing into controls nobody can see. `inert` takes focus and accessibility tree together — the one thing "this column is closed" means.
- **`push` against `drawer` is measured, not a breakpoint.** Dial is height-bound on any stage wider than tall, so taking `SIDEBAR_W` off width costs instrument _nothing_ — face does not even shrink. Once stage would be width-bound, every pixel column takes comes out of face: `rowWidth - SIDEBAR_W < rowHeight` is that condition. Not "is this a phone": an iPad in portrait is 1024 wide and still cannot afford it, and a half-screen desktop window flips exactly where it starts to hurt. Measured on the **row**, never `main` — `main` is already pushed width, so asking it would shrink stage, flip to drawer, un-shrink, oscillate. Pre-measurement frame is invisible because sidebar starts closed.
- **The drawer lives inside the row, under the top bar, and that is why it has no close button** — button that opened it is still on screen and reachable, so a header of its own is a second verb for one action. Modal in effect (covers whole face) ⇒ `role="dialog"`, focus trap, `tabIndex={-1}` for trap to land on, Escape. **Not** in `busy`: `busy` gates hotkeys because ← under an open editor steps day out from under unsaved work, and a drawer has no unsaved work. `shaded` is the other question — "is the instrument reachable" — what ambient timer and dial's ⌘⌫ ask.
- **The mini-month's dot row is always mounted, empty or not.** Rendered only when a day carried something, cell's `flex-col` re-centred and numeral rose half a dot on exactly the days with events — month read as a ragged line and the shift, not the dots, was loudest thing in grid. `h-[3px]` unconditionally. Any cell with conditional contents has this bug waiting in it.
- **The sidebar has no agenda — a decision, not a tidy-up.** Column printed selected day's occurrences two hundred pixels from dial's interior printing same ones, same fact twice, and the fact this 260px column had least room for. What is left is what interior cannot do: navigate to a day (mini-month), manage calendars, one complication. An agenda coming back needs an argument the interior does not already answer.
- **Settings is a near-full-screen overlay flowing balanced columns, not a 420px scroll.** `columns-[320px]` on scroll area, each `Section` a card with `break-inside-avoid`, so a new group spends width before scroll — panel only grows, and a setting below fold is one nobody finds. Consequences: a column is 320px, so every inline row inside a `FieldRow` MUST `flex-wrap` (a two-toggle row overflows a card at phone width), and each section's last row takes `last`, card's own border being the boundary.
- **`.label` is a label voice; a sentence uses `.caption`. And the two greys it is written in are a hierarchy, not a choice.** 11px mono uppercase at 0.18em tracking reads as three words, hostile as prose. `ink-2` (~5.4:1 on `surface`) for anything that _names_ — a `FieldRow` label, group heading, inline word naming its control, a `NumberField` suffix; `ink-3` and `ink-4` for anything that _annotates_ — a `PARTSTAT` tag, count, time under a title. A name may **not** take `ink-3`: `ink-3` is also `input::placeholder`'s grey, and at one grey a label and the words standing in for a missing value read alike — a card of unfilled rows was a wall of identical grey, labels no louder than absences. `ink-4` (~1.5:1) is decorative only, never text. `.caption` = 12px sans at `ink-2`; add `tabular-nums` for a time or count. Every inline `.label` naming a control moves with its row label, or the row comes apart at the two voices.
- **`MOD`, in `ui/primitives.tsx`, is the only place a modifier is spelled.** `useHotkeys` always accepted `metaKey || ctrlKey`, so chips were app's one Mac-only part. Read from platform at module scope — island is `client:only`, nothing can disagree — and only ⌘ is translated: ⇧, ↵ and ⌫ are printed on keys themselves, and `Ctrl Shift N` across four segments costs top bar something else. It is 40px against ⌘'s 18, making left group 67px wider, so **`TopBar`'s two measured thresholds are a pair** (readout 1220/1450, wordmark 1430/1660) written as whole class strings — Tailwind reads file as text, and a class it cannot see it does not emit. Anything joining that group re-measures both, on both spellings.
- **The top bar has three measured breakpoints and a fourth segment moved all of them.** The readout is absolutely centred on the _bar_, not on the space the button groups leave, so whatever the left group gains comes out of the readout's clearance — and the wordmark yields every time, being the only thing up there that is identity, not information. Wordmark gone below **1430px** (1080 at two segments, 1180 at three), readout below **1220px** (was 820), `‹ Today ›` stepper below **480px**, where three groups stopped fitting a phone. The stepper is right to drop: the one control with another route — the drawer's mini-month, a face in ⌘E, a date typed into ⌘P — where hiding a view or the drawer's button would cost something with no second route. All three measured against the longest header `formatDayHeader` produces (`Wednesday · Sep 30`); anything added re-measures all three, by a sweep from 360 to 1600 for overflow or collision, not a spot check at two widths.
- **`settings.weekStart` is one setting because it is one fact, and it is geometry as well as chrome.** The strip's seven days, the mini-month's grid _and_ header row, the top bar's week range, the life grid's columns (real weeks) and the loupe's transpose (a row is a weekday) all read it; three settings would let them disagree where a week starts. `WeekStart` is `0 | 1 | 6` — the three starts anybody picks; `weekOffset`'s arithmetic is general, the picker is not. **No default parameter anywhere in `lib`**: an implicit Monday is the bug, and a required argument makes a missed callsite a type error. `LifeLayout` and `LoupeLayout` carry it, so anything already taking a layout reads it there rather than growing a parameter. RFC's `wkst` untouched — a rule's meaning is not a display preference. **The one place `weekStart` still gets a default is `freshInstall()` in `store.ts`**, only there: `weekStartFor(locale)` (`time.ts`) reads `Intl.Locale`'s `getWeekInfo()`, or the older non-standard `weekInfo` property where `getWeekInfo` is absent, maps ISO's `firstDay` — 7 → Sunday, 6 → Saturday, else or throw → Monday — and runs only on the branch a browser with nothing stored takes, so a stored `localStorage` value can never be overwritten. No `SCHEMA` bump: a bump resets settings to defaults, and where a default came from is not a change of meaning — `hydrateEvents`'s missing-field fill-ins stand on the same argument.

### The mirror file, and the thing that reads it

- **The mirror file _is_ a `.json` backup, plus a `zone` and a `rev`.** Deliberately not a new format: same shape, same validators, so a mirror can go to Import and an export from before any of this to the mirror. `readMirrorFile` goes through `backup.readBackup`, boundary already assuming hostile input — something outside browser writing your calendar is exactly that, however well meant. An absent `zone` or malformed `rev` reads as "did not say" rather than failing file: losing a calendar over bookkeeping is the wrong trade.
- **A file, not a localhost bridge, and the reason is the tab.** A background daemon the page connects to only works while circal is open, making an assistant blind at unpredictable moments — worse than one never there. A file sits on disk whether tab exists or not. It also settles the other half of `AUDIT.md`'s oldest complaint for free: `localStorage` was the only copy, and "Clear site data" is one menu away.
- **`mirrorDigest` is what stops the file churning.** Mirror writes on every store change and a feed pull stamps `fetchedAt` on its calendar — so `serialiseMirror` zeroes a subscription's pull state (`exportBackup`'s own normalisation) and digest compares the three fields actually about the calendar. Without it every subscription refresh rewrites file and looks to a watcher like a changed calendar. Same trick as `baseSignature`, one layer out. An adopt records digest of what store **made** of contents, never contents' own — `adopt` normalises on the way in (`sane` clamps, feeds are swept), so file's digest can differ from store's, and recording file's answered every adopt with one extra write saying nothing.
- **A file ahead of us is merged where both documents are stamped, and adopted where either is not.** `mirrorVerdict`'s `adopt` used to mean "take their document whole", which across two machines discards a day: laptop edits Tuesday, PC Wednesday, and the undo step lands on the machine nobody sits at. `merge.ts` is the missing diff — `Grave` plus `CalEvent.updatedAt`, since a filtered array cannot tell _deleted here_ from _not seen here_. `mirrorMerges` is the gate, `MIRROR_VERSION` 2 what it reads: a v1 file, or `settingsAt` of `0` either side, gets today's adopt/stale behaviour exactly. `connect()` still adopts rather than merges, deliberately — the gesture is a person naming their calendar's file, and on a first run the local document is eight seed events that must not propagate. **`mirrorDigest` is canonical (`canonicalJson`) and cannot go back to `JSON.stringify`:** a merged document holds records from both sides, and an event stored here enumerates its keys differently from the same event rebuilt by `readEvent` out of the file, so an insertion-order digest reads a no-op merge as a change — both machines write, each reads the other's write as news, one write every poll for ever.
- **An undo restamps and buries; `adopt` never restamps and `restore` always does.** A step holds events as they were, _with the stamps they had_, so an undo put back a record the other machine's copy outranks and next merge silently reverted it. `merge.restamped` is the one answer: what a step changes is stamped now, what it removes is graved. `adopt` is exempt because what arrives is a merge or another writer's document, and re-dating it makes adopting machine win every subsequent merge wholesale — the bug this work exists to fix in a different hat. `restore` is not exempt: a user importing a backup asked for that file to win. Tidying that asymmetry into consistency reintroduces one of the two.
- **`rev` is the whole concurrency story, and `stale` does not adopt.** A writer reads, checks rev is still what it read, writes `rev + 1`. `mirrorVerdict` answers `ours` (we wrote it — adopting would loop), `adopt` (somebody moved it on) or `stale` (file is _behind_ us: an older copy restored underneath tab). Stale makes browser re-assert rather than adopt: winding a calendar backwards is the one outcome nothing undoes, and `localStorage` still holds newer truth.
- **Both halves keep that contract now; the browser did not, and it cost events.** `casWrite` in `mcp/file.ts` always read-checked-wrote. `mirrorLink.write()` went straight to `handle.createWritable()` — a blind truncate — so two events written through an agent vanished mid-session, no error either side: `onStoreChange` debounces `SETTLE_MS` (400ms) at `localRev + 1`, an agent writing inside that window does not move `localRev`, and the tab then wrote **its own `rev N+1` from memory**, so both writes carried the same number and nothing downstream could notice. `claim()` is the fix: re-read immediately before replacing, answer with the revision to write or `null` for no write. It reuses `mirrorVerdict` rather than forming a second opinion — the three answers are the same three — and only `adopt` changes anything, since `stale` re-asserting over an older copy is the anti-rollback already wanted. It **abandons rather than merges**: no diff here, only two whole documents, and merging by id resurrects anything deleted locally (`duplicateOf`'s resurrection rule from the other side). Adopting makes the casualty the _local_ edit instead of the agent's, and that one is recoverable — `store.adopt` records an undo step and toasts. The revision comes from disk (`max(found, local) + 1`), not a caller's arithmetic: two writes can queue behind `writing` and the second's number was worked out before the first ran. `absorb` is the adopt path `poll` and the guard share. Verified by driving the race through the shell bridge, not by reading it: pre-fix the agent's event is gone 600ms later, fixed it survives.
- **The window inside `casWriteOnce` is closed by an advisory lock, and the halves are deliberately asymmetric.** Between confirm-read and `atomicWrite` was a milliseconds-wide gap no re-read could close — the confirm-read _is_ the re-read. `acquireLock` takes a sibling `.lock` (exclusive create is the atom; mtime past `LOCK_STALE_MS` reads as a crashed writer and is broken; a live one is waited out to `LOCK_WAIT_MS`, then refused naming the file). Staleness judged by mtime, never pid: a pid cannot tell a dead writer from one on another machine, and a synced folder is exactly where a second writer lives. The browser cannot take that lock — a `FileSystemFileHandle` reaches one file, never its siblings — so on its side `withFileLock` (Web Locks, origin-scoped, exactly the writers sharing the IndexedDB handle) closes tab-vs-tab; browser-vs-server stays what it was, honest by `claim`'s re-read and the server's confirm-read, not excluded. Do not "simplify" either half onto the other's mechanism; neither can see the other's.
- **`atomicWrite` fsyncs, because temp-file-plus-rename alone was two thirds of what its comment claimed.** A rename survives a process crash, not a power loss, where `writeFile` returns with bytes in page cache and rename's metadata can reach disk first, leaving new name pointing at a short file where a complete one was. Temp file synced before rename, directory after — directory **best-effort**, since not every platform will open one and failing a write whose bytes are already durable over a durability nicety is the wrong way round, `remember()`'s trade one layer out. Temp file removed if anything after its creation throws.
- **A write is never a patch, so the reader refuses a file it does not fully understand.** Every mutation round-trips whole document through `readEvent`, which keeps fields it has names for and drops the rest — so an older reader writing a newer file silently loses exactly the fields it was too old to know about. Measured, not feared: published `circal-mcp@0.1.0` bundle dropped nine keys per document (`free`, `remindLead`, `organizer`, `attendees`, `attendeeCount`; `backupNudge`, `backupInterval`, `deviceZone`, `stampedZones`). `MirrorContents.version` carries envelope version — absent reads as this build's own, for the reason `zone` does — and `assertVersionAllowsMutation` refuses beside zone guard it mirrors. **No override env var**: an operator can reason about a zone mismatch and be right; "my reader is too old for this file" is not that. Reads still go through: reading cannot damage the file.
- **Remembering the handle must never fail a sync.** IndexedDB put persisting handle and rev is bookkeeping; write it follows already put calendar on disk. Reporting that write as failed because note did not stick is the wrong way round — and it is exactly what a browser with storage refused looks like, where file itself is written perfectly well. Found by driving it in a browser, not by reading it.
- **`store.adopt` says nothing itself.** `restore` without the toast: only caller knows which file moved and whether this was a sync or a reconnect. Undoable and owns its settings, so a wrong answer from an assistant is one ⌘Z away — also why `connect()` **adopts** a file already holding a calendar rather than overwriting it. Destructive direction is the one that cannot be undone.
- **`src/lib/mutate.ts` exists so the scope question has one answer.** `EditScope` — one / future / all — is asked at press in app and demanded as a parameter by server, both through same five reducers. Two copies of a three-way question drift into two vocabularies the moment either side changes. Server **refuses** a mutation on a repeating event naming no scope rather than picking one: guessing `all` deletes a year of standups.
- **The zone is in the file because every day boundary here is local.** `dayKey`, `startOfDay`, the whole of `tests/west/`. A reader in another zone would put events on wrong day and be confident about it, so server warns on a read and refuses a write unless `CIRCAL_ALLOW_ZONE_MISMATCH=1`.
- **The MCP server imports the app's own domain layer, and that is the point.** `parseQuickAdd`, `dayAgenda`, `freeGaps`, `scoreEvent`, `describeRule`, `readEvent`, `mutate.ts` — a second implementation of any is a defect, not a shortcut: it is how assistant and dial come to disagree about what Tuesday contains. `store.ts`, `backup.ts` and `notify.ts` import React but touch no DOM at module scope and guard their `localStorage`, so importing them in Node is safe. **Nothing in `src/` may import from `mcp/`** — browser bundle must not gain a byte from it.
- **Built on `@modelcontextprotocol/server` v2 (spec revision 2026-07-28), not the v1 `@modelcontextprotocol/sdk`.** v2 is `McpServer` + `registerTool` with Zod v4: one schema per tool, from which SDK derives the JSON Schema the model sees, validates arguments before handler runs, and infers handler's types. It also carries per-tool annotations that matter for a surface like this — `readOnlyHint` on six read tools, `destructiveHint` on `update_event` and `delete_event` — which is what a client uses to decide what to confirm. **stdout is the protocol channel**: log with `console.error`, one `console.log` corrupts the stream.
- **`MirrorFile.remembered()` mints and adopts the default path when nothing is remembered and nobody has said no.** `~/Library/Application Support/circal/calendar.json`, created empty — the safe seed `poll()` reads as "nothing to adopt, the next write fills it" — so an assistant connects on first launch with no gesture at all, not merely no second one. `mirror.declined` in `UserDefaults`, set by `forget()` and cleared only by `pick()`, makes disconnecting stick: without it the next launch mints the default back and silently undoes what the user did. The save panel stays, for a file wanted in iCloud Drive or a repo. Destructive direction unchanged either way: adopting never writes content to a file it did not just create, so a picked or default path already holding a calendar is adopted, never overwritten — the one outcome nothing undoes, the argument `mirrorVerdict`'s `stale` case stands on. `circal-mcp --find` checks this exact path first, named outright rather than discovered, because it sits inside `Library`, which its walk otherwise skips on purpose.
- **A `FileSystemFileHandle` exposes only `.name`, never a path — true of the browser, and now only of the browser.** Deliberate privacy design, no way around it from inside a page, so on web circal cannot tell a user where their own mirror file lives on disk and cannot pre-fill it into a command; `circal-mcp --find` exists for that gap, searching instead of being told, and `/assistant/` explains the absence rather than papering over it. `AUDIT.md` Tier 6.2 named the exception before it existed: shell's own picker returns a security-scoped bookmark, which does resolve to a path, so `MirrorFile` in `mac/main.swift` reads it straight off to mint and adopt default location with no gesture at all — the standing complaint "stops being true the moment the shell owns it," and now does. Copy written for web build still may not claim to know a path it cannot resolve; `circal-mcp --find` still matters there, unchanged.
- **A `.ics` the Dock hands over is text, and the page owns the one import path.** `application(_:open:)` in `mac/main.swift` never parses a calendar — `src/lib/ics.ts`'s `fromIcs` stays the only parser — it reads the file as UTF-8 and calls `window.__circalImportIcs`, the exact function the settings panel's Import button calls, so a drop and a menu import cannot mean two different things: same new calendar, same toast, same undo step. The first draft flushed a cold-launch drop on `didFinish`, reasoning a finished navigation meant the page had registered the global — true before the lazy split, false the moment `Settings` and `EventEditor` moved into their own chunks and pushed the registering effect later still. `window.__circalReady`, posted from that effect the instant it runs, is what the shell now waits for before flushing anything queued; a reload clears the flag until the page posts again, so a drop from before cannot reach a page that has not re-registered.
- **`window.__circalSave` exists because `<a download>` does nothing in a `WKWebView`.** Measured: click resolved to nothing, so both `.json` backup and `.ics` export silently wrote no file at all in app build, while identical code downloaded correctly on web. `backup.ts`'s one `download()` helper is now async and checks shell's bridge first, falling back to anchor, so no call site learns there are two ways to save — the bargain `mirrorLink.ts` already strikes for its own picker beside `showSaveFilePicker`. It returns whether a file was actually written: shell's `NSSavePanel` can be dismissed, and `exportIcs`/`exportBackup` skip their toast on that `false` rather than announcing an export user just cancelled — browser anchor has no cancel to observe, so it always reports `true`.
- **The status menu's login-item and Dock checks read live, in `menuNeedsUpdate`, never a cached boolean.** A login item can be removed from System Settings → General → Login Items without circal knowing, and a cached check would have menu asserting something no longer true; same argument for Dock check, since `NSApp.activationPolicy()` is running app's own answer and nothing else can go stale either. `SMAppService.mainApp.register()` is off until asked, deliberately: a calendar that adds itself to login items unbidden makes people distrust software, and `register()` throwing surfaces through `bridge.note` rather than leaving a check that no longer means what it says.
- **Menu-bar-only mode costs the `.ics` Dock drop, and that is the honest trade, not a bug.** `NSApp.setActivationPolicy(.accessory)` removes Dock tile, and without a tile `applicationShouldHandleReopen` never fires — the drop two bullets up cannot land, leaving ⌥⌘C and status item as only ways back in. Applied at launch, before window exists: switching once window is up needs a re-activate and re-key to avoid leaving app behind others, and toggle does both. Default `.regular`: a mode somebody chooses after finding status item, never one they wake up in.

### Sound and haptics

- **`lib/feedback.ts` builds `AudioContext` in `onPointerDown`, never module load.** Outside gesture = `suspended` forever, first drag silent. Re-`resume()`s per cue: backgrounded tab wakes asleep.
- **Every cue = one mechanism: 3 ms noise impulse struck through bandpass resonators, one impulse per hit time.** `SOUNDS` in `feedback.ts` = whole instrument. `step`/`slide` = single hits; `opened`/`created`/`deleted` = same hit 2–3× at 50–100 ms, pitch _order_ meaning (up finished, down removed). Earlier draft's oscillators for long cues sounded like another app's notification — no tone. Each hit needs own contact transient scaled by landing force; without, later hits read as hiss with resonance.
- **`level` = gain _into_ narrow resonance, not peak.** Most of 3 ms impulse's energy never passes — multi-hit cues carry levels above 1. Offline peaks at shipped `LEVEL` 1.35: `step` 0.43, `slide` 0.20, `created` 0.42, `deleted` 0.42, `opened` 0.28 (its `Synth.peak` directly: `renderVoice` normalises sum, `LEVEL` never touches a voice). Retune via `OfflineAudioContext`, measure **in a stream** — sixteen clicks at 45–110 ms, only condition a drag cue occurs in. Lone click isn't; not academic: see hour detent below.
- **Contact is sound; resonance table is colour.** Q=8 bandpass passes ~1% of 3 ms burst, `contact` highpass nearly all — click leads resonators **13.6 dB**; `SOUNDS` freqs = tint, not tune. `step` vs `slide`: octave apart every partial, yet 6.9 dB level, **3.6%** centroid. Speaks in level: tell apart by loudness or _when_.
- **Exciter seeded (`BURST_SEED` = 43) — bug fix, not tidiness.** Burst ~130 samples, resonator hears only its passband: Q=8, 1950 Hz ⇒ bandwidth × duration ≈ 0.7 ⇒ **one degree of freedom**, each resonance ~one coin toss. `Math.random()` tossed once per page load (buffer cached per session): 4.2 dB peak, **30 dB** tonal balance between reloads — `step` dull 1950 Hz knock one session, bright 4200 Hz tick next, switching on refresh. 43 measured, not chosen: of first 400 seeds, band energy at every `SOUNDS` resonance nearest random-draw ensemble mean (within 1.8 dB at 44.1 and 48 kHz, vs median 4.0, p90 6.1) — burst table was tuned against, every time. Per-click repeatability (0.1 dB across drag) unchanged; that's what caching was for.
- **A drag has one click, and the hour is deliberately not accented.** Two cues existed — `stepHour`/`slideHour`, deeper notch every 4th step, theory: dial countable by ear. Killed twice. Never worked: v1 accented via timbre+ring length, **1.3 dB in a stream** vs 0.1 dB click-to-click spread — fifth of way to audible, unnoticed for months. Retuned to real 4 dB + 14 ms rebound, still wrong feature: face centre prints `9:00 – 11:30 · 2h 30m` for whole gesture — accent answered answered question, on channel already firing fifteen times a second. **Do not add it back.** Second signal on drag? Readout works.
- **Only `gated` cues rate-limited.** `step`/`slide` fire dozens/sec, share one `MIN_GAP_MS`; one-shots bypass on purpose: `opened` lands ms after drag's last click — the gap limit swallows.
- **Keyboard = second instrument, `lib/keys.ts`, one mechanism down: every key = sum of damped sinusoids, no noise.** Recorded switch = broadband hiss + resonance; screenful = fatigue. Voice = `Synth` (`layers`, `length`, `peak`); `render` sums layers, scales _sum_ to `peak` — two partials add 1.0–1.5 by phase; guessing = key twice neighbours. **No asset, no fetch**: 8 buffers rendered on session's first keystroke, at device sample rate, well under a millisecond.
- **Two letter clicks = Refit from bundle** — 2600 → 200 Hz over 8 ms, and steady 2325 Hz, both 1.4 ms time constant, nothing above 3.5 kHz, spectral correlation 0.96 vs originals. Params not asset on purpose: exact at any sample rate, free. No noise transient "improvement" — that's this vs clack.
- **All three big keys were recordings first (Everglide Oreo board) and all three lost.** Space = 1820 → 140 Hz at τ 2.0 ms, letter click lower/longer; first click over 145 Hz partial ringing 14 ms — theory: bar needs tail, but tail read boom next to clicks this dry. Delete starts 1500 not 2600, glides less: duller not brighter — removing character shouldn't sound like typing one; recording's _release_ 1.8× press (0.115 vs 0.064), why it sounded undecided. Return lands twice; once layer could start late, clunk came from parameters — last asset out of app.
- **Late layer = key landing twice, belongs in buffer — never caller.** `Layer.at` (sec) offsets contact inside one voice: `render` measures that layer's glide, decay, 0.2 ms attack from its _own_ start. One buffer per voice = one `start()` per keystroke, only way gap scales with `playbackRate`; scheduled separately, jitter moves pitch, leaves gap. Return's contacts 9 ms apart; 14 ms draft read as two keys.
- **`CLICKS` alternates strictly; never random.** Two-item bag repeats ~half time; repeat keystroke = artefact alternation prevents.
- **Levels = one family both instruments, every key multiple of `LETTER_PEAK` (0.24)** — under detent's measured 0.27: typing hundreds to drag's once. Space/Return 1.1×, delete 0.92×; release: letter 0.275× press, space 0.32×, delete 0.30×, Return 0.42× — let-go = sound of thing having happened. Nothing baked: `LETTER_PEAK` moves whole keyboard, keeps ratios. That 0.27 = `step`'s, now _quiet_ half of detent pair — hour's 0.43 = accent 4× a drag, not working level, not compared to keyboard.
- **`useTypingSound` listens on `window`, reads `e.code`, not `e.key`.** "Typing" = document property, not component: one listener pair covers palette, editor, settings, anything later — no field knows sound. Physical key makes noise: shifted `2` and `@` = one key. Silent: bare modifiers, `⌘`/`Ctrl`/`Alt` combos, `date`/`range`/`checkbox`/`radio` inputs, `SELECT` — select arrowed, not typed; combo = command, panels announce those. Held-key map cleared on `blur`: field losing focus mid-hold never sees `keyup`, stale entry fires that key's next press.
- **Auto-repeat makes no sound: `if (e.repeat) return`.** One press = one sound however long held — what keyboards do physically, only fix for held-arrow machine-gunning. Rate-limiting failed first: 30 ms repeat interval clears any floor short enough for fast typist's digraphs; `MIN_GAP_MS` (18) exists only for those. Verified, 40 trusted `autoRepeat` events: two sounds, press and release.
- **Panel arriving says `opened`, from effect keyed on panel's own flag** (`paletteOpen`, `settingsOpen` in `App.tsx`), not per-call-site cue — four sites (⌘P, top bar, palette→settings) drift. Audio = external system: effect's job. Channels from ref updated in own effect: flipping Sound while panel open won't re-announce, `actions` need no dep. Refs never written during render here.

### Quick-add and palette parsing

- **Quick-add reads sentence right to left.** `parseQuickAdd` in `lib/quickadd.ts` peels duration, then time or dash-range, then date off _end_; rest = title — only free-text field, always prefix. Order irrelevant: `lunch 1pm tomorrow 45m` = `lunch tomorrow 1pm 45m`. Duration before time (`1h30` = 90 minutes, `130` = 01:30 — only unit distinguishes), date last: bare number _in a sentence_ = hour, not day of month. Range = dash only: `to` hits titles ("go to gym") more than times; eating it eats title.
- **`parseQuickAdd` returns `null` unless line names more than title, invents nothing.** Bare word = search, bare date = jump — palette answers both; why no create row under every query. Day, no time = **all-day**: that's what was said. Duration, no start = `defaultStart` (next quarter hour today, 9:00 else), ⌘N's rule, imported not copied. Creates+closes, no review: row prints span before Enter.
- **Palette whole-query parsers in `lib/quickadd.ts`, split 3 ways.** `parseDate` (jump), `parseSlot` (free-time search — only form where bare number = minutes), `parseDurationToken` (unit required; scanner uses). Private to `CommandPalette.tsx`, untested — why composing them wasn't the "wiring" it looked.
- **Repeat claimed before date, always carries own word.** `parseRepeat` reads `daily` / `every 2 weeks` / `every other friday` / `weekdays` / `every mon/wed/fri`; scanner tries it _first_ each pass: `every friday` ends in weekday — date matcher first grabs weekday, leaves `every` in title, fires once. Converse: bare weekday never a rule — `party friday` = one party; fifty-two = worst mistake.
- **Weekday rule moves first instance onto day rule generates.** `gym every monday` typed Wednesday starts Monday. Else seed = skipped day, arc vanishes on save — `daysOfPeriod` generates from rule, not seed. Only if no date named: explicit `2026-09-14` = instruction, outranks tidying.
- **`RepeatSpec` carries only what editor can spell** — frequency, interval, `byDay`. No `until`: needs _second_ date from same line, nothing says which is last. Palette rule stays editable.
- **`in` switches length→offset, so deliberately not in `FILLER`.** `dinner 2h` = two-hour dinner; `dinner in 2h` starts two hours out. Sweeping `in` up as connector — tidy-up, word stranded in title — keeps length reading, _removes evidence_: two-hour dinner at default hour, no `in` left. Same reason `parseOffset` claimed before duration matcher, else `2h` taken from under it.
- **All after `in` = offset, greedily; length before name.** `in 1h 30m` = 90 min out — trap: "in an hour, lasting thirty"; that spelling of 90 min is normal. Both = `45min dinner in 1h`, so `parseQuickAdd` claims **leading** duration from left after right-to-left pass (trailing wins, title never empty). `in` before non-duration = word: `dinner in Rome`, `coffee in a bit`.
- **Offset names clock; date still names day.** `dinner tomorrow in 2h` = tomorrow at now+2h: `fromNow` sets day only if nothing else did; named day keeps date, `fromNow % MINUTES_PER_DAY` gives minutes. Unnamed, offset rolls day — 23:20+2h = tomorrow 01:15. Explicit clock beats offset: line with both half-edited.
- **Offset lands on quarter hour** (`snap(minutesOfDay(now) + offset, 15)`), nearest not next — `now` = quarter you're _in_: at 10:07 next is 8 min off, not now. All machine times on dial grid — `defaultStart`, drag — 19:07 on 15-min face reads accidental.
- **Palette ranks with `fuzzyScore`, not `includes` filter.** Letters in order, non-adjacent (`dsgn rev` finds "Design review"); **one** query char forgiven from four up — covers wrong letter and transposition: both leave clean subsequence minus offender. Sort = score, then old nearness-to-day tiebreak; empty query scores all `0`, list order survives. Commands keep hand-written order till query: "New event first, calendars last" _is_ answer to empty box.
- **Two things in `fuzzy.ts` are corrections, not decoration.** Run bonus _rises_ through run (`RUN * n`): flat scored three adjacent letters as three word-initials, `run` ranked "Roll up now" over "Morning run" — whole word not initialism. Scan restarts at every word start: greedy takes earliest fit — `run` matched `r` in "Morning", reached for rest. Both cheaper than dynamic program per candidate per keystroke, unjustified for eight rows. Hit outside title = **penalty** (`FIELD_PENALTY` in `CommandPalette.tsx`), never multiplier — scores go negative, halving negative promotes it.

- **Runs draw as bands, never dots — `CellBand` makes it affordable.** Day-runs contiguous in reading order ⇒ ≤3 rects (tail of first line, whole lines, head of last): dragging a life = three `<rect>`s, not 30k arcs on canvas rebuilt per pointer move. One private `cellBands`, both surfaces, own axis each: `lifeBands` day rows, `loupeBands` weekday weeks, clipped to on-screen year. Transpose again.
- **Life grid lights `pending` too — rule other two faces keep.** White/faint while run draws (no colour yet), draft's colour once editor has one, so modal handover doesn't look like range tossed. `run` refuses `pending` missing span: `lifeRange` clamps, not declines — else 1850 edit lights birth dot.
- **Life grid's box measured by shell, not view.** `App.tsx` observes `main`, resolves `lifeStage(...)`: zoom needs day's dot in screen coords _before_ grid exists. Hence `LIFE_META_H` constant + strip pinned to that height in CSS: shell subtracts it for field origin; +2px strip = dial off 2px/dot.
- **Life span = 2 settings, storable wrong, not just missing.** `sane()` in `store.ts` = one clamp: `birth` not `YYYY-MM-DD` → `""` (re-prompts); `lifeExpectancy` pinned in `LIFE_EXPECTANCY_RANGE`. On `parse`, `store.setLife`, `restore`: `readSettings` in `backup.ts` guarantees only types.
- **Milestones are three or four marks; count is the design.** `lifeMilestones` in `lib/life.ts`: round days in span (10,000 / 20,000 / 30,000) + midpoint — default 80-year life = three. 1,000/5,000 sound like milestones, aren't: before memory of the day, already past. Decades **not** listed: rules/labels name them; dot on rule = fact twice.
- **Midpoint = `floor(days / 2) + 1`, not rounder `ceil(days / 2)`.** Card para 2 claims: past this dot spendable half is smaller — even spans, `ceil` leaves one more day ahead than behind ⇒ false. `tests/life.test.ts` asserts claim, not formula. Midpoint on round day dropped, not double-drawn: 2 marks/1 dot = 1 unclickable mark.
- **Milestone ring drawn in SVG overlay; hit area a real `<button>` in own layer.** Two layers, one `marks` array: ring under today's halo + hover ring (milestone = grid property; those three = where you are now), target above canvas. Buttons also **the grid's only focus path** — 3 tab stops usable, 30,000 dots not. Cost: those 3 days lose field click — hence `Go to this day`, not courtesy.
- **Milestone prose lives in `lib/life.ts` beside the function, no em dashes.** House rule for long-form user-facing writing, asserted in `tests/life.test.ts` so future paragraphs can't reintroduce one. Comments keep repo voice; ban = prose users _read through_: milestones + all of `src/pages/manifesto.astro` (866 words, verified on rendered page; no DOM in suite → on you). One-line captions: not long-form.
- **`lifeMilestones` walks with `addDays`, so it has a `tests/west/` case.** 10,000-day mark crosses 20 US DST transitions; ms walk drifts 1h off midnight → wrong-day dot west of UTC. Per `dayKey`/`startOfDay`: day-keyed ⇒ west case.
- **Shell clock ticks once a minute — free, not a compromise.** Nothing in circal prints a second: `splitTime` is `HH:MM`, `untilText`/`formatDuration` round to minute, hand is `minutesOfDay`. `useNow` aligns to own period boundary: `useNow(60_000)` in `App.tsx` fires at `:00` — exact instant those strings change (verified: `01:17 → 01:18` landed `01:18:00.09`). Formerly 1 Hz, waking Dial, CenterPanel, YearView, LifeView 3,600×/hour to redraw already-correct pixels. **Anything finer than a minute asks for its own clock in the leaf that prints it, never by raising the shell's rate.** Exactly one: `LifePercent` in `LifeView.tsx`. Hook also re-aligns: `visibilitychange`-to-visible and `window` `focus` re-read clock, re-arm to true boundary — suspended machine or throttled tab leaves last tick stale up to a full period. Wake observer (`NSWorkspace.didWakeNotification`, synthetic `focus` at page) makes laptop lid trigger that vs awaiting next focus; reload fixes same skew, rejected — discards scroll position, open editor, unsaved draft over ≤60s error.
- **`PERCENT_DECIMALS` is derived, not chosen; moving it needs the table beside it.** Step = `span / 10^(decimals + 2)`. At 6: 25s at 80y, 47s at 150y max — six decimals sitting still, slower than shell's minute. At 8: 0.25s — several steps per 1s clock tick below, 3 of 4 values never drawn; honest only on `requestAnimationFrame`, digit faster than read = noise. **Seven is the only value inside five seconds across the whole of `LIFE_EXPECTANCY_RANGE`** (2.5s default, 4.7s at 150). `tests/life.test.ts` pins bound, not arithmetic: digit moves within 5s on every span drawn, 3s at default, _not_ within 1s — stops it outrunning its clock.

### Loupe

- **Loupe = magnifier, not zoom — the view's whole invariant.** 30k dots at 4px read as picture, not day; pan-zoom makes life a map, worse than a picture of it. So 80 years never move: year under pointer redrawn large on card over field. Rejected fisheye-in-place — fine for 1D closed year ring, `spread` conserves own slack; grid pushed in 2 axes overlaps rows or opens hole, columns stop being real weeks. Distort cartogram ⇒ picture no longer the picture.
- **Loupe = grid's own cell arithmetic at `colsPerLine = 7`, transposed — arithmetic, not taste.** At desktop split a field line already spans full width: magnifying a year in the field's orientation gains nothing across, nowhere to go down. Sideways it's `LOUPE_COLS` (54 — always the wider of 53 or 54, else the strip wobbles as the pointer crosses a year) not 372, pitch 4–5×. A column _is_ a week ⇒ no week gap. `loupeCell(d).row === mondayOffset(d)` is the claim, and the tested one.
- **`LOUPE_GAIN` is a coverage correction, not a preference.** Field dot covers ~`0.36` of cell (`π·r²` over `pitchX · pitchY`, desktop split); loupe `π · 0.4²` = `0.50` of a square one. Same `TONE` = 40% more light/area — plate competed with event colours, which this grey channel may not do. Gain = `0.36 / 0.50`. _Ratio_ in `TONE` untouched: past still reads vs future, month band still drifts; only absolute light moves.
- **Loupe writes field's own `hover` — control, not picture.** Point big dot → small one's ring + tip move; press opens day; drag draws run of days into editor — impossible on four-pixel field. So card alone must _keep_ hover when pointer leaves canvas: one `onPointerLeave` on wrapper around pair, never canvas; blank loupe cells ignored, not cleared (crossing one drops card from under pointer). `loupeLayout` → `null` if cells don't beat field's dot by `1.8` or under five pixels: second picture earns no room.
- **Card hangs in the half the pointer isn't in, on two thresholds.** `sideFor` flips top past `0.62` of field, back below `0.5`: one line = 150px chrome flipped per pixel jitter — `DayTip`'s own flip with hysteresis, card isn't a tooltip. `DayTip` takes `avoid` band, moves to pointer's other side when it'd hit loupe, only if clear. Band + keyboard `aim` = why `locate` returns its point even on a miss: blanks between years answer which half too.
- **Card waits `LOUPE_DWELL` before arriving — tool vs flicker.** Largest unclicked-appearing thing here: pointer crossing field toward top bar mustn't throw 150px of chrome behind it. `asked` is its own flag, not a hover reading — hover changes every 4px, wait mustn't restart; `wake()` early-returns once asked: field → card → field never re-dwells. **Keyboard skips it** — `aim` sets `asked` directly: dwell is for a pointer headed elsewhere, a keypress never is. In `LOUPE_IN`, out `LOUPE_OUT` = ⅔: things go faster than they come, a lingering card blocks what it magnified.

### View transitions

- **Day ⇄ life = zoom, year ⇄ life = unroll, day ⇄ year = crossfade.** All in `PANEL` (`transitions.ts`); `AnimatePresence` keys one panel per view. Dial scales onto its day's dot (`transformOrigin` = _style_, so already right on leaving panel's frozen render) as grid's wave leaves it; reversed, wave collapses, dial grows out. Exiting panel drops pointer events at once — on top nearly a second; click on view you left = invisible bug.
- **`exit` is a variant label, so panel MUST get whole table.** `initial`/`active` resolve at render as objects (see frozen-props rule); `exit="exit"` is a _label_, and label with no `variants` resolves to **nothing at all** — silently, no type error, no lint. `variants` dropped when other two left labels ⇒ 2 months of no-op exits: dial popped out, not shrinking onto its dot. Objects outrank table ⇒ `variants={PANEL}` free, keeps `exit` alive. Verified by measuring leaving panel's `transform` across flight — only way it's visible.
- **Zoom's scale keyframes are geometric, not linear.** Size linear in scale ⇒ plain `1 → 0.008` hangs, vanishes in 3 frames. `ZOOM_STEPS` = 5 keyframes, each a third of last, `ease: "linear"`, uneven `times` → smallest step longest slice = settle. Wave near-linear, reverse: ease-outs crossed window in 120 ms, crept.
- **A leaving element cannot read the new view from its props** — frozen at last render. So `ViewFlow` = _ref_ (`flow` in `App.tsx`, `{ from, to, day }`, written by `go()` + popstate): motion resolves dynamic `exit` at exit start, `usePresence` fires then too, both read `.current` = truth. `usePresence` also holds life view mounted till wave collapses — `safeToRemove()` from `onComplete`, or at once if no wave.
- **Year ring owns both unroll halves; shell stays out of way.** `YearView` holds ring geometry, both ends must agree to pixel — so it canvas-draws ⌘Y → ⌘L and ⌘L → ⌘Y itself, holds unmount open via `usePresence`, same contract `LifeView` has with zoom. So `PANEL`'s unroll branches neither fade nor scale: canvas shows all; fade only cuts contrast. `stage` = null (no birth date, box too small) → crossfade; presence effect's `!canUnroll` arm stops that hanging panel forever.
- **`unroller` is an honest unroll, not fly-to-target.** At `t` days lie on circle of curvature `(1 - t) / radius`, arc _length_ easing circumference → row width — one curve throughout; lerping 365 positions to destinations scatters at a line. `1 / k` undefined at `t = 1`: write `sin θ / k`, `(1 - cos θ) / k` → `s`, `0`; guard `1e-9`.
- **Unroll easing isn't `EASE`, can't be.** Angle subtended falls ~`(1 - t)²` — halved curvature still a semicircle — nearly all _visible_ straightening in `t`'s first half. `EASE` spends two thirds of travel in first quarter of time: ring a line 150 ms in, over before eye found it. `UNROLL_EASE` leans opposite. Same reason grid arrives on **0.44 s delay**: ring is grid's greys, invisible against 30k dots — must happen on black.
- **A year isn't always one row, so unroll settles onto true dots.** `lifeLayout` splits a year over ≤6 lines; straightened ring = first only. From `SETTLE_FROM` days blend off flattening curve onto `lifeDot`'s real answer — both continuous ⇒ one movement, not unroll-then-rearrange. 1 Jan's dot anchors, `length` to 31 Dec's when sharing a line — desktop: ring lands on row it becomes, no end to reel in.

### Intro animation

- **Intro isn't a reveal. Every face element animates itself; `introDelay` is the whole schedule.** One rule — delay = _where this face puts it_ — for tick, hour, event arc, elapsed-ramp segment alike: day assembles in day order because day **is** order. No timeline, nothing kept in step; later ring placed free. V1 masked all behind rotating conic gradient: one CSS line, reads as wipe — nothing has mass or arrives, geometry's ordering discarded, re-imposed outside.
- **Delay is an _angle_, not minutes since midnight — works on both faces.** Hand starts top: midnight on 24-hour, noon on twelve-hour. Clock-keyed, twelve-hour face assembles from bottom, half-turn out of step with its hand — caught by eye, only way.
- **Three CSS classes + `pathLength="1"` carry all of it** (`global.css`). `.intro-draw`/`.intro-arc` normalise dash math to path's own length ⇒ half-hour tick + six-hour arc share easing, read as one gesture; `.intro-pop` lands what has no length, about `fill-box` so numeral grows around itself, not dial. `backwards` fill load-bearing on all three — else element fully drawn through its own delay = all visible frame one. Arc's **group** fades, **body** draws: body opacity `0.42` on past arcs, so keyframe ending at `1` brightens every morning event in, then drops it.
- **The hand is the one part that is not CSS, and it is a rotation of the same `NowHand`** — shell drops `intro`, nothing to hand over. One turn, constant rate, in step with assembly (both linear in `INTRO_SWEEP_MS`), then springs to current minute **carrying the turn's velocity**: no seam, ~4° overshoot — stops it reading as diagram. SVG's own `rotate(deg cx cy)` **attribute**: `motion`'s `style` route resolves `transform-origin` against element bbox — for a spoke, the rim: hand swung about its middle, left the face. Same trap `NowHand` documents one level down.
- **`INTRO_MS` holds 950 ms slack past settle — not padding.** Dropping `intro` kills rotation; spring still off home at `visualDuration` end: 1.6° at 3.0 s = 4px rim snap.
- **`circal.intro` is its own key; `App` clears `intro` after `INTRO_MS`.** Not a setting: `SCHEMA` bumps reset settings, replaying arrival at a year-long user = opposite of introduction — nobody chose it, so no preference. Marked seen when it _starts_: mid-animation reload isn't a rewatch request. Timer drops it — ⌘Y/⌘L/⌘E unmount the dial; true boolean would replay on return. Off under `prefers-reduced-motion`, **not** marked seen, so disabling still gets one; Settings hides `Play again` there vs. dead button.
- **Three keys sit outside the `circal.v1` blob, each for its own reason.** `circal.intro`: neither data nor preference; `SCHEMA` bump mustn't replay arrival. `circal.marks`: path cache = render state regenerated from a chunk on demand, never exported/restored; a backup with it ships build internals as user data (`ui/icons.tsx`). `circal.backup`: last-backup time _inside_ a backup tells a restoring fresh browser a backup it never took happened — silencing the one warning Safari/Firefox get. `circal.feed.<id>`: fourth, odd one out — real data, out for quota not meaning, reassembled as `Snapshot.feeds`. New keys need this argument, else blob.

### Year ring

- **Year ring commits on _release_ — that's what makes a drag possible.** `onPointerDown` once called `onSelectDay`, exited to dial: no gesture room. Now press starts `Span`; `onUp` reads `sweep === 0` as click (name day, go), wider as range (`onCreateSpan` → all-day draft) — dial's arc rule. Hence `locate` returns `{ day, onRing }`, not `null`: hover needs radius gate, captured drag doesn't — ring in hand, angle is all.
- **Year sweep clamped to `[-from, days - 1 - from]`, never rolled into next year.** Rolling must commit a day to change `year`; committing leaves this view — same argument as arrow keys. Sweep accumulates per pointer event via `ringDelta`: 2 ring positions don't say which way round.
- **Year ring's keyboard is a listbox, not 365 tab stops.** Old month grid put every day in tab order — a wall. Canvas marks can't carry names, so semantics live in `sr-only` `<ul role="listbox">` + `aria-activedescendant`: one stop, arrows inside, ring draws cursor with pointer's magnifier. Arrows move a **cursor**, Enter chooses — naming a day `goDay`s to dial, so commit-per-arrow falls out of view on press one. Cursor clamps at year ends: rollover would commit. ← / → step the _year_ when ring lacks focus; inside, ring's — hence `onKeyDown` `stopPropagation` (`useHotkeys` on `window`, React root bubbles to it).
- **Year face shares dial's crop; `YEAR.MONTH` = `DIAL.ZONE` deliberately.** Same 1000-unit space, `polar`, `VIEW_BOX` ⇒ ⌘D ⇄ ⌘Y = one object relabelled, not two drawings. `faceToPanel` redoes `xMidYMid meet` for anything _beside_ SVG (unroll canvas): px off on frame 1 between two exact positions = one unhideable error.
- **`markRadius` has fifty-eight units of travel because the interior is empty.** Ring _is_ the face; at 20, year read as hairline round a hole. Empty days still mark (`DAY_STUB`) — at render size a square, the life grid's dot; holed ring isn't a year. Today = pip inside ring, not brighter mark, per life grid's halo: day's colour is its events', today isn't one. `DAY_INNER`/`DAY_OUTER` pulled from 336/396 for magnifier room; `TICK_INNER` clears `DAY_OUTER + GROW_OUT`.
- **The hover is a magnifier, and it grows _outwards_.** At 0.99° day < pointer: colour-only highlight = counting teeth; fixed bar over ring = 4× its mark on a one-event day, read as crossing the ring, not one of its days. `Ring` swells hovered day, neighbours less (`magnify`, Gaussian — no corner; every kink = a day snapping as you cross), pushes neighbourhood aside (`spread`: zero under pointer, peak at `SIGMA_PUSH` where room is wanted, zero by `REACH` so rest never moves). Draft grew _inwards_ — outer tip is datum, pushing out makes hovered empty day look booked; true, wrong trade: outward = day meeting you, inward = smudge. Length free, generous (`GROW_OUT` 32, tip four units inside month ticks); width expensive, test ties `PUSH` to it, no longer one-to-one — see ink budget below.
- **Bulge snaps to slot centre and springs there; doesn't follow pointer.** Draft `pointerAt` tracked pointer's fractional place in year: quantised bulge lurches slot at a time. Real effect: full bulge hit a mark only at its midpoint — elsewhere two flanking marks split it, neither full, named day looked like its neighbour. Now `pointerAt` = `useSpring` on `day + 0.5`: fixes _which_ mark is subject, stays continuous. `SLIDE_SPRING` critically damped — overshoot in size = pop, in position = magnifier past day it names. `slideTo` short way via `ringDelta` (31 Dec→1 Jan = one slot, not 364); `jump`s when bulge down (arriving cold, keyboard pickup) — sliding would sweep a swell across two months nobody pointed at.
- **`FALLOFF` lives in `YearView`, not `YEAR`.** Bell = tested geometry; exponents = how hard drawing leans on it. Ordered: length gentlest (`1.4`), _reach_ — 2 marks each side come along; width steep (`4`), _focus_; light steepest (`3.5`), _name_. Bulge locked to slot ⇒ steep channels make subject unmistakable; length can't — wide bell gives first neighbour 70%.
- **Light is what an empty day gets _instead_ of a colour, never over one.** `white` = zero for marks with `count > 0`: events already say what a day is; washing white for hover spends this face's only information on a highlight growth already gave. Empty days say nothing with fill → magnifier lights them grey→near-white. _Selection_ excepted: full white regardless, not hover — where dial lands, unroll leaves from.
- **Ring is 78% ink — hard ceiling on magnifier width.** 4.4 stroke in 5.65 slot = 1.25 black/side; closed ring conserves it: `spread` → zero both ends, gap fixed, `PUSH` only picks _where_ air comes from. Five marks at ~double width need ~16 units, neighbourhood lends 10 ⇒ `PUSH`/`SIGMA_PUSH` 1.7/3.0, not old 0.9/1.15: borrowing must reach four days out+, marks dark, at resting width, crowded pair reads as nothing. Old pair took all from two adjacent slots → 3-unit hole beside hovered day, 1.2-unit overlap one and two days out — a weld, a bar. Past this: thinner `DAY_WIDTH` or black keylines, swell centre-last. No third option; arithmetic decides, not taste.
- **Marks are a canvas because they move.** One `<path>` per colour suits static art; this changes every frame — bulge rides `pointerAt` and `amount`, both springs, both **motion values, never state**: 365 SVG nodes re-diffed at 60 Hz = the cost canvas avoids. _day_ stays React state — readout and listbox name it, changes once per slot. `REACH` cut where both curves are invisible ⇒ loop runs 365 sans exponential each; scales with both sigmas: 4.5 vs `SIGMA_PUSH` 3 left most a slot of tail at cut = mark jumping five days out.
- **The day-crossing tick cannot come from `setHover`.** React bails on identical values ⇒ post-settle, a move within a slot looks like one crossing into the next; a cue per pointer event isn't a tick, it's noise. So `ticked` = ref, written in handler. Fires `slide`, quieter gated drag cue, same `tickSound` / `tickHaptics`: crossing a day = crossing a detent. Slow read = 1 tick/day, fast sweep = a rip — finger along a comb, right for 365 teeth. Keyboard cursor deliberately does **not** tick: `useTypingSound` already answers the arrow key.
- **Year's interior held a daylight figure one draft; not coming back.** Radius inside marks = time of day; sunrise/sunset round the year: one picture a grid can't make. Filled: coffee stain. Two hairlines: quiet, interesting — interesting is the problem: never why you came to a calendar, and readout wants the room. Rim band stays: annotates a day you're actually looking at.
- **Year ring's centre prints a line the user wrote, not a figure the app computed.** Year stats (busiest month, longest empty run): obvious, wrong — dial interiors answer a day because you live in it; nobody opens a year to hear which month was busy. `settings.yearQuote` is it: capped at `YEAR_QUOTE_MAX` in `sane()`, **only at rest** — pointing at a day is a question, a quote no answer. `ink-3`, as the date above (`ink-4` = ticks + disabled; 12.5px on true black = visible, unreadable). Italic + gap subordinate it.
- **`store.setYearQuote` caps, deliberately no `trim()`.** Per keystroke — trim eats space between two words as typed. `sane()` trims: load/restore, value already finished.
- **Ring answers search with the same engine the life grid does, one face over.** `scoreEvent` filters events; survivors run the same `dayTally` marks build from ⇒ ring can't light for a query the palette's list would miss. Match keeps colour, grows a step; miss falls to empty-day grey — **white was not available**: here it already means selection + hovered empty day, one signal can't mean two. Chip takes subtitle's slot (query, days lit, a clear); quote suppressed while lit — quote shows only at rest, typing isn't rest. `App` holds query ⇒ outlives ⌘P closing, same string the life grid threads — one field, two faces.
